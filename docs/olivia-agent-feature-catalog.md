# 올리비아 에이전트 — 전체 기능 카탈로그

> 실제 코드베이스(app/, lib/, api/, supabase/, vercel.json) 기준으로 조사한 전체 기능 목록입니다.
> 카테고리마다 **① 무슨 기능인가 ② 어떻게 개발됐는가 ③ 어떤 API/외부 서비스와 연결됐는가**를 정리했습니다.

## 1. 로그인·보안

**기능**
- 관리자 비밀번호 로그인 (환경변수로 관리, 코드에 저장 안 함)
- Touch ID / Face ID 패스키 로그인 (등록·삭제·목록 관리)
- 대표자 전용 구글 로그인 연동 (Gmail 조회용)
- 고객 포털은 별도 로그인 없이 **토큰 링크**로 접근 (병원 담당자용)

**어떻게 개발됐나**
- 표준 기술인 WebAuthn(`@simplewebauthn`)을 그대로 사용 — 생체인증을 직접 구현하지 않고 검증된 표준 라이브러리에 위임
- 세션·패스키 정보는 Supabase에 저장

**연결 API/서비스**: Supabase, Google OAuth, WebAuthn

---

## 2. CRM · 고객/프로젝트 관리

**기능**
- 고객(병원) 목록 — 칸반 보드 / 리스트 뷰 전환
- 고객 상세 — 현재 워크플로우 단계, 담당자, 촬영일 표시
- PER 리워드 프로그램 — 소개 리워드 포인트 적립/사용 관리
- 캘린더 — 촬영·미팅·업무 일정 통합 관리
- 상담 메모 — 텍스트/손글씨 템플릿, **음성 메모를 텍스트로 자동 변환 후 AI 요약**

**어떻게 개발됐나**
- 고객 하나당 Supabase의 `clients`, `workflow_runs` 테이블에 진행상태가 저장되고, 화면은 이 데이터를 그대로 읽어서 표시
- 음성 메모는 파일 업로드 → OpenAI Transcribe로 텍스트화 → Claude로 요약하는 2단계 파이프라인

**연결 API/서비스**: Supabase(데이터), OpenAI Transcribe(음성→텍스트), Claude(요약)

---

## 3. 워크플로우 자동화 엔진 (올리비아의 핵심)

**기능**
- 14단계 워크플로우: 상담 → 견적 → 계약 → 콘티 → 촬영 → 백업정리 → 원본전달 → 고객선택 → RAW매칭 → 리터칭 → 리터칭전달 → SEO전달생성 → 최종납품 → 리뷰수집
- 단계 진입 시 작업(agent_tasks) 자동 생성 → 실행 → 초안/메일큐/승인 자동 생성 → 사람 승인 → 다음 단계 자동 이동
- 승인 대기함 (승인/반려/수정요청)
- 작업 실행 로그, 지연/확인 필요 항목 자동 감지

**어떻게 개발됐나**
- `lib/workflow.ts`에 14단계 정의(각 단계별 승인 필요 여부, 고객 노출 여부, 자동 메일 초안 생성 여부를 속성으로 지정)
- `lib/workflowAutomation.ts`가 실제 진행 엔진 — 단계 완료 조건이 충족되면 다음 단계로 자동 이동
- 이 프로젝트에서 가장 복잡한 부분으로, 실제로 "진행률 6/12 어긋남" 같은 버그가 여기서 나왔음(전체 18단계 카탈로그 vs 실사용 12단계 기준이 서로 달랐던 사례)

**연결 API/서비스**: Supabase(상태 저장의 중심), Claude(초안 판단·요약)

## 4. 견적서·계약서·콘티 — 문서 자동 생성

**기능**
- 조건 입력 → 견적서 PDF 자동 생성 및 전달
- 계약서 PDF 생성
- 촬영 콘티(스토리보드) 생성, 영상 콘티(씬·컷·전환·배경음악까지 포함)
- 초상권 동의서 자동 생성
- 공유 토큰으로 고객이 링크만으로 콘티/동의서 열람 가능

**어떻게 개발됐나**
- 화면(HTML)을 `html2canvas`로 이미지화한 뒤 `jsPDF`로 PDF 변환하는 방식 — 별도 PDF 생성 서버 없이 브라우저에서 바로 처리
- 영상 콘티의 씬 자동 생성, 배경음악 추천은 Claude가 담당

**연결 API/서비스**: Claude(콘티 문구/씬 생성), Supabase, jsPDF/html2canvas

---

## 5. 사진·영상 작업 도구

**기능**
- 사진 분류/색상 체크(피부톤 일관성 확인)
- 셀렉 갤러리 — 고객이 마음에 드는 사진을 직접 고르는 화면 (원본은 저장하지 않고 대표 썸네일만 Supabase Storage에 저장)
- RAW-JPG 자동 매칭 (파일명 OCR)
- 리터칭 작업 관리, 리비전(수정) 요청 처리
- 영상 파일 분류, 포맷 변환

**어떻게 개발됐나**
- 사진 장면 분석은 사진을 잘 "보는" 모델(OpenAI Vision)에 맡기고, 색상/피부톤처럼 판단이 필요한 분석은 Claude가 담당 — Week 1에서 다룬 "업무별로 AI를 다르게 쓰는" 설계
- 이미지 처리(리사이즈, 썸네일)는 `sharp` 라이브러리로 서버에서 처리

**연결 API/서비스**: OpenAI Vision(사진 씬 분석), Claude(색상/피부톤 분석), Supabase Storage, Sharp

## 6. 콘텐츠 마케팅 자동화

**기능**
- 리뷰 콘텐츠 스튜디오 — 고객 후기를 인스타그램 카드뉴스/캡션으로 자동 변환 (레이아웃 여러 버전 생성)
- 오늘의 아이디어 — 매일 밤 각 병원별 콘텐츠 아이디어를 AI가 자동 생성
- SNS 콘텐츠 관리자 — 블로그, 인스타 캡션, 네이버플레이스, 유튜브 설명 작성
- 콘텐츠 캘린더 — 발행 일정 시각화
- AI 이미지 생성기 — 병원 이미지 프롬프트를 Claude가 작성한 뒤 이미지 생성

**어떻게 개발됐나**
- 카드뉴스는 SVG 레이아웃을 만들고 PNG로 렌더링하는 방식으로 여러 스타일 변형을 자동 생성
- "오늘의 아이디어"는 Week 2에서 다룬 크론 작업(매일 밤 11시) 중 하나로 사람 개입 없이 실행

**연결 API/서비스**: Claude(문구·아이디어 생성), 이미지 생성 서비스

---

## 7. 진단·분석 도구

**기능**
- 병원 이미지 진단 — 병원 전문 분야에 맞는 사진 콘텐츠 니즈 진단
- 브랜드 이미지 종합 진단 — 웹사이트+네이버플레이스+블로그+인스타+유튜브를 한꺼번에 분석해 실행계획 도출, 공유 링크로 리포트 전달
- 채널 분석 — SNS/웹 채널별 현황 분석
- 트렌드 대시보드 — SNS 트렌드, 검색량, 경쟁 병원 현황 수집·분석
- AI 신뢰도 격차 분석 — AI(챗GPT 등)가 특정 병원을 왜 반복 추천하는지 패턴을 분석해 촬영 전략 도출

**어떻게 개발됐나**
- 여러 채널에서 데이터를 먼저 수집한 뒤, Claude가 기준(criteria)에 따라 채점하고 리포트를 컴파일하는 2단계 구조
- 완성된 리포트는 토큰 기반 공유 링크로 고객에게 그대로 전달 (로그인 불필요)

**연결 API/서비스**: Claude(분석·리포트 생성), Supabase

---

## 8. 고객 포털 (병원 담당자가 직접 보는 외부 화면)

**기능**
- 진행 상황 확인, 갤러리 열람 및 사진 선택, 서류(계약서 등) 열람
- 촬영 준비사항 체크리스트, 콘티 피드백
- 후기 작성, 수정(리비전) 요청
- PER 리워드 확인

**어떻게 개발됐나**
- 어드민 화면과 완전히 분리된 별도 영역(`client-portal/`)이지만 같은 Supabase 데이터를 바라봄
- 로그인 대신 발급된 접근 토큰(`/client-portal/access/[token]`)으로 접속 — 병원 담당자가 계정을 만들 필요 없음

**연결 API/서비스**: Supabase

---

## 9. 올리비아 AI 비서 & 카카오톡/텔레그램 연동

**기능**
- 대표자 전용 카카오톡 대화 — 카카오톡으로 올리비아에게 말을 걸면 업무 조회/실행
- Gmail 조회·요약·답장 초안 작성
- 아침/오후/저녁 자동 브리핑 발송
- 일정 알림을 텔레그램으로 발송
- 올리비아 스스로 매일 밤 활동을 점검(observer)하고 이상 있으면 보고

**어떻게 개발됐나**
- `lib/olivia/`, `lib/assistant/` 아래에 대규모 모듈(액션플래너, 브리핑생성, 규칙엔진, 지식패치 등)로 구성된 이 프로젝트에서 가장 큰 하위 시스템
- 카카오 i 오픈빌더의 스킬/이벤트 API와 연동, 대화 식별자·OAuth 토큰은 암호화해서 저장
- 크론 작업으로 하루 여러 번 자동 실행 (섹션 11 참고)

**연결 API/서비스**: Claude(대화·판단·브리핑), 카카오 i 오픈빌더, Google OAuth(Gmail), Telegram Bot API

## 10. 팀 협업 도구

**기능**
- 팀 채팅(채널·초대링크)
- 칸반 작업 보드 — 작업 시작/제출/승인/보류/재오픈
- 프로젝트 관리, 팀원 배정
- OKR/목표 관리, 오늘의 스탠드업

**어떻게 개발됐나**
- Supabase 데이터를 기반으로 한 자체 구축 협업 도구 (외부 협업툴 대신 내부에 통합)
- 파일 공유는 Google Drive OAuth 연동으로 처리

**연결 API/서비스**: Supabase, Google Drive

## 11. 자동화 크론 작업 (24시간 운영)

`vercel.json`에 등록된, 사람이 실행하지 않아도 정해진 시간마다 저절로 도는 13개 작업입니다.

| 시각 | 작업 | 하는 일 |
|---|---|---|
| 매주 월요일 자정 | weekly-report | 7일치 활동 집계 후 요약 메일 발송 |
| 매일 밤 11시 | daily-ideas | 병원별 콘텐츠 아이디어 AI 생성 |
| 매일 자정 | shoot-reminder | 촬영 일정 리마인드 발송 |
| 매주 월요일 새벽 1시 | trend-collect | SNS 트렌드·키워드 데이터 수집 |
| 매일 새벽 3시반 | trash-cleanup | 30일 지난 휴지통 영구 삭제 |
| 매일 자정 15분 | data-retention | 데이터 보존정책 처리 |
| 매일 밤 9시반 | olivia-observer | 올리비아가 활동 패턴 스스로 점검 |
| 매일 밤 11시 | olivia-morning-briefing | 아침 브리핑 준비 |
| 매일 자정 5분 | assistant-jobs | 비서 대기 작업 실행 |
| 매일 자정 10분 | assistant-important-email | 중요 메일 자동 감지 |
| 매일 새벽 5시 | assistant-afternoon-briefing | 오후 브리핑 |
| 매일 새벽 10시 | assistant-evening-briefing | 저녁 브리핑 |
| 매일 새벽 3시 | select-galleries 정리 | 만료된 셀렉 파일 정리 |

**어떻게 개발됐나**: Vercel Cron이 정해진 시간에 각 API 주소를 자동으로 호출하는 방식. 별도의 서버를 띄워둘 필요 없이 서버리스 함수가 그 순간에만 실행됨.

**연결 API/서비스**: Claude, Telegram, Gmail, Supabase

## 12. 리포트·분석

**기능**
- 주간/월간 리포트 — AI 활동 요약, 병원별 통계, 차트
- 병원별 진행 통계

**어떻게 개발됐나**: Supabase에 쌓인 데이터를 집계해서 `recharts`로 시각화하고, 요약 문구는 Claude가 생성

**연결 API/서비스**: Claude, Supabase

## 부록 — 기술 스택 요약

| 영역 | 기술 |
|---|---|
| 프레임워크 | Next.js 15 (App Router) |
| 데이터베이스 | Supabase (PostgreSQL + Storage) |
| AI (텍스트/판단) | Anthropic Claude |
| AI (사진/음성) | OpenAI (Vision, Transcribe, Image) |
| 인증 | WebAuthn 패스키, Google OAuth, 관리자 비밀번호 |
| 메일 발송 | Gmail + Nodemailer |
| 메시징 | 카카오 i 오픈빌더, Telegram Bot API |
| 문서 생성 | jsPDF, html2canvas |
| 엑셀 내보내기 | xlsx (SheetJS) |
| 이미지 처리 | Sharp |
| 배포·자동화 | Vercel + Vercel Cron |

> 규모 참고: 화면(페이지) 60개 이상, API 엔드포인트 330개 이상, 자동화 작업 13개, Supabase 테이블 40개 이상 — 이 모든 게 처음부터 설계된 게 아니라 Week 1에서 다룬 "가장 아픈 것부터 하나씩" 확장한 결과입니다.
