# 관리자 보정본 한 장 삭제 설계

## 범위

- 개인별 사진선택 관리자 상세에서 보정본을 한 장씩 삭제한다.
- 고객 공개 화면에는 삭제 조작을 노출하지 않는다.
- 원본 셀렉 사진, 고객 계정, 주문, 다른 보정본은 변경하지 않는다.
- DB 스키마는 변경하지 않는다.

## 화면

- 기존 사람 상세 서랍의 각 보정본 가로 행 오른쪽에 약한 휴지통 버튼을 둔다.
- 누르면 파일명과 모든 버전이 영구 삭제된다는 확인창을 표시한다.
- 삭제 중에는 해당 버튼만 비활성화하고, 실패하면 보정본 목록 아래에 원인을 계속 표시한다.
- 성공하면 관리자 데이터를 다시 읽어 해당 행을 즉시 제거한다.

## 서버 흐름

1. 관리자 세션과 `eventId` 소속을 확인한다.
2. 해당 보정본의 모든 버전에서 원본·미리보기 Storage 경로를 수집한다.
3. `person-select` 버킷의 수집된 파일을 삭제한다.
4. Storage 삭제에 성공한 경우에만 보정본 행을 삭제한다. 버전 행은 기존 외래키의 `ON DELETE CASCADE`로 함께 삭제된다.
5. 해당 고객의 마지막 보정본이었다면 보정본 검토 상태와 관련 시각을 `none`/`null`로 초기화한다.

## 오류와 검증

- 다른 프로젝트의 `deliveryId`는 404로 처리한다.
- Storage 삭제 실패 시 DB 행은 유지한다.
- API 테스트는 관리자 거부, 소속 검증, Storage 경로 삭제, DB 삭제 순서, 마지막 보정본 상태 초기화를 확인한다.
- TypeScript 검사, 관련 Vitest, 프로덕션 빌드를 실행한다.
