# Olivia Bridge 이동·리사이즈 창 설계

작성일: 2026-10-24

## 목적

Olivia Bridge의 앱 창과 내부 기능 창을 자유롭게 줄이고 늘릴 수 있게 한다. 창 크기가 바뀌면 폴더, 썸네일, 사진 미리보기와 기능 내용이 실제 Bridge 영역을 기준으로 자동 재배치되어야 한다. 기능 창은 기본적으로 오른쪽에 열되, 사용자가 제목줄을 잡아 옮기고 가장자리에서 크기를 바꿀 수 있어야 한다.

## 적용 범위

- Olivia OS의 Olivia Bridge 앱 창
- 사진 셀렉, RAW 매칭, 사진 분류, T컷 정리, 사진 리사이즈, 이름변경, 사진 보정 기능 창
- AI Scene 분류 검토 창

macOS 전체화면 사진 미리보기는 사진 감상 전용 레이어이므로 이동·리사이즈 대상에서 제외한다.

## 확정 동작

### Bridge 앱 창

- Olivia OS가 이미 제공하는 앱 창 이동·리사이즈 동작을 유지한다.
- Bridge 내부 레이아웃은 브라우저 화면 폭이 아니라 Bridge 앱 창의 실제 콘텐츠 폭을 기준으로 반응한다.
- 넓은 창에서는 폴더, 파일 목록, 사진 미리보기의 3열 구조를 유지한다.
- 중간 폭에서는 폴더와 미리보기 폭을 줄여 파일 목록을 확보한다.
- 좁은 창에서는 파일 목록과 미리보기를 위아래로 배치하고, 폴더 영역은 축약한다.
- 크기를 바꿔도 현재 폴더, 현재 사진, 다중 선택, 별점, 제외 표시와 열려 있는 기능을 유지한다.

### 내부 기능 창

- 모든 기능 창은 같은 공통 이동·리사이즈 창을 사용한다.
- 처음 열릴 때 Bridge 오른쪽 위에 18px 안쪽 여백을 두고 배치한다.
- 제목줄을 드래그하면 Bridge 영역 안에서 이동한다.
- 오른쪽, 아래쪽, 오른쪽 아래 핸들로 크기를 조절한다.
- 최소 크기 이하로 줄어들지 않으며 Bridge 영역 밖으로 완전히 밀려나지 않는다.
- Bridge 앱 창 자체가 작아지면 열린 기능 창의 위치와 크기를 새 경계 안으로 자동 보정한다.
- 닫았다 다시 여는 동안에는 도구 종류별 마지막 위치와 크기를 Bridge 세션에서 기억한다.
- X 닫기 버튼과 기존 저장·취소·실행 동작은 그대로 유지한다.
- 기능 창 뒤의 Bridge 화면을 흐리거나 어둡게 만들지 않는다.

### 기능 창 내부 반응형

- 기능 창 본문은 남은 높이를 사용하고 필요한 영역만 내부 스크롤한다.
- 폭이 줄면 제목, 상태, 실행 버튼이 겹치지 않도록 줄바꿈하거나 세로로 재배치한다.
- 기존 사진작업실 기능은 그대로 임베드하며 파일 처리, 안전 확인, 오류 처리 로직을 바꾸지 않는다.
- 창 리사이즈와 내용 스크롤은 현재 폴더·선택 파일 전달값을 바꾸지 않는다.

## 구현 구조

### 공통 창 컴포넌트

`components/olivia-bridge/BridgeFloatingWindow.tsx`를 추가한다.

- 제목, 부제, 닫기, 본문을 받는다.
- Bridge 루트 참조와 창 종류별 형상 상태를 받는다.
- Pointer Events와 pointer capture로 드래그·리사이즈를 처리한다.
- 제목줄의 버튼이나 입력 요소에서 시작한 포인터는 드래그로 해석하지 않는다.
- 드래그·리사이즈가 취소되거나 포인터를 잃어도 상호작용 상태를 정리한다.
- 접근 가능한 창 제목과 닫기 버튼을 유지한다.

### 형상 계산

순수 계산 모듈에 다음 동작을 둔다.

- 오른쪽 기본 위치 계산
- 최소 폭·높이 적용
- Bridge 경계에 맞춘 위치·크기 보정
- 오른쪽·아래·오른쪽 아래 리사이즈 계산

계산은 DOM과 분리해 단위 테스트한다.

### Bridge 반응형

Bridge 루트에 CSS container를 선언한다. 기존 viewport media query를 보조로 남기되, Olivia OS 창 크기에 반응하는 핵심 배치는 container query로 처리한다. 기능 창 본문도 독립 container로 선언해 기능 창 자체의 폭에 따라 헤더와 본문이 조정되게 한다.

## 크기와 경계

- 기능 창 기본 상단: Bridge 툴바 아래
- 기본 오른쪽 여백: 18px
- 최소 폭: 일반 도구 520px, Scene 검토 420px
- 최소 높이: 360px
- Bridge가 최소 크기보다 좁으면 가용 영역을 우선하며, 사방 8px 안전 여백 안에 맞춘다.
- 제목줄은 항상 화면 안에 남겨 다시 이동하거나 닫을 수 있게 한다.
- 리사이즈 핸들은 시각적으로 과도하게 강조하지 않되 포인터 커서와 충분한 조작 영역을 제공한다.

## UI 원칙

- 기존 Olivia Bridge의 어두운 사진 작업 톤을 유지한다.
- 새 채운 주 실행 버튼이나 새 강조색을 만들지 않는다.
- 기능 창 제목과 버튼의 글자 굵기는 600을 넘지 않는다.
- 아이콘은 기존 lucide 선 아이콘을 사용한다.
- 닫기 버튼은 최소 44px 조작 영역과 `aria-label="닫기"`를 유지한다.
- 배경 오버레이와 화면 전환을 추가하지 않는다.

## 보존 범위

- 사진 폴더 탐색과 파일 목록 조회
- JPG 썸네일과 오른쪽 미리보기
- RAW·사이드카 파일 표시
- 키보드 선택, 별점, 제외, macOS 전체화면 미리보기
- 사진작업실 각 기능의 파일 처리 로직과 안전 확인
- AI Scene 승인 전 파일을 변경하지 않는 규칙
- Olivia OS 기본 창 이동·최대화·최소화·닫기 동작

## 검증

- Bridge 앱 창을 넓게·중간·좁게 조절했을 때 실제 창 폭에 따라 레이아웃이 바뀐다.
- 모든 기능 창이 오른쪽에 처음 열리고 제목줄로 이동된다.
- 오른쪽·아래·오른쪽 아래에서 기능 창 크기가 바뀐다.
- 기능 창과 Bridge 창을 연속으로 줄여도 창 제목과 닫기 버튼이 경계 밖으로 사라지지 않는다.
- 열린 도구와 현재 폴더·사진 선택 상태가 리사이즈 전후에 유지된다.
- Scene 검토와 기존 일곱 기능이 같은 공통 창 동작을 사용한다.
- 760px, 1024px, 1440px 상당의 앱 창 너비에서 내용 겹침과 잘림을 확인한다.
- 형상 계산 단위 테스트, 관련 Bridge 테스트, 타입 검사, 린트, 전체 테스트, 빌드를 실행한다.

- 데이터, 파일 변경 로직과 기존 사진작업실 기능은 변경하지 않는다.
