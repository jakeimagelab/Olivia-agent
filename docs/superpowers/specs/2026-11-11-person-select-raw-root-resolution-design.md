# 개인별·공동 셀렉 RAW 경로 분리 설계

## 배경

사진선택 프로젝트는 고객에게 보여 줄 JPG 폴더를 `source_relative_path`로 저장한다. 푸른안과 프로젝트처럼 이 값이 `root-0/.../JPG전체/프로필`인 경우, 기존 RAW 매칭 워커는 이 JPG 폴더를 RAW 검색 범위와 결과 저장 위치로도 사용했다. 그 결과 촬영 폴더의 형제 RAW 폴더를 찾지 못해 선택 사진 52장이 모두 `RAW 없음`이 되었고, 결과 경로도 `JPG전체/프로필/Selected_RAW`로 잘못 계산됐다.

## 결정

JPG 읽기, RAW 검색, 결과 저장 경로를 분리한다.

- JPG 읽기: 행사에 기록된 원래 `source_relative_path`
- RAW 검색: 같은 스토리지 루트 안의 촬영 폴더
- 결과 저장: 촬영 폴더의 `Selected_RAW/<소유자>`
- 공동 셀렉 소유자 폴더: `프로젝트`
- 개인별 셀렉 소유자 폴더: 기존 사람 이름

예시:

- JPG: `root-0/1026_푸른안과/JPG전체/프로필`
- RAW 검색: `root-0/1026_푸른안과`
- 결과: `root-0/1026_푸른안과/Selected_RAW/프로젝트`

## 촬영 폴더 판정

가상 경로의 각 구간을 NFC로 정규화하고, `JPG전체`, `JPG원본`, `JPG` 구간을 찾는다. 해당 구간의 바로 위를 촬영 폴더로 사용한다.

- 알려진 JPG 구간이 있으면 그 상위 경로를 사용한다.
- 알려진 구간이 없으면 기존 호환성을 위해 행사 원본 폴더 자체를 사용한다.
- `root-N` 식별자는 그대로 유지한다.
- JPG 폴더와 촬영 폴더를 각각 서버 허용 루트로 해석한 뒤 두 경로의 루트 ID가 같은지 다시 검증한다.
- 다른 루트로 바뀌거나 허용 루트를 벗어나는 경로는 실행하지 않는다.

이 규칙으로 Workstation(`root-0`)에서 시작한 작업이 Agentstation(`root-2`)으로 자동 전환되는 것을 막는다.

## 워커 동작

1. 행사 `source_relative_path`를 JPG 루트로 해석한다.
2. 촬영 폴더 가상 경로를 결정하고 별도로 해석한다.
3. JPG EXIF는 JPG 루트의 `source_rel_path`에서 읽는다.
4. RAW 인덱스는 촬영 폴더에서 만들되 `JPG전체`, `JPG원본`, `JPG`, `Selected_RAW`, `N차보정본`을 제외한다.
5. 파일명과 촬영시각 검증을 통과한 RAW만 `ditto` 기반 복사 함수로 저장한다.
6. 결과에 JPG 위치, RAW 검색 범위, 결과 저장 위치를 기록한다.

## 관리자 UI

기존 RAW 매칭 확인창의 구조와 버튼 위계는 유지한다. 선택 기준 아래에 다음 세 경로를 얇은 정보 영역으로 표시한다.

- JPG 위치
- RAW 검색 범위
- 결과 저장 위치

결과 줄도 실제 저장 위치를 사용한다. 새 팝업이나 새로운 주동작 버튼은 추가하지 않는다.

## 오류 처리

- 같은 루트 검증 실패: 실행 중단
- 촬영 폴더를 읽을 수 없음: 실행 중단하고 구체적인 경로 오류 표시
- RAW 없음 또는 촬영시각 불일치: 기존 확인 필요 목록 유지
- 복사 대상 충돌: 덮어쓰지 않음
- RAW 원본: 이동·삭제하지 않음

## 검증

- `root-0/.../JPG전체/프로필` → 촬영 폴더 `root-0/...`
- 한글 NFD/NFC 경로에서도 같은 결과
- `root-0`이 `root-2`로 바뀌지 않음
- 알려진 JPG 구간이 없는 기존 프로젝트는 원래 동작 유지
- 공동 셀렉 결과는 `Selected_RAW/프로젝트`
- 개인별 결과는 `Selected_RAW/<이름>`
- 타입 검사와 관련 Vitest 통과
