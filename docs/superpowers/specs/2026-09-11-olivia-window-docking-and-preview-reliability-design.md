# Olivia 창 도킹·대화 기록·텔레그램 미리보기 안정화 설계

## 목표

Olivia OS에서 채팅을 작업 기능의 보조 도구로 명확히 동작하게 한다. 사용자는 견적서·계약서·콘티 같은 메인 창 옆에 Olivia 채팅을 붙여 하나처럼 이동할 수 있어야 한다. 동시에 긴 대화 기록 팝업은 마우스로 실제 조작할 수 있어야 하며, 텔레그램의 문서 미리보기 안내는 실제 모바일 URL 전송 결과와 일치해야 한다.

## 범위

이번 변경은 다음 다섯 부분을 포함한다.

1. 대화 기록 네비게이터 팝업 위치와 hover 이동 경로 수정
2. 메인 기능 창과 Olivia 채팅창의 부모–자식 도킹
3. 견적 요청의 항목 누락과 재시도 응답 오류 수정
4. 실제 문서를 여는 7일짜리 Telegram 모바일 미리보기 URL
5. 임시문서함의 안전한 문서 복원

임시문서 생성 방식이나 문서 승인·고객등록 상태 머신 자체는 변경하지 않는다. 기존 화면 가장자리 Snap Layout도 유지한다.

## 1. 대화 기록 네비게이터

### 현재 문제

기록바에서 팝업까지의 거리가 멀고 팝업의 세로 위치가 선택한 기록과 무관하게 고정되어 있다. 기록바의 `onMouseLeave`가 팝업으로 이동하기 전에 선택을 해제하므로 팝업 안의 “이 대화로 이동” 버튼을 누를 수 없다.

### 동작

- 팝업은 선택된 tick 바로 왼쪽에 4~8px 간격으로 표시한다.
- tick의 중심을 기준으로 팝업의 세로 위치를 계산하되 채팅 창의 상단과 하단을 벗어나지 않도록 제한한다.
- 기록바와 팝업을 하나의 hover 영역으로 취급한다.
- 두 요소 사이에는 보이지 않는 포인터 이동 통로를 둔다.
- 포인터가 전체 영역을 벗어났을 때만 짧은 닫기 지연 후 선택을 해제한다.
- 팝업에 진입하면 닫기 타이머를 취소한다.
- 키보드 focus와 클릭 고정 동작은 계속 지원한다.
- 좁은 모바일 화면에서는 기존 하단 고정 팝업을 유지한다.

### 구현 경계

`OliviaConversationGuide`가 선택된 tick DOM 좌표와 hover 상태를 소유한다. CSS는 팝업의 모양과 연결 통로를 담당하고, 선택 좌표 및 viewport 제한은 컴포넌트에서 CSS custom property로 전달한다.

## 2. 부모–자식 스마트 도킹

### 역할

- 견적서·계약서·콘티 및 Olivia가 조작 대상으로 삼는 기능 창은 메인 창이 될 수 있다.
- `olivia-chat` 창은 항상 서브 창이다.
- 일반 앱 창끼리는 이번 범위에서 서로 도킹하지 않는다.

### 결합

- 사용자가 채팅창을 메인 창의 오른쪽 가장자리에 가까이 이동하면 도킹 후보를 계산한다.
- 수평 간격과 세로 겹침이 임계값 안에 들어오면 메인 창 오른쪽에 가이드선과 반투명 채팅 배치 영역을 표시한다.
- 포인터를 놓으면 채팅창의 왼쪽을 메인 창의 오른쪽에 작은 간격을 두고 맞춘다.
- 채팅창 높이는 메인 창의 사용 가능한 높이에 맞추되 기존 최소 크기와 데스크톱 경계를 지킨다.
- 화면 오른쪽 공간이 부족하면 메인 창과 채팅창을 함께 왼쪽으로 이동해 두 창이 데스크톱 안에 들어오게 한다. 공간 자체가 부족한 경우에는 채팅 너비를 최소 너비까지 줄이고, 그래도 불가능하면 결합하지 않는다.

### 결합 후 이동

- 데스크톱 상태에는 서브 창이 어느 메인 창에 붙었는지를 나타내는 `parentWindowId`를 저장한다.
- 메인 창을 이동하면 동일한 이동량을 서브 창에도 적용한다.
- 메인 창을 화면 가장자리에 스냅하거나 복원해도 서브 창은 오른쪽 도킹 위치를 다시 계산한다.
- 메인 창의 크기를 조절하면 서브 창의 왼쪽 위치와 높이를 다시 맞춘다.
- 메인 창을 최소화하면 서브 창도 함께 최소화하고, 복원하면 함께 복원한다.
- 메인 창을 닫아도 채팅은 닫지 않고 현재 위치에서 독립 창으로 남긴다.

### 분리

- 사용자가 채팅창 헤더를 드래그하기 시작하면 `parentWindowId`를 즉시 제거한다.
- 분리 순간의 화면 좌표와 크기를 유지하므로 창이 튀지 않는다.
- 분리 후에는 기존 자유 이동 및 화면 가장자리 Snap Layout을 그대로 사용한다.

### 상태와 순수 계산

- 도킹 후보 계산, 결합 좌표, 데스크톱 경계 보정은 별도의 순수 함수 모듈에 둔다.
- 드래그 중 후보는 영속화하지 않고 overlay 표시용 상태로만 둔다.
- 확정된 `parentWindowId`만 기존 데스크톱 상태와 함께 localStorage에 저장한다.
- 상태 버전을 올리고 이전 버전은 기존 정책에 따라 안전하게 초기화한다.

## 3. 견적 요청 완전성

### 현재 확인된 오류

- 견적 생성 도구는 촬영일이 없을 때 `shootDate: null`을 전달하지만 공통 CRUD 검증기는 문자열만 허용한다.
- 첫 도구 실행이 실패한 뒤 모델이 재시도해 성공하면 실패 문구와 성공 문구가 한 답변에 이어 붙는다.
- `create_quote` 입력 구조는 패키지·프로필·연출 인원·메모만 표현할 수 있어 할인과 별도 서비스 항목을 한 번에 저장하지 못한다.
- 확인한 실제 사례에서는 프리미엄 패키지와 연락처·메모는 저장됐지만 10% 할인은 누락됐고 작품사진 서비스는 별도 항목이 아니라 메모에만 들어갔다.

### 입력과 계산

- `create_quote`는 할인율, 추가 유료 항목, 무료 서비스/혜택을 구조화된 입력으로 받는다.
- 촬영일·담당자·전화·이메일·메모처럼 선택 가능한 값은 `null`을 정상 입력으로 취급하고 DB에는 타입에 맞게 변환한다.
- 할인은 모델이 최종 금액을 임의 계산하지 않는다. 서버의 견적 계산 함수를 사용해 공급가액·할인·부가세·총액·계약금·잔금을 한 번에 계산한다.
- “서비스로 작품사진 별도 촬영”과 같은 요청은 금액 없는 서비스 항목으로 견적 `items`에 저장하고, 소개 경로처럼 문서 메모에 해당하는 내용만 `memos`에 저장한다.
- 저장 후에는 병원명, 연락처, 항목, 할인, 메모, 합계가 요청에서 추출한 구조와 일치하는지 검증한다.
- 검증이 실패하면 임시문서 등록과 미리보기 링크 발급을 중단하고 누락된 부분을 구체적으로 알려준다.

### 재시도 응답

- 한 턴에서 같은 생성 도구가 실패 후 성공한 경우 최종 성공 결과만 사용자 응답에 표시한다.
- 복구되지 않은 실패만 오류로 표시한다.
- 동일 요청의 재시도에는 같은 client request ID에서 중복 문서가 생기지 않도록 idempotency를 적용한다.

## 4. Telegram 모바일 미리보기 URL

### 기본 방식

Telegram용 PNG 생성·전송을 기본 경로에서 제거한다. 문서 생성과 저장 검증이 완료되면 실제 DB 문서를 읽는 모바일 미리보기 URL을 발급한다.

- 견적은 기존 `/quote-preview/m/[token]` 화면을 재사용한다.
- 미리보기 화면은 별도 데이터 복사본이 아니라 원본 견적 row를 안전한 공개 응답 형태로 변환해 표시한다.
- 같은 견적이 수정되면 기존 URL에서도 최신 내용이 표시된다.
- Telegram에는 병원명, 문서 종류, 주요 항목, 할인, 최종 금액의 짧은 요약과 `📄 견적서 미리보기` URL 버튼을 보낸다.
- `내용 확인`, `수정 요청`, `보류` callback 버튼은 같은 메시지에 유지한다.
- Olivia는 Telegram 메시지 전송과 URL 발급이 모두 성공한 뒤에만 “미리보기 링크를 보냈어요”라고 말한다.
- 계약서와 콘티도 문서별 모바일 미리보기 화면과 공유 토큰을 추가해 같은 방식으로 확장한다.
- 문서 전용 URL을 만들 수 없는 유형에만 범용 텍스트 요약을 사용하며, 한글이 깨지는 범용 PNG는 사용하지 않는다.

### 7일 보안 토큰

- 공유 토큰에는 `expires_at`을 저장하며 발급 시점부터 7일간 유효하다.
- 토큰은 추측하기 어려운 암호학적 난수로 생성하고 로그에 기록하지 않는다.
- 모바일 페이지와 미리보기 API 모두 만료·취소 여부를 검사한다.
- 만료된 URL은 문서 내용을 노출하지 않고 “링크가 만료됐어요” 화면을 보여준다.
- Telegram에서 같은 문서의 미리보기를 다시 요청하거나 임시문서함에서 모바일 링크를 열면 기존 토큰을 폐기하고 새로운 7일 토큰을 발급한다.
- 문서가 삭제·보관 처리되면 활성 토큰을 취소한다.
- 임시문서 내용 승인이나 보류만으로는 링크를 즉시 끊지 않는다. 사용자가 7일 동안 검토할 수 있게 유지한다.

### 성공의 정의

Olivia가 미리보기를 제공했다고 말할 수 있는 조건은 다음 세 단계가 모두 성공한 경우뿐이다.

1. 원본 문서 저장 후 필드·합계 검증 성공
2. 유효기간이 설정된 공유 토큰과 모바일 URL 생성 성공
3. Telegram URL 버튼 메시지 전송 성공 및 Telegram message ID 수신

문서를 DB에 저장한 것과 Telegram에 링크를 보낸 것은 별개의 결과로 취급한다.

### 전달 흐름

- 문서 생성 도구 결과에서 `temporaryDocumentId`, `documentType`, `resourceId`를 공통 결과 구조로 전달한다.
- Telegram 어댑터는 해당 ID로 문서별 7일 공유 URL을 발급한다.
- 전송 성공 후에만 assistant message metadata에 Telegram outbound message ID와 문서 연결 정보를 기록한다.
- 발급한 공유 토큰 자체는 대화 metadata에 복사하지 않고 공유 row에서 관리한다.

### 실패 복구

- 공유 URL 발급 또는 Telegram 메시지 전송 실패를 조용히 성공으로 처리하지 않는다.
- 임시문서 저장은 유지한다.
- Telegram에는 “미리보기 링크를 만들지 못했지만 임시문서함에 저장했어요”라는 짧은 안내를 보낸다.
- 서버 로그에는 단계(`document_verify`, `share_create`, `telegram_send_message`)와 문서 ID를 남기되 Telegram 토큰이나 공유 URL은 남기지 않는다.
- 웹 Olivia Chat에도 실제 전송 성공 여부가 반영되며, 전송되지 않았는데 “열었다” 또는 “보냈다”라고 표현하지 않는다.

### Telegram에서 찾기 쉬운 표시

- 메시지 첫 줄에 문서 종류와 병원명을 표시한다.
- 본문에 “임시문서” 상태와 링크 만료일을 명시한다.
- 미리보기 URL, 내용 확인, 수정 요청, 보류 버튼을 한 메시지에 제공한다.
- 미리보기 버튼은 Telegram 인앱 브라우저와 일반 모바일 브라우저에서 모두 열린다.

## 5. 임시문서함 복원

### 현재 확인된 오류

견적 임시문서의 route는 `/quote?id=<sourceId>`로 생성되지만 페이지 모드의 `QuoteBuilder`는 `id` query parameter를 읽지 않는다. 따라서 해당 URL은 DB 견적을 복원하지 않고 새 빈 견적 화면을 연다. 사용 환경에 남은 상태와 결합하면 client-side exception으로 이어질 수 있다.

### 동작

- Olivia OS 문서함에서는 일반 `<a target="_blank">` 대신 문서 유형과 `sourceId`를 Window Manager에 전달한다.
- 견적 문서는 OS 내부 견적 창을 열고 `resourceId`로 단건 API를 조회해 폼과 실제 미리보기를 복원한다.
- 계약서와 콘티도 같은 typed open action을 사용한다.
- 전통적인 페이지 URL이 필요한 경우 `/quote?resourceId=...`처럼 하나의 표준 parameter를 사용하고 페이지가 실제로 이를 읽게 한다.
- 문서 조회 전 로딩 상태를 표시하고, 404·권한 오류·payload 변환 오류는 전체 앱을 중단시키지 않고 해당 창 안의 오류 화면으로 처리한다.
- 복원 payload는 문서 유형별 mapper에서 검증하고 기본값을 적용한다. 깨진 `form_state`가 있어도 DB의 정규 컬럼으로 복원할 수 있어야 한다.
- 임시문서 카드에는 `OS에서 열기`와 `모바일 미리보기`를 구분해 제공한다.

## 오류 처리

- 도킹 대상이 드래그 도중 닫히거나 최소화되면 후보를 취소하고 채팅은 자유 창으로 남긴다.
- 저장된 부모 창이 복원 시 존재하지 않으면 해당 연결을 제거한다.
- 대화 기록이 갱신되어 선택한 message ID가 사라지면 팝업을 닫는다.
- Telegram 전송 실패는 대화 턴 전체 실패로 바꾸지 않는다. 문서 저장 성공과 링크 전송 실패를 분리해 알려준다.
- 복원 화면에서 예외가 발생해도 Olivia OS 전체 error boundary로 전파하지 않는다.

## 테스트

### 단위 테스트

- 선택 tick 좌표에 따른 팝업 위치와 상·하단 제한
- 도킹 후보 임계값, 오른쪽 배치, 화면 경계 보정
- 메인 이동량이 서브 창에 동일하게 적용되는지
- 채팅 드래그 시작 시 연결 해제
- 메인 최소화·복원·닫기 시 서브 창 상태
- 선택 필드의 `null` 입력과 10% 할인·무료 서비스 항목 저장
- 실패 후 성공한 재시도 응답에서 이전 실패 문구 제거
- 같은 요청 재시도 시 중복 견적 방지
- 미리보기 성공 판정이 유효한 7일 토큰과 Telegram message ID까지 요구하는지
- 만료·취소·재발급 시 이전 토큰으로 문서가 노출되지 않는지
- 각 링크 생성·전송 실패 단계에서 성공 문구가 생성되지 않는지
- 문서 유형별 route와 복원 mapper

### UI 검증

- 기록바에서 팝업으로 천천히 또는 빠르게 이동해도 유지되고 버튼을 누를 수 있다.
- 견적서 왼쪽, 채팅 오른쪽 구성에서 가이드가 나타나고 놓으면 결합된다.
- 메인 창 이동·리사이즈·스냅에 채팅이 따라간다.
- 채팅을 직접 끌면 즉시 분리된다.
- 계약서와 콘티 창에서도 동일하게 동작한다.

### 통합 검증

- 패키지·서비스·할인·메모가 포함된 테스트 임시 견적서를 생성해 모든 요청 항목이 DB와 모바일 미리보기에 나타나는지 확인한다.
- Telegram에 7일 모바일 미리보기 버튼이 실제 도착하고 열리는지 확인한다.
- Telegram message ID가 대화 metadata에 저장되는지 확인한다.
- 공유 URL 발급 실패와 Telegram API 실패를 각각 모의해 저장 성공과 전송 실패가 구분되는지 확인한다.
- 데스크톱 및 모바일 Olivia OS의 `문서함 > 임시문서`에서 같은 문서를 확인한다.
- 임시문서 카드로 견적을 열었을 때 빈 폼이나 client-side exception 없이 정확한 DB 문서가 복원되는지 확인한다.

## 완료 기준

- 기록 네비게이터 팝업을 마우스로 열고 실제 버튼을 누를 수 있다.
- Olivia Chat이 메인 기능 창의 오른쪽에 도킹되고 메인 창을 따라 움직인다.
- 채팅창을 직접 드래그하면 연결이 해제된다.
- 견적 요청의 모든 항목과 할인이 실제 DB 및 합계에 반영된다.
- Telegram의 7일 미리보기 URL이 실제 문서를 모바일에 표시하며 성공 안내가 수신 결과와 항상 일치한다.
- 임시문서함에서 문서를 열 때 정확한 원본이 OS 내부 창에 복원되고 예외가 발생하지 않는다.
- 링크 발급 실패 시에도 사용자가 임시문서함에서 해당 문서를 바로 찾을 수 있다.
