# Olivia 사진 작업 직접 실행 우회 설계

작성일: 2026-09-20

## 목적

Hermes API Server가 Olivia MCP 도구를 실행 목록에 탑재하지 못하는 동안에도 사용자가 채팅에서 명시한 사진 원본 분리와 Scene 분류 작업을 기존 Olivia 사진 파이프라인으로 안전하게 주문할 수 있게 한다.

일반 대화와 사진 Scene 판단용 `OLIVIA_PHOTO_HERMES_BRAIN`은 기존 Hermes 경로를 유지한다. 새 파일 처리 파이프라인은 만들지 않는다.

## 활성화 조건

- `OLIVIA_PHOTO_DIRECT_EXECUTION` 값이 정확히 `1`일 때만 활성화한다.
- 미설정, 빈 문자열, `0` 및 그 밖의 값에서는 기존 동작을 유지한다.
- 분기 판단에는 현재 사용자가 직접 입력한 원문만 사용한다.
- Hermes 응답, 대화 요약, 메모 또는 모델이 생성한 텍스트에서는 실행 명령을 추출하지 않는다.
- Hermes가 해당 요청에서 사진 도구를 이미 호출했다면 직접 실행을 생략해 중복 작업을 막는다.

## 지원 의도

### 원본 분리

다음과 같이 명시적인 표현만 인식한다.

- 원본 분리
- RAW/JPG 분리와 이에 준하는 구분 표기
- 1차 분류
- JPG 통합

실행 순서:

1. `find_photo_folder`
2. 후보가 정확히 하나이면 `start_photo_source_prep`

### Scene 분류

다음 표현만 인식한다.

- Scene 분류
- 사진 분류
- Scene별 분류
- 2차 분류

실행 순서:

1. `find_photo_folder`
2. 진료과와 촬영모드 확인
3. `start_photo_scene_sort`

`RAW 매칭`, 리사이즈, 셀렉, 보정 등은 이 우회 범위에 포함하지 않는다.

## 실행 위치와 순서

직접 실행 분기는 기존 Hermes 채팅 응답을 받은 뒤, 최종 응답을 사용자에게 확정하기 전에 한 곳에서 수행한다.

1. 기존 방식으로 Hermes 응답을 생성한다.
2. Hermes 도구 실행 기록을 확인한다.
3. 사진 도구 실행 기록이 있으면 Hermes 결과를 그대로 사용한다.
4. 사진 도구 실행 기록이 없으면 환경변수와 사용자 원문을 검사한다.
5. 명확한 사진 명령이면 Olivia의 `executeAgentTool()`로 기존 도구를 호출한다.
6. 직접 실행 결과나 필요한 확인 질문으로 Hermes 원문을 교체한다.

이 구조는 Hermes가 추후 MCP 도구를 정상 호출하기 시작해도 같은 작업이 두 번 주문되지 않게 한다.

## 구성요소

### 사진 명령 파서

작은 독립 모듈이 다음 값만 반환한다.

- 작업 종류: `source_prep` 또는 `scene_sort`
- 사용자가 말한 폴더 검색어 목록
- 사용자 원문에서 명시적으로 확인되는 진료과
- 사용자 원문에서 명시적으로 확인되는 촬영모드

애매하거나 작업 표현만 있고 폴더 단서가 없으면 실행하지 않는다. 파서는 자연어를 넓게 추측하지 않고 명시적인 표현만 다룬다.

여러 폴더는 `이랑`, `랑`, `하고`, `와`, `과`, `그리고`, 쉼표 등 명확한 연결 표현으로 분리한다. 각 폴더는 독립 실행 단위다.

### 직접 실행 오케스트레이터

의존성 주입 가능한 함수로 만들고 다음 책임만 가진다.

- 각 검색어로 `find_photo_folder` 실행
- 0개·1개·복수 후보 분기
- 정확히 선택된 후보에만 쓰기 도구 실행
- 여러 폴더를 독립 처리하고 결과 수집
- 기존 완료·실패 상태의 재시작 확인 처리
- 사용자에게 보낼 결정적 결과 문구 생성

실제 NAS 조회, 프로젝트 생성, 잡 생성은 기존 `executeAgentTool()`과 기존 tool executor가 담당한다.

### 대화 대기 상태

후속 답변이 필요한 경우 대화 metadata에 `pendingPhotoDirectExecution`을 저장한다.

상태에는 다음 최소 정보만 둔다.

- 작업 종류
- 원래 요청한 폴더 검색어
- 현재 선택 대상의 후보 목록
- 이미 확정된 실제 폴더 경로
- Scene 분류의 진료과와 촬영모드
- 재시작 확인 필요 여부
- 여러 작업 중 완료·실패·대기 항목

절대경로나 비밀값은 저장하지 않는다. Source Root 기준 상대경로만 사용한다.

후속 사용자 원문은 다음 경우만 처리한다.

- 후보의 정확한 이름 또는 번호 선택
- 진료과·현장/스튜디오 정보 제공
- 완료 또는 실패 작업의 재실행 동의·거절

그 밖의 새 명령은 기존 대기 상태를 임의 실행하지 않고 일반 대화로 처리한다.

## 폴더 후보 처리

- 후보 0개: Workstation에서 찾지 못했다고 알리고 이름 확인을 요청한다.
- 후보 1개: 필요한 설정과 재실행 확인이 모두 충족되면 즉시 실행한다.
- 후보 여러 개: 이름, JPG/RAW 장수, 용량, 수정일, 현재 상태를 표시하고 하나를 고르게 한다.
- 후보 선택 전에는 쓰기 도구를 호출하지 않는다.
- 파일 업로드를 대안으로 제시하지 않는다.

## Scene 분류 확인

Scene 분류는 진료과와 촬영모드가 모두 있어야 실행한다.

- 값이 사용자 원문에 명시되어 있으면 사용한다.
- 누락되면 한 문장으로 필요한 값을 요청한다.
- 촬영모드는 `현장`을 `field`, `스튜디오`를 `studio`로만 변환한다.
- 진료과는 사용자가 말한 값을 그대로 전달하고 추측하지 않는다.

## 완료 작업과 재실행

후보의 `photo_storage_projects` 상태 또는 기존 시작 도구의 안전 오류를 기준으로 이미 완료되었거나 재실행 확인이 필요한 작업을 판별한다.

- 먼저 현재 상태를 알려준다.
- 사용자의 명시적 동의를 받은 뒤에만 `confirmRestart: true`로 다시 실행한다.
- 동의가 없으면 잡을 만들지 않는다.

## 응답과 스트리밍

사진 직접 실행 대상으로 판정된 요청은 Hermes 최종 문구를 그대로 노출하지 않는다. 다음 중 하나로 교체한다.

- 실행됨: 폴더별 주문 결과
- 복수 후보: 선택 질문
- 설정 부족: 진료과·촬영모드 질문
- 재실행 필요: 현재 상태와 재시작 확인 질문
- 검색 결과 없음: Workstation에서 찾지 못했다는 안내
- 실패: 폴더별 실패 원인과 원본 미변경 안내

도구 시작·완료 이벤트는 기존 스트림 이벤트 형식을 사용한다. 저장되는 assistant message에는 직접 실행한 도구 기록과 verification을 남긴다.

## 오류와 안전

- 후보 검색 실패는 쓰기 실행으로 이어지지 않는다.
- 한 폴더가 실패해도 다른 폴더 처리는 계속한다.
- 실패를 성공으로 표현하지 않는다.
- `executeAgentTool()`의 권한, 검증, 상태 머신과 기존 파일 안전장치를 우회하지 않는다.
- Hermes 응답에만 존재하는 폴더명이나 명령은 무시한다.
- 기존 `PHOTO_PREPARE_SOURCE`, `PHOTO_STAGE_JPG`, `PHOTO_CLASSIFY_WORK` 흐름만 사용한다.
- RAW 보호, symlink 거부, EXDEV 차단, 용량 검사, `.olivia-part`, 분류 전후 불변식은 변경하지 않는다.

## 로깅

민감정보와 절대경로를 기록하지 않고 다음만 구조화해 남긴다.

- 직접 실행 기능 활성 여부
- 감지한 작업 종류
- 검색어 개수
- 후보 개수
- 호출한 Olivia 도구 이름과 성공 여부
- 직접 실행을 생략한 이유 (`disabled`, `no_intent`, `hermes_already_called`, `needs_input`)

## 테스트

최소 회귀 테스트:

1. 환경변수가 없으면 직접 실행하지 않는다.
2. 일반 일정 질문은 사진 명령으로 인식하지 않는다.
3. Hermes가 사진 도구를 호출했으면 직접 실행하지 않는다.
4. 사용자 원문에는 명령이 없고 Hermes 답변에만 있어도 실행하지 않는다.
5. `0918 삼칠갈비 원본 분리해줘`에서 단일 후보이면 검색 후 원본 분리를 주문한다.
6. 복수 후보이면 쓰기 호출 없이 장수·용량·수정일을 포함해 되묻는다.
7. 후보가 없으면 파일 업로드를 안내하지 않는다.
8. Scene 분류는 진료과·촬영모드가 없으면 실행하지 않는다.
9. 설정 후속 답변을 받으면 선택된 같은 폴더로 분류를 주문한다.
10. 완료 작업은 확인 없이 재실행하지 않는다.
11. 명시적 재실행 동의 뒤에만 `confirmRestart: true`를 전달한다.
12. 여러 폴더 중 하나가 실패해도 나머지를 계속 처리하고 폴더별 결과를 반환한다.
13. 직접 실행 시 Hermes의 실행 불가 답변이 최종 응답에 남지 않는다.

전체 검증은 관련 단위 테스트, `npm run typecheck`, `npm run test`, `npm run build` 순으로 수행한다.

## 제거 가능성

모든 우회 진입은 한 모듈과 한 환경변수 분기에 모은다. Hermes API Server에서 MCP 호출이 정상화되면 `OLIVIA_PHOTO_DIRECT_EXECUTION`을 끄는 것만으로 기존 Hermes 도구 경로로 복귀할 수 있어야 한다.
