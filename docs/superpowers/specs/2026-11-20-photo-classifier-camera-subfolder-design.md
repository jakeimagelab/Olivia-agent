# 사진 분류 카메라 하위 폴더 지원 설계

## 목표

`촬영폴더/JPG전체/100MSDCF/*.JPG`처럼 카메라가 만든 하위 폴더가 남아 있어도 사진 분류가 촬영 프로젝트 이름과 진료과를 올바르게 판정하고, 여러 카메라 폴더의 JPG를 촬영시각 순서로 한 번에 분류한다. 결과 Scene 폴더는 카메라 폴더 내부가 아니라 `JPG전체` 바로 아래에 만든다.

## 폴더 의미 판정

- `isCameraGeneratedFolderName(name)`을 공통 순수 함수로 둔다.
- NFC 정규화, 대소문자 무시 후 다음을 의미 없는 관리 폴더로 본다.
  - `숫자 3자리 + 영문·숫자·밑줄 5자리`: `100MSDCF`, `100CANON`, `100EOS5D`, `100_FUJI` 등
  - `DCIM`, `PRIVATE`, `AVCHD`, `M4ROOT`, `CLIP`, `THMBNL`
  - `JPG전체`, `JPG원본`, `JPG`, `RAW`, `원본`
- 진료과·고객 판정은 전체 경로를 뒤에서 앞으로 읽어 처음 만나는 의미 있는 폴더명을 사용한다.
- 기존 단일 `folderName` 호출은 호환하되, 새 호출은 `folderPath: string[]`을 우선한다.

## 브릿지와 분류 입력 계획

- 브릿지는 현재 breadcrumb 전체 이름과 핸들을 분류 계획에 넘긴다.
- 현재 폴더가 카메라 폴더면 가장 가까운 `JPG전체` 핸들을 출력 루트로 사용한다.
- 현재 폴더가 `JPG전체`이고 바로 아래에 카메라 폴더만 있으면 모든 카메라 폴더를 입력으로 합친다.
- 각 JPG는 파일 핸들 외에 원본 부모 핸들, 상대 폴더명, 실제 출력 파일명을 유지한다.
- 촬영시각을 읽은 뒤 전체 입력을 하나로 정렬한다.
- 같은 파일명이 여러 원본 폴더에 있으면 해당 파일만 `<카메라폴더>_<파일명>`으로 출력 이름을 바꾼다.

## 파일 출력 안전 규칙

- Scene 폴더는 `JPG전체/<Scene 이름>`에 만든다.
- 원본 제거는 각 파일이 실제 들어 있던 `sourceDirectory.removeEntry(sourceName)`으로 수행한다.
- 카메라 하위 폴더는 비어도 삭제하지 않는다.
- 기존 평면 폴더 분류 동작은 유지한다.
- 브릿지 Scene 계획 검증은 basename이 아니라 상대 경로와 파일 메타데이터를 사용해 중복 이름도 구별한다.

## 진료과 미확인 처리

- 진료과를 찾지 못해도 분류 시작을 막지 않는다.
- 내부 실행값은 `general`을 사용하되 자동 판정 실패 상태를 별도로 유지한다.
- 화면은 `진료과 미확인 · 기타 기준으로 분류 · [변경]` 한 줄만 보이고, `[변경]`을 누를 때만 진료과 선택 목록을 연다.
- 충돌 상태도 실행을 막지 않고 `기타`로 시작하며 변경할 수 있게 한다.

## JPG 정리

- 하위 폴더 포함 시 기본값은 평탄화다.
- 평탄화 상태에서 파일명이 겹치면 충돌로 멈추지 않고 `<원본폴더>_<파일명>`으로 안전하게 구분한다.
- 구조 유지 옵션은 기존 사용자를 위해 계속 제공한다.

## 검증

- 카메라 폴더 판별과 의미 있는 프로젝트 폴더 선택 단위 테스트
- `0923_전주푸른안과/JPG전체/100MSDCF`에서 고객명과 안과 판정 테스트
- 두 카메라 폴더 통합·촬영순 정렬·중복 파일명 구분·`JPG전체` 출력 테스트
- 진료과 미확인 상태에서 실행 가능 여부 테스트
- JPG 평탄화 기본값과 중복 이름 계획 테스트
- TypeScript 및 관련 Vitest 통과
- 실제 또는 동일 구조의 브라우저 폴더에서 결과 위치를 화면으로 확인
