# Olivia Bridge 탐색·RAW 기본 폴더·Scene 승인·폴더 복원 설계

작성일: 2026-10-24

## 목적

Olivia Bridge의 현재 파일 탐색 상태를 유지하면서 다음 네 가지 불편을 해결한다.

1. 메인 썸네일 그리드에서 `ArrowUp`과 `ArrowDown`이 옆 사진으로 이동하는 문제
2. 분류된 JPG 하위 폴더를 연 뒤 RAW 매칭에서 상위 폴더를 다시 골라야 하는 문제
3. AI Scene 분류 검토창의 실행 버튼이 긴 결과 아래로 밀려 보이지 않는 문제
4. Bridge를 다시 열 때 마지막 작업 폴더를 다시 선택해야 하는 문제

기존 파일 처리, 선택·별점·컬러 레이블, 전체 미리보기, 사진 도구 실행 방식은 보존한다.

## 1. 메인 그리드 키보드 탐색

메인 썸네일 그리드의 방향키는 화면에 배치된 썸네일의 실제 위치를 기준으로 동작한다.

- `ArrowLeft`, `ArrowRight`: 현재 표시 순서의 바로 이전·다음 사진
- `ArrowUp`, `ArrowDown`: 현재 카드의 중심과 가로 위치가 가장 가까운 위·아래 행 사진
- 첫 행·마지막 행처럼 해당 방향에 사진이 없으면 현재 사진을 유지한다.
- 이동한 사진은 단일 선택·포커스되며 필요한 만큼만 `scrollIntoView` 한다.
- 창 너비, 좌우 패널 너비, 썸네일 크기가 바뀌어도 DOM 카드 위치로 대상을 계산한다.
- Space 전체 미리보기에서는 기존 동작을 유지한다. 왼쪽·위쪽은 이전 사진, 오른쪽·아래쪽은 다음 사진이다.
- 오른쪽 미리보기의 이전·다음 버튼도 기존 선형 이동을 유지한다.

방향 계산은 UI와 분리한 순수 함수로 두고, 3열·4열·불완전한 마지막 행·가장자리 동작을 단위 테스트한다.

## 2. RAW 매칭 기본 검색 폴더

Bridge는 현재 폴더와 별도로 RAW 매칭에 제안할 폴더 핸들을 사진 도구 실행 컨텍스트에 보관한다.

- 사용자가 Bridge 폴더 트리에서 하위 `JPG` 폴더로 들어오면 breadcrumb의 바로 위 폴더를 RAW 매칭 기본 검색 폴더로 전달한다.
- RAW 매칭 도구를 열면 이 기본 폴더를 먼저 표시하고 사전 확인에 사용한다.
- 사용자는 기존 `다른 RAW 폴더 선택` 동작으로 언제든 검색 폴더를 바꿀 수 있다.
- JPG 폴더 자체를 최초 폴더로 직접 선택해 상위 폴더 핸들이 없는 경우에는 기존 동작을 그대로 사용한다. 부모 경로를 문자열로 추측하거나 권한 밖 폴더에 접근하지 않는다.
- Bridge의 현재 JPG 폴더, JPG 선택 목록, 별점 연동은 그대로 유지한다.
- RAW 복사·이동 안전 검증과 원본 유지 기본값은 바꾸지 않는다.

## 3. AI Scene 분류 검토창

검토창은 헤더, 스크롤 가능한 결과 본문, 고정 실행 바의 세 영역으로 구성한다.

- Scene 카드만 본문에서 스크롤된다.
- 하단 실행 바는 창 크기와 결과 수에 관계없이 항상 보인다.
- 실행 바에 `Scene N개 · JPG N장 · 경계 확인 N곳` 요약을 표시한다.
- 주 실행은 `승인하고 분류 실행` 하나다.
- 분석 중에는 버튼을 비활성화하고 현재 진행 상태를 표시한다.
- 승인 전에는 파일 이동·이름 변경을 실행하지 않는다.
- 승인하면 현재 Bridge 폴더와 선택 상태를 유지한 채 기존 사진 분류 도구를 연다.
- 오류 상태에서는 기존 재시도 동작을 보존한다.

현재 문제의 원인은 진행 막대가 조건부로 사라질 때 CSS의 고정 행 수와 실제 자식 수가 달라지는 것이다. 진행·오류 영역을 결과 본문 안에 묶어 자식 수와 무관한 레이아웃으로 수정한다.

## 4. 마지막 폴더 복원

최근 breadcrumb의 이름과 `FileSystemDirectoryHandle` 배열을 IndexedDB에 저장한다. 경로 문자열만 저장하지 않는다.

- Bridge에서 폴더를 열거나 하위 폴더로 이동할 때 마지막 breadcrumb를 갱신한다.
- 다음 Bridge 실행 시 저장된 각 핸들의 읽기 권한을 확인한다.
- 활성 폴더 권한이 이미 `granted`이면 마지막 폴더를 즉시 스캔해 복원한다.
- 권한 상태가 `prompt`이면 자동 권한 요청을 반복하지 않고 `지난 폴더 다시 열기` 버튼을 보여준다. 사용자가 누른 동작에서 권한을 요청하고 성공하면 복원한다.
- 권한이 거절됐거나 핸들이 더 이상 유효하지 않으면 복원 실패 이유를 한 줄로 보여주고 기존 `폴더 선택`을 제공한다.
- 새 폴더를 정상적으로 선택하면 오래된 복원 오류를 지우고 새 breadcrumb로 교체한다.
- breadcrumb 전체를 복원하므로 마지막 폴더의 상위 핸들도 RAW 매칭 기본값에 재사용할 수 있다.

저장 정보는 브라우저 로컬 IndexedDB에만 남고 서버나 Supabase로 전송하지 않는다.

## 5. 상태와 오류 처리

- 방향 이동에 유효한 대상이 없으면 아무 상태도 바꾸지 않는다.
- RAW 기본 폴더가 없으면 기존 RAW 매칭 화면과 동작을 그대로 사용한다.
- 저장된 폴더 복원 실패는 Bridge 전체 오류로 취급하지 않는다. 사용자는 즉시 다른 폴더를 선택할 수 있다.
- Scene 승인 바는 분석 성공 전에는 외곽선형 비활성 상태와 다음 할 일 문구를 사용한다.
- 사진 처리 API, 원격 작업, 파일 변경 실행 코드는 이번 작업에서 변경하지 않는다.

## 6. 검증

### 자동 테스트

- 3열과 4열에서 상·하·좌·우 대상 계산
- 마지막 행의 칸 수가 부족할 때 가장 가까운 열 선택
- 그리드 가장자리에서 이동하지 않음
- breadcrumb가 있는 경우 상위 폴더가 RAW 기본값이 됨
- 최초 선택 폴더라 부모가 없으면 기존 동작 유지
- Scene 창의 고정 실행 바 구조와 요약 계산
- 마지막 breadcrumb 저장값 검증과 권한 상태별 복원 판정
- 기존 Olivia Bridge 및 사진 도구 연동 테스트 회귀

### 수동 확인

- 패널 폭과 썸네일 크기를 바꾼 뒤 `ArrowUp`, `ArrowDown` 이동
- Space 전체 미리보기의 기존 이전·다음 이동
- `촬영 폴더/JPG`로 이동한 뒤 RAW 매칭 기본 폴더가 `촬영 폴더`인지 확인
- 처음부터 `JPG`만 선택했을 때 기존 RAW 폴더 선택 동작 확인
- Scene 결과가 긴 경우에도 승인 버튼이 항상 보이는지 확인
- Bridge를 닫았다 다시 열었을 때 마지막 폴더 자동 복원
- 권한이 만료된 경우 `지난 폴더 다시 열기` 동작 확인
- 타입 검사, 린트, 관련 테스트, 빌드 실행

## 7. UI 규칙

- Bridge의 중성 다크 톤과 기존 민트 선택·실행 색을 유지한다.
- 새 탭이나 새 색은 추가하지 않는다.
- Scene 창의 채운 주 실행 버튼은 하나만 둔다.
- 기존 공통 사진 도구, 실행 컨텍스트, 이동식 창을 재사용한다.
- 글자 굵기는 600을 넘기지 않고 아이콘은 기존 lucide 선 아이콘만 사용한다.
