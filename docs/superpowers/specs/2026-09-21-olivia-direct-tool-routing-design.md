# Olivia 직접 도구 실행 라우팅 설계

작성일: 2026-09-21

## 목적

Hermes API Server가 Olivia MCP 도구를 호출하지 못하는 동안에도 채팅의 실행 요청이 정상적으로 처리되게 한다. Hermes는 일반 대화와 추론을 담당하고, 실행 요청은 Olivia의 기존 도구 실행 경로가 담당한다.

새 실행 파이프라인은 만들지 않는다. 기존 `selectOliviaTools()`, OpenAI Responses 도구 루프, `executeAgentTool()`, UI action, 승인 상태, 원격 워커 잡을 그대로 재사용한다.

## 엔진 선택

새 환경변수는 `OLIVIA_DIRECT_TOOL_EXECUTION`이다.

- 값이 없거나 `1`이면 직접 실행 라우팅을 활성화한다.
- `0`이면 직접 실행 라우팅을 비활성화하고 기존 Hermes MCP 경로로 복귀한다.
- `OLIVIA_AGENT_ENGINE=legacy`이면 기존처럼 모든 요청을 legacy 경로에서 처리한다.

Hermes가 기본 엔진이고 직접 실행 라우팅이 활성화된 경우 다음 요청은 Hermes를 건너뛴다.

- `TOOL_ACTION`
- 실행성 `FAST_COMMAND`
- 코드가 확정한 화면 동작
- 기존 database fast path로 처리 가능한 요청

`NORMAL_CHAT`과 `REASONING`은 Hermes가 계속 처리한다.

## 실행 흐름

### 웹에서 바로 실행되는 도구

캘린더, 견적, 계약, 메모, 문서, 화면 열기·닫기와 같은 요청은 기존 Olivia 도구 선택과 `executeAgentTool()`을 거친다. 성공한 UI action은 현재 스트림 이벤트로 브라우저에 전달한다. 기존 승인 카드와 실행 검증 규칙을 유지한다.

### 맥스튜디오 워커가 필요한 도구

사진 원본 분리와 씬 분류는 기존 사진 도구가 기존 remote job을 생성한다. 파일 조작 코드를 새로 만들지 않으며 RAW 보호, 충돌 검사, 임시 파일, 복사 검증, 상태 머신을 변경하지 않는다.

현재 사진 전용 직접 실행기가 제공하는 다음 동작은 Hermes 호출 이전으로 옮겨 보존한다.

- 폴더 후보 검색과 복수 후보 확인
- 폴더명 재입력
- 완료 작업 재시작 확인
- 씬 분류 진료과·촬영모드 확인
- 여러 폴더의 독립 실행 및 결과 보고

사진 직접 실행이 요청을 처리하지 않은 경우에는 일반 Olivia 도구 루프가 이어서 처리한다.

## 대화와 상태

사용자 원문만 실행 의도 판단에 사용한다. Hermes 응답, 대화 요약, memory에만 등장한 명령으로 작업을 실행하지 않는다.

기존 pending action과 사진 pending state는 대화 metadata에 그대로 저장한다. 짧은 승인·수정 답변은 저장된 정확한 도구와 입력을 사용한다.

실행 결과 문구는 실제 도구 결과로 만든다. 성공 기록 없이 완료를 주장하지 않으며, Hermes의 실행 불가 문구를 실행 결과와 섞지 않는다.

## 관측성

라우팅 로그에는 다음을 기록한다.

- 요청된 엔진
- 실제 사용한 엔진
- request class
- 직접 실행 활성화 여부
- 우회 이유
- 선택 도구 수와 실제 도구 호출 결과

환경변수를 `0`으로 바꾸면 코드 배포 없이 기존 Hermes MCP 실행 경로로 되돌릴 수 있다.

## 오류 처리

- legacy 실행에 필요한 모델 설정이 없으면 기존 설정 오류를 반환한다.
- 웹 도구 실패는 해당 도구 결과만 실패로 보고한다.
- 워커 잡 생성 실패는 파일 작업을 시작한 것으로 표시하지 않는다.
- 하나의 실행 실패 때문에 일반 대화 경로 또는 다른 독립 작업을 임의로 실행하지 않는다.
- 동일 요청 재전송 시 기존 idempotency와 중복 실행 방지 로직을 유지한다.

## 테스트

다음 회귀 테스트를 추가한다.

1. 직접 실행 활성화 시 `TOOL_ACTION`은 legacy로 간다.
2. 실행성 `FAST_COMMAND`와 확정적 UI 동작은 legacy로 간다.
3. 일반 대화와 추론은 Hermes로 간다.
4. `OLIVIA_DIRECT_TOOL_EXECUTION=0`이면 `TOOL_ACTION`도 Hermes로 돌아간다.
5. 캘린더·견적·메모 도구가 기존 실행기를 통해 실행된다.
6. 화면 열기·닫기 UI action이 기존 스트림으로 전달된다.
7. 사진 원본 분리와 씬 분류가 기존 워커 잡을 생성한다.
8. 사진 후보 선택과 씬 설정 pending state가 유지된다.
9. Hermes 응답에만 있는 명령은 실행되지 않는다.
10. 기존 승인·검증·중복 방지 테스트가 모두 통과한다.

검증 명령은 `npm run typecheck`, `npm run test`, `npm run build`다.
