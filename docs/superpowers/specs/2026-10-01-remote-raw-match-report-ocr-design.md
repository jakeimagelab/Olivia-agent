# Remote RAW 매칭 — 셀렉 리포트 OCR 설계

## 목적

RAW 매칭에 셀렉 리포트 이미지(스크린샷 포함)를 올렸을 때, 이미지 안에 표기된 JPG 파일명을 읽어 RAW 매칭 대상으로 사용할 수 있게 한다. 현재 JPG/EXIF 기반 매칭과 Mac Studio의 RAW 원본 복사 로직은 변경하지 않는다.

## 범위

- 원격 RAW 매칭 화면의 업로드 이후에만 `이미지 속 파일명 분석` 동작을 제공한다.
- 리포트 이미지에서 `R5K04439.JPG`, `IMG_1001.jpeg`처럼 JPG/JPEG 확장자를 가진 파일명만 추출한다.
- 추출 결과는 NFC·대소문자 기준으로 중복 제거한다.
- 이미 불러온 JPG 목록과 일치하면 해당 사진을 자동 선택한다.
- 목록에 없는 이름도 매칭 후보로 보존하고, `목록에서 찾지 못한 파일명`으로 별도 표시한다. 이 이름은 사용자가 확인한 뒤 RAW 매칭 요청에 포함할 수 있다.
- 결과를 확인한 뒤에만 기존 RAW 복사 작업을 주문한다.

## 선택한 방식

이미지 전체를 자동 분석하지 않는다. 사용자가 셀렉 리포트/스크린샷을 올린 뒤 명시적으로 분석을 실행한다. 촬영 JPG 수백 장에 불필요한 OCR을 실행하지 않으며, 일반 촬영 이미지에서 우연히 읽힌 문자열로 선택이 바뀌는 것을 막는다.

OCR은 기존 서버 AI 이미지 분석 경로를 재사용해 요청 이미지에서 파일명 후보만 구조화해 반환한다. 서버는 이미지를 저장하지 않고 요청 처리 후 폐기한다. 모델 응답은 파일명 정규화 함수로 다시 검증해, 경로·RAW 확장자·임의 문자열은 RAW 작업 payload에 들어가지 못하게 한다.

## 사용자 흐름

1. 사용자가 JPG 폴더/파일 또는 셀렉 리포트 이미지를 올린다.
2. `이미지 속 파일명 분석`을 누른다.
3. 추출된 JPG 파일명을 보여준다.
   - 현재 불러온 JPG와 일치: 자동 선택됨
   - 현재 목록에 없음: 확인 필요 목록에 표시
4. 사용자가 확인한 이름만 포함한 상태에서 NAS 촬영 폴더를 선택하고 RAW 복사를 시작한다.

## 안전성

- OCR은 RAW를 직접 찾거나 복사하지 않는다.
- OCR 결과는 `parseRemoteSelectedFileNames`와 동일한 JPG/JPEG·basename·Unicode 검증을 거친다.
- 원본 RAW 처리, 중복 방지, 복사/검증, 재시작 확인은 기존 `PHOTO_RAW_MATCH` 작업을 그대로 사용한다.
- OCR 실패 또는 0개 인식은 기존 직접 선택 상태를 변경하지 않는다.

## 테스트

- `R5K04439.JPG`, `r5k04410.jpg`, `R5K04351.JPG` 텍스트에서 중복 없이 JPG 이름을 추출한다.
- RAW·경로·비파일명 문자열은 제외한다.
- OCR로 추출한 이름이 기존 사진 목록과 일치하면 자동 선택한다.
- 목록에 없는 이름은 미확인 후보로 유지한다.
- OCR 실패 시 기존 수동 선택은 유지된다.
