# 진료과별 AI 콘티 생성 로직 설계

## 목표

Olivia 콘티 V2를 사용자가 콘티를 직접 편집해 만드는 도구가 아니라, 진료과와 최소한의 촬영 조건을 선택하면 촬영 가능한 장면표를 자동 생성하는 시스템으로 완성한다.

진료과별 기본 체크 항목은 애플리케이션 코드가 원본(source of truth)이 된다. `scene_templates` 테이블이 없거나 비어 있어도 제작 화면, 실시간 미리보기, 콘티 생성이 모두 작동해야 한다. DB는 병원별 공간·의료진 정보, 선택적으로 추가되는 사례 기반 템플릿, 생성 결과 저장에 사용한다.

## 범위

이번 변경에 포함한다.

- 진료과별 대분류와 세부 촬영 항목
- 의료진 수에 따른 주요 장면 복제 및 의료진별 순서 구성
- 실장·직원·기타 역할 촬영 장면
- 로비 하모니컷
- 자유 입력 기타 촬영 항목
- 장소, 시간, 설명, 필요 인원, 준비사항, 비고의 기본 생성
- DB 템플릿 조회 실패 또는 빈 결과에 대한 코드 데이터 fallback
- 제작 화면의 선택 UI와 실시간 예상 결과
- 순수 생성 로직 단위 테스트

기존 결과 표 편집, 현장뷰, 공유 링크, PDF 기능의 구조는 유지하며 신규 필드를 읽을 수 있도록 필요한 범위만 확장한다.

## 진료과 모델

진료과는 한 번에 하나를 선택한다. 복수 진료과 병원은 대표 촬영 콘티를 진료과별로 각각 생성하는 것을 기본 흐름으로 삼는다. 이는 서로 다른 진료과의 장면이 한 체크리스트에 섞여 복잡해지는 것을 방지한다.

우선 지원 진료과는 다음과 같다.

- 치과
- 피부과
- 정형외과
- 재활의학과
- 신경외과
- 마취통증의학과
- 한방병원·한의원
- 안과
- 산부인과
- 성형외과
- 소아과·소아청소년과
- 요양병원

정형외과, 재활의학과, 신경외과, 마취통증의학과는 동일한 근골격·통증 중심 taxonomy를 사용하되 선택한 실제 진료과 이름은 결과에 보존한다. 한방병원과 한의원, 소아과와 소아청소년과도 각각 공용 taxonomy와 별칭 정규화를 사용한다.

코드 데이터의 각 대분류는 다음 정보를 가진다.

- 표시명과 안정적인 키
- 세부 체크 항목 목록
- 결과 장면명
- 기본 장소
- 기본 촬영 시간
- 장면 설명
- 기본 필요 역할
- 준비사항
- 비고
- 의료진별 복제 여부
- 환자 역할 규칙

세부 항목은 별도 장면이 아니라 해당 대분류 장면의 `procedures`로 저장한다. 예를 들어 피부과 리프팅에서 울쎄라와 써마지를 선택하면 장면은 하나의 `리프팅 시술`로 만들고, 세부 시술에 울쎄라와 써마지를 함께 표시한다.

## 공통 입력 UI

제작 화면은 다음 순서로 구성한다.

1. 병원 선택(선택 사항)
2. 진료과 단일 선택
3. 의료진 수
4. 촬영 참여 역할: 실장, 직원, 기타
5. 하모니컷 여부
6. 진료과별 대분류와 세부 촬영 항목
7. 기타 촬영 항목 자유 입력

`기타` 역할을 선택하면 역할명 입력란을 바로 표시한다. 기타 촬영 항목은 여러 개 추가·삭제할 수 있으며 각 항목은 독립 장면으로 생성한다.

오른쪽 예상 결과에는 장면 수, 총 예상 시간, 생성 예정 장면 순서를 즉시 표시한다. 데이터베이스 템플릿을 불러오지 못해도 코드 기본 데이터로 예상 결과를 계산하며, 이 경우 차단성 오류 대신 `기본 콘티 데이터 사용 중`이라는 짧은 상태 안내를 표시한다.

## 장면 생성 규칙

생성 순서는 사람과 촬영 동선을 모두 고려한 결정론적 규칙을 우선 적용한다.

1. 직원 촬영을 선택하면 접수·안내 장면을 앞부분에 추가한다.
2. 각 의료진에 대해 상담 장면을 만든다.
3. 의료진별 복제가 필요한 선택 대분류 장면을 같은 의료진 아래에 배치한다.
4. 의료진별 복제가 필요 없는 검사, 직원 업무, 치료사 중심 장면은 한 번만 추가한다.
5. 실장 촬영을 선택하면 실장 상담을 추가한다.
6. 기타 역할을 선택하면 해당 역할 장면을 추가한다.
7. 자유 입력 기타 촬영 항목을 추가한다.
8. 하모니컷을 선택하면 로비 하모니컷을 마지막에 추가한다.

예를 들어 피부과, 의료진 2명, 리프팅·스킨부스터·색소, 실장·직원·하모니컷을 선택하면 다음 순서를 만든다.

1. 접수·안내
2. 원장1 상담
3. 원장1 리프팅 시술
4. 원장1 스킨부스터 시술
5. 원장1 색소 치료
6. 원장2 상담
7. 원장2 리프팅 시술
8. 원장2 스킨부스터 시술
9. 원장2 색소 치료
10. 실장 상담
11. 직원 업무
12. 로비 하모니컷

선택한 대분류가 여러 개일 때 무조건 서로 합치지 않는다. 같은 촬영 행위와 장소를 공유하도록 taxonomy에 명시한 항목만 하나의 장면으로 묶는다. 세부 치료는 항상 부모 대분류 장면에 묶는다.

## 진료과별 특수 규칙

- 소아과·소아청소년과의 환자 역할은 기본적으로 `아이, 보호자`이며 의료진 장면의 필요 인원은 `원장N, 아이, 보호자`로 생성한다.
- 요양병원은 치료 장면뿐 아니라 회진, 간호, 병동생활, 보호자 상담, 간병, 시설 및 프로그램을 독립 대분류로 제공한다. 설명 문구에는 돌봄, 재활, 일상생활, 직원과 환자의 관계를 반영한다.
- 산부인과는 산과 및 출산 관련 항목을 제공하지 않고 로컬 부인과 진료와 여성 시술 중심으로 구성한다.
- 정형외과 계열은 뇌·척수 수술 중심 분류를 사용하지 않고 진료, 검사, 주사, 체외충격파, 도수·물리·운동치료 중심으로 구성한다.
- 한방병원은 한의원 공통 항목에 더해 병동, 입원, 회진, 재활, 협진 항목을 선택적으로 제공한다.

## 데이터와 DB 경계

정적 taxonomy 모듈은 UI와 서버 생성 로직이 함께 import할 수 있는 순수 TypeScript 데이터로 만든다. 클라이언트가 DB 응답을 기다리지 않고 체크리스트를 즉시 표시하도록 한다.

`scene_templates`는 필수 의존성이 아니다. 조회에 성공하면 코드 taxonomy에 없는 사례 기반 장면이나 운영자가 추가한 장면만 병합한다. 동일한 진료과와 장면 키가 충돌하면 코드 기본값을 우선한다. 이렇게 해야 모든 배포 환경에서 기본 콘티 품질이 동일하다.

생성 결과를 저장하는 `conti_runs`, `conti_groups`, `conti_scenes` 테이블이 없는 환경에서는 저장 API가 명확한 설정 오류를 반환한다. 제작 화면과 미리보기는 계속 사용할 수 있지만 결과 화면·현장뷰·공유로 넘어가려면 생성 결과 저장용 마이그레이션이 필요하다. 생성 API에서 일부 행만 저장된 경우에는 생성한 run과 하위 데이터를 정리하거나 원자적 DB 함수로 저장해 불완전한 콘티가 남지 않게 한다.

## 결과 데이터

각 결과 장면은 다음 필드를 유지하거나 추가한다.

- 순서
- 장면명
- 그룹 또는 층
- 장소
- 예상 촬영 시간
- 장면 설명
- 세부 치료·시술
- 필요 인원
- 환자 역할
- 준비사항
- 비고
- 원본 템플릿 키와 필드 출처

결과 표에서는 장면명, 장소, 시간, 설명, 필요 인원, 준비사항, 비고를 직접 수정할 수 있다. 세부 치료는 장면명과 분리해 보존하므로 사용자가 결과를 수정해도 최초 선택 내용을 잃지 않는다.

## 오류 처리

- 템플릿 API 오류: 코드 기본 데이터로 계속 동작하고 비차단 안내를 표시한다.
- 병원 공간·직원 API 오류: 일반 장소명과 역할명을 사용해 계속 동작한다.
- 선택한 촬영 항목 없음: 상담 및 선택한 공통 장면만 미리보기하고, 생성 버튼 주변에 세부 항목 선택을 권장한다.
- 결과 저장 실패: 결과 화면으로 이동하지 않고 재시도 가능한 오류를 표시한다.
- 빈 장면 저장: 금지한다. 최소 상담 장면 한 개를 보장한다.

## 테스트 기준

순수 생성 함수 단위 테스트로 다음을 검증한다.

- DB 템플릿 없이 모든 지원 진료과의 체크리스트와 장면을 생성한다.
- 같은 대분류의 세부 시술 여러 개가 장면 하나에 묶인다.
- 의료진 2명일 때 상담과 의료진 중심 시술이 각각 원장1·원장2로 분리되고 의료진별로 정렬된다.
- 직원, 실장, 기타 역할, 하모니컷 장면이 정확히 한 번 추가된다.
- 소아과 필요 인원에 아이와 보호자가 포함된다.
- 산부인과 taxonomy에 출산·분만 항목이 없다.
- 정형외과 계열이 동일 taxonomy를 사용하면서 실제 진료과 이름을 보존한다.
- 기타 촬영 항목이 입력 순서대로 생성된다.
- DB에서 받은 추가 템플릿의 병합과 코드 데이터 우선순위가 안정적이다.

API 테스트 또는 통합 테스트로 저장 성공, 저장 실패, 템플릿 조회 실패를 검증한다. 기존 결과 표와 현장뷰는 신규 장면의 준비사항을 표시하고 완료 상태 및 현장 메모 동작을 유지해야 한다.

## 완료 조건

- 신규 환경에서 `scene_templates` 시드 없이 진료과별 체크 항목이 보인다.
- 사용자가 최소 입력으로 생성한 장면 순서가 정의된 자동 로직과 일치한다.
- 주어진 모든 우선 진료과의 대분류와 세부 항목이 반영된다.
- 미리보기와 서버 저장 결과가 동일한 생성 함수를 사용해 서로 어긋나지 않는다.
- 기존 결과 수정, 현장뷰, 공유 흐름이 깨지지 않는다.
