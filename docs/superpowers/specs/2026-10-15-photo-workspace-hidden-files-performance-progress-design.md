# 사진작업실 숨김파일·성능·JPG정리 진행 표시 설계

작성일: 2026-10-15  
대상: `main`의 JPG정리 탭 적용본

## 목표

사진작업실 브라우저 경로에서 macOS 숨김파일을 사진으로 집계하지 않고, 대량 사진을 준비할 때 UI가 과도하게 다시 그려지지 않도록 하며, JPG정리 실행 중 실제 처리량 기반 진행 상태와 안전한 중지를 제공한다.

기준 폴더는 `/Volumes/JAKEPHOTO2T/2026/1009_양재선(결혼)/JPG전체`이다. 2026-10-15 실측값은 실제 JPG 1,637개와 `._` 숨김 JPG 1,637개로, 기존 확장자 기반 집계는 3,274개다. 수정 후 사진 셀렉 후보 수는 1,637개여야 한다. 이 폴더는 이미 `JPG전체`이므로 JPG정리 입력으로는 차단한다.

## A. macOS 숨김파일 제외

- `lib/photo/extensions.ts`에 `isHiddenSystemFile(name)`을 추가한다. 이름이 `.`으로 시작하면 `true`다.
- 다음 다섯 브라우저 스캔 경로에서 파일 확장자를 읽기 전에 호출한다.
  1. `lib/selectMatch/folderScanner.ts`
  2. `lib/photo-classifier/countJpgFiles.ts`
  3. `components/photo-classifier/PhotoSortingWorkspace.tsx`의 공용 RAW/JPG 분리 함수
  4. `components/photo-workspace/PhotoJpgPrepWorkspace.tsx`의 파일 스캔
  5. `components/photo-workspace/PhotoJpgPrepWorkspace.tsx`의 폴더 재귀 진입
- 숨김 파일과 숨김 폴더는 세거나 목록에 넣지 않는다. 이동·복사·삭제하지 않는다.
- JPG정리 계획에 제외한 숨김 항목 수를 보관하고, 0보다 클 때만 `맥 숨김파일 N개는 제외했습니다.`를 안내한다.
- 원본 폴더 이름은 폴더 선택 영역과 머리글 chip에 표시한다.
- `JPG_INTEGRATED_DIRECTORY` 폴더는 재귀 스캔에서 제외하고, 그 폴더 자체를 선택하면 `이미 정리된 폴더입니다. 촬영 폴더를 선택하세요.`로 차단한다.
- 하위 폴더 구조 유지 옵션 기본값은 `true`다.

## B. 대량 사진 렌더링 비용 제한

### 상태 갱신

- 반복 작업의 화면 상태는 마지막 표시 후 120ms가 지났거나 20장 단위일 때만 갱신한다.
- 마지막 항목은 조건과 무관하게 반드시 갱신한다.
- 처리 순서, 전체 개수, 현재 번호 계산은 바꾸지 않는다.

### 썸네일 메모리

- `AiPhotoSelectPanel`, `PhotoTcutWorkspace`, `SelectMatchWorkspace`의 썸네일 생성은 `canvas.toDataURL()` 대신 `canvas.toBlob()`과 `URL.createObjectURL()`을 쓴다.
- 폴더 교체, 후보 초기화, 컴포넌트 해제 시 Object URL을 회수한다.
- 썸네일 크기 360px과 JPEG 품질 0.72는 유지한다.

### 제한 렌더링과 브라우저 양보

- JPG정리 결과 표는 충돌·오류를 먼저 정렬한 뒤 최대 40줄만 렌더링하고 나머지는 `… 외 N개`로 표시한다.
- 사진 셀렉 후보는 처음 200장만 렌더링하고 `더 보기`로 200장씩 늘린다. 선택·분석 대상 데이터는 전체를 유지한다.
- 썸네일 생성은 순차 처리 구조를 유지하며 20장마다 `setTimeout(..., 0)`으로 브라우저에 제어를 돌려준다.

### 상태표시줄 폴링

- `PhotoTaskStatusBar`는 화면이 보이고 작업이 있으면 5초, 숨겨졌으면 60초, 표시할 작업이 없으면 30초 간격으로 조회한다.
- 화면이 다시 보이면 즉시 한 번 조회하고 5초 주기로 돌아간다.
- `PhotoStudioBackgroundJobBridge`는 수정하지 않는다.

## C. JPG정리 실제 진행 상태와 중지

- 로컬 실행 중 `3. 결과`를 실제 진행 화면으로 교체한다.
- 진행률은 `처리한 행 수 / 미리보기에서 확인한 전체 행 수`로만 계산한다.
- 현재 파일명과 옮김·건너뜀·충돌 수를 표시한다.
- 진행 화면 갱신은 B와 동일하게 120ms 또는 20장마다, 마지막 항목은 반드시 갱신한다.
- 중지는 ref로 요청 상태를 기록한다. 현재 파일은 끝까지 처리하고 다음 파일부터 루프를 종료한다.
- 이미 옮긴 파일은 되돌리지 않는다. 결과 계획과 목적지 상태를 유지해 다음 실행에서 기존 파일을 건너뛰고 이어간다.
- 중지 문구는 `중지했습니다. 전체 N개 중 M개를 옮겼습니다. 다시 실행하면 남은 것만 이어서 합니다.` 형식이다.
- 충돌이 있으면 결과 표의 맨 위에 표시하고, 실패 이유는 사라지지 않는다.
- 남은 시간 예측이나 가짜 애니메이션은 추가하지 않는다.

## 보존 범위

- RAW 파일은 어떤 경로에서도 이동·복사·삭제하지 않는다.
- 서버 숨김파일 가드, `lib/photo-classifier/node/**`, `storageLayout.ts`, `moveFileFast`는 수정하지 않는다.
- 사진 분류·셀렉·T컷의 판정 알고리즘과 처리 순서는 유지한다.
- 가상 스크롤 또는 다른 패키지를 설치하지 않는다.
- UI는 기존 `WorkspaceSurface.module.css`의 중성 다크 패널과 버튼 역할을 유지한다.

## 검증

- 숨김 파일·폴더 제외와 JPG정리 계획을 단위 테스트한다.
- Object URL 생성·회수, 후보 200장 증가, 결과 표 40줄, 중지와 이어하기를 가능한 범위에서 테스트한다.
- 기준 SSD 폴더를 터미널에서 실측하고 사진 셀렉 스캔 결과와 비교한다.
- 넓은 폭과 좁은 폭에서 JPG정리 준비·진행·완료 화면을 확인한다.
- `npm run typecheck`, 변경 파일 ESLint, 관련 Vitest, 전체 Vitest와 프로덕션 빌드를 실행한다.
