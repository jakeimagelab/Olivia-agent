# 견적서 부가세·번호 및 Dock 정렬 설계

## 목표

포토클리닉과 제이크이미지연구소 견적서에 부가세 표기 방식을 명시적으로 저장하고, 새 견적 번호 형식과 Olivia OS Dock 순서를 적용한다.

## 부가세 방식

견적서는 `separate`(기존 기본값), `excluded`, `included` 중 하나의 부가세 방식을 저장한다.

| 방식 | 계산 | 문서 하단 표기 |
| --- | --- | --- |
| 부가세 별도 | 공급가의 10%를 반올림해 더한다 | 공급가액 / 부가세(10%) / 합계 |
| 부가세 제외 | 부가세를 0원으로 하고 공급가를 그대로 합계로 쓴다 | 공급가액 / 부가세 제외 / 합계 |
| 부가세 포함 | 사용자가 입력한 금액을 합계로 고정하고, 공급가와 부가세를 역산한다 | 공급가액 / 부가세 포함(10%) / 합계 |

부가세 포함의 역산은 `합계 - round(합계 / 11)`을 부가세로 하고, 나머지를 공급가로 한다. 예를 들어 1,800,000원은 공급가 1,636,364원과 부가세 163,636원으로 저장·표시한다. 계약금과 잔금은 세 방식 모두 최종 합계를 기준으로 계산한다.

`computeQuoteTotals`를 단일 계산 원본으로 유지하고, QuoteBuilder·채팅 미리보기·문서 데이터·PDF가 같은 저장된 부가세 방식을 전달한다. 과거 견적은 저장값이 없을 때 `separate`로 읽어 기존 결과를 보존한다.

## 견적 번호

새로 생성하는 견적의 날짜별 순번은 네 자리이며 `0002`에서 시작한다.

| 브랜드 | 새 형식 |
| --- | --- |
| 포토클리닉 | `PCQ-YYYYMMDD-0002` |
| 제이크이미지연구소 | `JKQ-YYYYMMDD-0002` |

당일·동일 브랜드의 새 접두사 번호만 조회해 가장 큰 순번 다음 값을 발급한다. 기존 `PC-`·`JI-`·시간형 `Q-` 번호는 과거 문서 및 계약 연결을 위해 변경하지 않는다.

## UI

QuoteBuilder의 금액 영역에 `부가세 별도 / 부가세 제외 / 부가세 포함`을 하나의 선택 그룹으로 둔다. 선택된 방식만 활성 상태로 보이며, 금액 요약과 미리보기 문구는 저장할 방식과 동일하게 갱신된다. 밝은 견적 화면은 기존 밝은 화면 버튼 규칙을 따른다.

## Dock

Dock 앱 항목을 다음 순서로 고정한다.

`전체앱보기 → 캘린더 → 고객관리 → 문서함 → 사진작업실 → 영상작업실 → 메모 → 채팅 → 바탕화면 → 휴지통`

`review-studio`는 Dock에서만 제거한다. 리뷰 기능, 기존 경로, 검색 및 저장 데이터는 삭제하지 않는다.

## 검증

- 세 부가세 방식의 공급가·부가세·합계·계약금·잔금 단위 테스트를 추가한다.
- 1,800,000원 포함세 사례가 1,636,364 / 163,636 / 1,800,000인지 확인한다.
- 각 브랜드에서 새 접두사, 4자리 순번, `0002` 시작과 다음 순번 발급을 확인한다.
- 과거 번호 형식과 저장된 과거 견적이 그대로 열리는지 확인한다.
- Dock 배열과 렌더 순서를 확인하고 리뷰콘텐츠가 Dock에 없는지 확인한다.
- 타입 검사, 변경 파일 린트, 관련 Vitest를 실행한다.
