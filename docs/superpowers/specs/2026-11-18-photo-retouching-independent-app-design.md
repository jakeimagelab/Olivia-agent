# 사진보정 독립 앱 통합 설계

## 목표

`/photo-retouching`을 Olivia OS의 독립 앱으로 정리한다. 기존 사진작업실의 사진보정 진입점은 제거하되 독·전체 앱·채팅 별칭은 새 앱을 연다. 행사에 묶여 있던 색 맞춤과 수동 편집은 NAS 임의 폴더를 입력으로 받는 공용 작업으로 바꾸며, 기존 개인별 셀렉 기능은 호환 어댑터로 유지한다. 색감 체크와 색감 동기화의 화면 응답 형식은 유지하면서 AI 공급자만 OpenAI로 교체한다.

이 작업은 편집 엔진 `lib/photo-edit/*`의 픽셀 계산법, 다른 기능의 AI 공급자, 가운·스크럽 합성을 변경하지 않는다. 데이터베이스 스키마 변경도 없다.

## 선택한 접근

폴더 기준 공용 작업을 기준 구현으로 만들고 기존 행사형 기능을 어댑터로 연결한다.

- 새 작업 `PHOTO_COLOR_MATCH`와 `PHOTO_COLOR_RENDER`가 NAS의 `source_path` 및 `output_path`를 직접 사용한다.
- 기존 `PERSON_SELECT_COLOR_MATCH`와 `PERSON_SELECT_COLOR_RENDER`는 같은 공용 실행 모듈을 호출하며 현재 API와 기록 형식을 보존한다.
- 화면은 독립 앱용 컴포넌트로 분리하고 행사 화면은 독립 앱으로 이동하는 링크와 복귀 정보만 제공한다.
- 기존 코드를 복제하거나 임시 행사 ID를 만드는 방식은 사용하지 않는다.

이 구조는 색 맞춤 계산과 파일 렌더링의 구현이 한 벌만 존재하므로 DRY 원칙을 지키며, 행사 외 폴더와 기존 행사 양쪽의 결과가 달라지는 것을 방지한다.

## 독립 앱 구조

`/photo-retouching`은 밝은 와이드 셸 안에 5개의 2단계 밑줄 탭을 제공한다.

1. 색 맞춤
2. 수동 편집
3. 색감 체크
4. 색감 동기화
5. 보정 레시피

페이지 파일은 라우팅과 쿼리 해석만 맡고, 실제 화면은 `components/photo-retouching/` 아래의 작은 컴포넌트로 분리한다. 공통 셸, 탭별 진행 문구, 폴더 선택, 최근 작업, 비율 보존 이미지 프레임, 색 맞춤 결과, 수동 편집 패널을 각각 독립 단위로 둔다.

`lib/workspaceGroups.ts`에서는 `retouch` 도구를 제거한다. `lib/toolNav.ts`의 기존 `/photo-retouching` 항목은 설명을 다음 문구로 바꾸고 독립 앱 진입점으로 유지한다.

> 보정본의 얼굴 밝기·톤을 맞추고, 직접 편집하고, 색감을 분석합니다.

기존 OS 앱 레지스트리와 별칭이 이미 `/photo-retouching`을 가리키는 경우 이를 재사용하고, 누락된 경우에만 독립 창 등록을 보완한다. 앱은 singleton으로 연다.

## 밝은 와이드 UI

화면은 `olivia-workspace-ui` 규칙과 `--ui2-*` 토큰을 사용한다. 이번 요구의 밝은 톤 지시가 기존 수동 편집기의 다크 톤보다 우선한다.

- 고정 `max-width`와 가운데 검정 카드를 제거한다.
- 바깥 여백은 좌우 24~28px, 카드 간격은 16~18px로 둔다.
- 기본 본문은 사진 영역 1.35, 결과·조정 영역 1의 두 칸이다.
- 1100px 미만에서는 위아래 한 칸으로 쌓는다.
- 채운 주 실행 버튼은 현재 화면에 하나만 둔다.
- 비활성 버튼에는 바로 아래 이유를 표시한다.
- 별도 사용 가이드 카드는 없애고 탭 줄 오른쪽에 현재 탭의 단계 진행을 한 줄로 표시한다.
- 작업 정보 서랍은 기본 닫힘 상태를 유지한다.
- 사진 판단 영역만 무채색 `#E6E6E6`을 쓰고 나머지는 밝은 OS 토큰을 사용한다.

색감 체크 결과는 하이라이트·미드톤·쉐도우를 기준색과 현재색으로 나란히 표시하고 각 줄에 판정 태그를 붙인다. Camera Raw 값은 값별 칸으로 나누고 `보정값 복사`만 채운 주 실행 버튼으로 둔다. 결과 하단에는 `색감 분석: OpenAI · 결과는 참고값입니다`를 표시한다.

## 사진 비율 보존

모든 미리보기는 하나의 비율 보존 규칙을 공유한다.

- 이미지 요소는 `object-fit: contain`만 사용한다.
- `object-fit: cover`, 상반신 크롭, 고정 4:3·4:5 상자는 제거한다.
- 원본의 EXIF 회전을 반영한 `width`와 `height`로 `aspect-ratio`를 계산한다.
- 전원 나란히와 필름 줄은 높이를 맞추되 각 항목 너비는 사진 비율에서 계산한다.
- 빈 공간은 무채색 회색으로 채우며 이미지를 늘리지 않는다.
- 워커 미리보기는 `sharp().rotate().resize({ fit: "inside" })`로 만든다.

공용 `PhotoAspectFrame`은 화면 렌더링용 너비·높이와 대체 상태를 캡슐화한다. 비율 계산은 DOM과 분리된 순수 함수로 두어 가로 3:2, 세로 2:3, 정사각, EXIF Orientation 6과 8을 테스트한다. 렌더링 비율 오차 허용치는 0.5%다.

## 폴더 기준 색 맞춤 작업

### 입력과 결과

`PHOTO_COLOR_MATCH` payload:

```json
{
  "source_path": "NAS 상대 또는 허용 절대 경로",
  "output_path": "선택 사항",
  "options": {
    "brightness": true,
    "skin_tone": true
  },
  "reference": {
    "mode": "median",
    "file": null
  },
  "selected_file_names": []
}
```

`PHOTO_COLOR_RENDER`는 `output_path`, 변경된 파일별 레시피, 공통 레시피, 기준 측정값을 받는다. 경로는 기존 `resolvePersonSelectSourcePath`의 허용 루트 검증을 공용 경로 해석기로 이동하거나 래핑하여 동일한 보안 경계를 유지한다.

색 맞춤 실행은 다음 순서를 따른다.

1. 원본 폴더를 읽고 JPG/JPEG를 하위 폴더까지 수집한다.
2. 선택 파일 목록이 있으면 그 파일만 작업한다.
3. 기존 `lib/photo-edit` 측정과 레시피 계산을 사용한다.
4. 결과 폴더를 `<원본폴더명>_색맞춤`, 충돌 시 `_2`, `_3` 순으로 만든다.
5. 원본과 레시피에서 매번 다시 렌더링한다.
6. JPEG 100, 4:4:4, EXIF·ICC 보존, 필요 시 sRGB 변환 규칙을 유지한다.
7. `.olivia-color-match/recipes.json`에 결과와 측정값을 기록한다.
8. 미리보기는 `photo-retouch/<작업ID>/...`에 올린다.

기존 행사형 작업은 `event_id`를 호환 메타데이터로 추가하고 같은 공용 실행 함수를 호출한다. 기존 행사 미리보기 경로와 응답 필드는 유지해 이미 저장된 결과를 계속 읽을 수 있게 한다.

### API

`app/api/photo-retouch/color-match/route.ts`는 관리자 인증 후 다음 동작을 제공한다.

- `POST`: 폴더 색 맞춤 작업 생성
- `GET ?output_path=...`: 해당 결과와 레시피, 현재 작업 상태 조회
- `GET ?recent=1`: 완료된 `PHOTO_COLOR_MATCH` 작업에서 최근 결과 10개 조회
- `PATCH`: 변경 레시피를 검증하고 `PHOTO_COLOR_RENDER` 작업 생성

최근 작업은 기존 `remote_jobs`의 action, payload, result를 조회하여 계산한다. 별도 테이블이나 DB 변경은 만들지 않는다.

## 수동 편집

기존 `ColorMatchEditor`의 계산과 작업 방식을 재사용하되 데이터 공급자를 `eventId` 전용 API에서 `output_path` 기반 API로 분리한다. 편집기 상태와 UI를 분리하여 행사형 호환 화면도 같은 편집기 본체를 쓸 수 있게 한다.

- `tab=edit&output_path=...`이면 해당 폴더 결과를 연다.
- `tab=edit`에 결과가 없으면 최근 작업이나 폴더 선택 안내를 보여준다.
- 저장은 변경된 파일만 `PHOTO_COLOR_RENDER`에 전달한다.
- 저장 전 변경이 있으면 이탈 확인을 유지한다.
- 전체 공통 레시피와 파일별 레시피의 병합 규칙은 변경하지 않는다.
- 필름 줄, 전후 보기, 전원 보기 모두 전체 사진 비율을 유지한다.

기존 `/person-select/[id]/color-match`는 최근 행사 색 맞춤 결과를 찾아 `/photo-retouching?tab=edit&output_path=...&return=...`로 리다이렉트한다. 최근 결과가 없으면 독립 앱의 색 맞춤 탭으로 이동한다.

## OpenAI 색감 분석

`lib/photoRetouch/colorCheckService.ts`와 `app/api/color-sync/route.ts`는 `getOpenAIClient()`를 사용한다.

- 모델은 `process.env.OPENAI_COLOR_MODEL ?? SCENE_MODEL_HIGH`다.
- 이미지는 `data:<mime>;base64,<data>` 형식의 `image_url`로 전달한다.
- 기존 프롬프트 내용과 결과 계산은 유지한다.
- 응답은 `response_format: { type: "json_object" }`로 제한한다.
- 파싱한 AI 원본 JSON을 현재 데코레이터에 전달하여 화면 응답 필드를 그대로 유지한다.
- `OPENAI_API_KEY`가 없으면 API가 `OpenAI 키가 설정되지 않았어요.`를 반환한다.
- Anthropic 패키지와 다른 기능의 공급자는 변경하지 않는다.

OpenAI 오류, 빈 응답, 잘못된 JSON은 사용자용 한 줄 오류로 바꾸며 키나 원문 이미지 데이터는 로그에 기록하지 않는다.

## Bridge 연결

Olivia Bridge의 사진 보정 액션은 분석 작업을 직접 실행하지 않고 독립 앱을 연다.

- 원격 NAS 폴더에서는 현재 폴더 경로, 선택 파일명, 생성 시각을 `sessionStorage`에 저장한다.
- URL에는 임의 키만 넣어 `/photo-retouching?tab=match&handoff=<key>`로 이동한다.
- 앱은 키를 한 번 읽고 만료되었거나 잘못된 데이터면 폐기한다.
- 선택 사진이 있으면 그 파일만 체크된 상태로 연다.
- 로컬 브라우저 폴더는 Mac Studio 경로로 해석하지 않는다. `브릿지에서 연 로컬 폴더는 Mac Studio 경로를 알 수 없어요. NAS에서 같은 폴더를 선택하세요.`를 표시한다.
- 사진이 없을 때는 액션을 비활성화하고 이유를 보여준다.

## 개인별 셀렉 연결

보정본 올리기 모드에 있던 색 맞춤 패널은 보조 버튼 `사진보정에서 색 맞춤`으로 교체한다.

- 폴더를 선택한 뒤 `/photo-retouching?tab=match&path=...&return=/person-select/<행사ID>`로 이동한다.
- 색 맞춤 완료 후 `셀렉으로 돌아가 올리기`를 표시한다.
- 결과 폴더 경로는 `sessionStorage`의 일회성 복귀 데이터로 전달한다.
- 셀렉 화면은 복귀 데이터를 읽어 보정본 올리기 경로를 `_색맞춤` 결과로 변경한다.
- 안내 순서의 두 번째 문구를 `사진보정 앱에서 색 맞춤`으로 바꾼다.

기존 보정본 업로드, 고객 연결, Storage 업로드 로직은 변경하지 않는다.

## 오류 처리와 안전성

- 워커가 오프라인이면 실행 버튼을 비활성화하고 바로 아래 이유를 표시한다.
- 경로가 허용 루트 밖이면 작업을 만들지 않는다.
- 결과 폴더 충돌은 자동 번호 증가로 해결하며 기존 결과를 덮어쓰지 않는다.
- 편집 저장은 원본 폴더를 수정하지 않고 결과 폴더만 갱신한다.
- 원격 작업 실패는 기존 작업 상태줄과 결과 박스에서 단계·원인·시각을 표시한다.
- 세션 전달 데이터는 URL에 실제 경로나 파일 목록을 노출하지 않으며 사용 후 제거한다.
- OpenAI 공급자 오류는 색 맞춤 픽셀 엔진과 무관하므로 색 맞춤·수동 편집 사용을 막지 않는다.

## 테스트와 검증

### 단위 및 통합 테스트

- 회전 반영 비율 계산: 3:2, 2:3, 1:1, Orientation 6/8 모두 0.5% 이내
- 공용 폴더 payload 검증과 허용 루트 거부
- 행사 없이 색 맞춤 후 수동 렌더 저장
- 기존 행사 action이 같은 공용 실행 모듈을 호출하는 호환 테스트
- OpenAI 요청 모델, data URL, JSON 모드 및 기존 응답 필드 보존
- OpenAI 키 누락 안내 문구
- Bridge handoff가 폴더와 선택 3장만 복원하고 사용 후 제거되는지 확인
- 셀렉 복귀 handoff가 결과 폴더를 업로드 경로로 복원하는지 확인
- workspaceGroups에서 사진 보정 제거, toolNav와 OS 독립 앱 진입 유지

### 정적 및 실제 화면 검증

- `npm run typecheck`
- `npm run lint`
- `npm test`
- 1440px와 1920px에서 화면 양쪽을 두 칸이 채우는지 캡처
- 1100px 미만에서 한 칸으로 쌓이는지 확인
- 모든 탭에서 `object-fit: cover`와 크롭이 남지 않았는지 검사
- 가로·세로·정사각 및 회전 사진의 실제 DOM 비율 확인
- Bridge 원격 폴더 3장 전달과 셀렉 복귀 흐름을 실제 브라우저로 검증

## 구현 순서

1. 공용 비율·handoff·폴더 작업 타입과 테스트
2. 공용 색 맞춤/렌더 러너 및 원격 작업 action/API
3. OpenAI 색감 분석 전환과 응답 호환 테스트
4. 밝은 와이드 앱 셸과 색 맞춤·수동 편집 탭
5. 기존 색감 체크·동기화·레시피 탭 이전
6. Bridge 및 개인별 셀렉 진입·복귀 연결
7. 전체 테스트, 빌드, 실제 화면 캡처
