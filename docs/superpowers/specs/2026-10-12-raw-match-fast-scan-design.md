# RAW 파일명 매칭 빠른 탐색 설계

## 목표

사진작업실의 `RAW 매칭 > 파일명 매칭`에서 외장 SSD를 선택했을 때 발생하는 긴 `RAW 탐색 중` 시간을 줄인다. 매칭 기준, 복사·이동 방식, 원본 보존 동작과 결과 화면은 바꾸지 않는다.

## 적용 범위

- 브라우저에서 실행되는 파일명 RAW 탐색
- `lib/selectMatch/rawIndex.ts`의 RAW 인덱스 생성
- `components/photo-workspace/SelectMatchWorkspace.tsx`의 사전 확인과 실행 전 탐색
- 같은 탐색 함수를 쓰는 채팅 내 RAW 매칭 카드
- 탐색 조기 종료, 출력 폴더 제외, 제한된 하위 폴더 병렬화
- 탐색 성능과 기존 동작을 보장하는 단위 테스트

촬영시간(EXIF) 매칭, Mac Studio 원격 작업, RAW 복사·이동 구현, 화면 디자인은 이번 변경에 포함하지 않는다.

## 현재 병목

현재 탐색은 선택된 JPG 개수와 무관하게 지정 폴더를 최대 5단계까지 순차 순회한다. `Selected_RAW`만 제외하고 다른 결과 폴더와 숨김 폴더도 탐색하며, 필요한 RAW를 모두 찾은 뒤에도 끝까지 계속 돈다. 외장 SSD 자체가 빨라도 브라우저 File System Access API 호출을 파일과 폴더마다 순차 대기하므로 파일 수가 많을수록 지연된다.

## 탐색 구조

### 대상 기반 탐색

- `buildRawIndex`에 선택된 JPG basename 집합을 선택적으로 전달한다.
- basename 비교는 현재와 동일하게 NFC 정규화 후 영문 소문자로 한다.
- 선택한 RAW 폴더의 바로 아래 파일은 알려진 RAW 확장자로 직접 조회해, 일반적인 단일 폴더 촬영본은 디렉터리 전체 열거 없이 찾는다.
- 대소문자를 구분하는 볼륨이나 하위 폴더 촬영본은 직접 조회 실패 후 재귀 탐색으로 자동 전환한다.
- 대상 집합이 있으면 매칭 대상 RAW만 인덱스에 넣는다.
- 대상 RAW를 모두 찾으면 남은 디렉터리 탐색을 즉시 중단한다.
- 대상 집합이 없으면 기존처럼 모든 RAW를 인덱싱해 기존 호출부와 테스트 호환성을 유지한다.

### 폴더 제외

아래 폴더는 RAW 원본 후보가 아닌 작업 결과이므로 재귀 탐색에서 제외한다.

- `Selected_RAW`
- `Finished_RAW`
- `JPG전체`
- `.olivia`
- 점(`.`)으로 시작하는 숨김 폴더
- 사진 리사이즈 결과 규칙인 `숫자px_Q숫자`

폴더명 비교는 macOS 외장 볼륨의 대소문자 차이를 고려해 case-insensitive로 처리한다.

### 제한된 병렬 탐색

- 현재처럼 디렉터리 하나를 끝낸 뒤 다음 디렉터리로 내려가지 않고, 발견된 하위 디렉터리를 작은 작업 큐에 넣는다.
- 최대 동시 탐색 수를 고정해 외장 SSD와 브라우저를 과부하시키지 않는다.
- 대상 RAW를 모두 찾거나 오류가 발생하면 새 작업을 시작하지 않는다.
- 동일 basename이 여러 위치에 있을 때는 기존 인덱스처럼 하나의 항목만 사용한다. 복사·이동 단계의 인터페이스는 유지한다.

## 데이터 흐름

1. 사용자가 선택한 JPG basename 집합을 만든다.
2. `runPreflight`가 RAW 폴더와 대상 basename을 `buildRawIndex`에 전달한다.
3. 탐색기는 출력·숨김 폴더를 제외하고 제한된 병렬 큐로 디렉터리를 읽는다.
4. 발견한 RAW 중 대상 basename만 인덱스에 넣는다.
5. 모든 대상이 발견되면 즉시 결과를 반환한다.
6. 사전 확인 결과를 기존 `rawIndexRef`에 저장한다.
7. 실제 복사에서는 저장된 인덱스를 그대로 사용한다. 인덱스가 없을 때만 같은 대상 기반 탐색을 다시 실행한다.

선택된 파일 중 실제로 존재하지 않는 RAW가 있으면 탐색기는 전체 허용 범위를 끝까지 확인한 뒤 기존과 같이 누락으로 보고한다.

## 오류 처리

- 폴더 권한 오류와 파일 시스템 오류는 기존 오류 흐름으로 전달한다.
- 제외 폴더 때문에 일반 RAW 폴더가 누락되지 않도록 제외 목록은 고정된 작업 결과 이름에만 적용한다.
- 대상 기반 탐색 결과가 비어 있어도 기존의 `RAW 파일을 찾을 수 없습니다` 처리를 유지한다.
- 중단, 복사 실패, 이동 실패 처리에는 손대지 않는다.

## 테스트

- 대상 basename을 모두 찾으면 뒤쪽 디렉터리를 읽지 않고 종료한다.
- 일부 대상이 없으면 전체 허용 범위를 탐색하고 누락으로 남긴다.
- `Selected_RAW`, `Finished_RAW`, `JPG전체`, `.olivia`, 숨김 폴더와 리사이즈 결과 폴더를 읽지 않는다.
- 대상 집합이 없을 때 기존 전체 RAW 인덱스 동작을 유지한다.
- 대소문자와 RAW 확장자 처리 결과가 기존과 같다.
- 진행 콜백의 최종 개수가 호출된다.
- 기존 `rawIndex`, 이름 파싱, 사진작업실 관련 테스트와 TypeScript 검사를 통과한다.
- 테스트용 대형 가상 폴더에서 기존 전체 순회보다 방문 엔트리 수가 감소하는지 확인한다.

## 배포

- 변경 파일 lint, 관련 Vitest, 전체 TypeScript 검사를 실행한다.
- 변경만 별도 커밋한다.
- `main`을 원격 저장소에 push해 연결된 배포 파이프라인을 실행한다.
- push 뒤 원격 브랜치와 배포 상태를 확인하고 결과를 보고한다.
