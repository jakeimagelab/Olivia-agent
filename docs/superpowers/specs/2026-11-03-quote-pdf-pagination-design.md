# 견적서 PDF 다중 페이지 설계

## 목적

견적 항목과 상세 설명이 A4 가로 한 페이지 높이를 넘을 때 하단 내용이 잘리는 문제를 없앤다. 화면의 견적서 편집·미리보기 모습은 유지하고, PDF 출력에서만 필요한 만큼 페이지를 늘린다.

## 검토한 방식

1. 한 페이지에 맞게 전체를 축소한다.
   - 구현은 단순하지만 항목이 많을수록 글자가 작아져 견적서 가독성이 무너진다.
2. PDF 전용 문서를 별도로 다시 만든다.
   - 페이지를 세밀하게 제어할 수 있지만 화면 견적서와 PDF가 서로 달라질 위험이 크다.
3. 기존 견적서 DOM을 인쇄 매체에서 자연스럽게 분할한다. **채택**
   - 현재 디자인과 데이터 경로를 그대로 사용하면서 Chromium의 페이지 분할을 이용할 수 있다.

## 출력 동작

- 내용이 한 페이지에 들어가면 기존과 동일한 A4 가로 1장으로 출력한다.
- 내용이 넘치면 A4 가로 2장 이상으로 자동 분할한다.
- 좌측 브랜드 레일은 모든 페이지에 같은 위치와 크기로 반복한다.
- 표 머리글은 다음 페이지에서도 반복한다.
- 항목 한 행, 카테고리 행, 결제·합계·계약 안내 영역은 페이지 중간에서 쪼개지지 않는다.
- 합계·계약 안내와 브랜드 서명 영역은 전체 항목 뒤 마지막 페이지에 한 번만 나온다.
- PNG 미리보기와 Olivia 안의 견적서 화면에는 인쇄 전용 규칙을 적용하지 않는다.

## 구현 범위

- `app/quote-print/[id]/page.module.css`의 인쇄 규칙에서 고정 높이와 `overflow: hidden`을 제거한다.
- 인쇄 시 `.quote-page`를 페이지 분할 가능한 블록 흐름으로 바꾸고, 좌측 레일을 고정 반복 요소로 둔다.
- 표 머리글 반복과 행·하단 영역의 `break-inside` 보호 규칙을 추가한다.
- `tests/quoteNativePdf.test.ts`에 인쇄 페이지가 고정 높이로 잘리지 않고 페이지 분할 규칙을 유지하는 회귀 검사를 추가한다.

## 검증

- 기존 견적서 PDF 관련 테스트와 타입 검사를 통과해야 한다.
- 항목이 적은 견적서는 1페이지인지 확인한다.
- 상세 설명이 긴 항목을 충분히 넣은 견적서는 2페이지 이상인지 확인한다.
- 최종 PDF를 PNG로 렌더링해 행 잘림, 표 머리글 반복, 좌측 레일, 마지막 페이지 합계·계약 안내를 육안으로 확인한다.
- PDF 텍스트 추출로 첫 항목부터 최종 금액까지 내용이 빠짐없이 존재하는지 확인한다.

## 비범위

- 견적 데이터 구조, 계산식, 저장 방식은 바꾸지 않는다.
- 견적서의 색상, 폰트, 항목 구성과 화면 편집 UI는 재디자인하지 않는다.
- 계약서나 다른 PDF 출력에는 이 변경을 적용하지 않는다.
