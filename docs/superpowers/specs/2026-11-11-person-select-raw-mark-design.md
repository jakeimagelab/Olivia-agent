# 사진선택 RAW 매칭·로우 셀렉 설계

## 범위

기존 `RAW 매칭` 버튼과 위치를 유지하고 확인 창에서 실행 방식만 선택한다. `copy`는 기존 `Selected_RAW` 복사를 그대로 사용하고, `mark`는 매칭된 원본 RAW 옆 XMP의 별점·컬러만 수정한다. 개인별·공동 셀렉의 제출본과 현재 상태 선택 로직은 공통으로 재사용한다.

## 데이터 흐름

관리자 화면은 프로젝트별 `mode`, `source`, 검토자 범위와 컬러 라벨 이름을 기억해 `PERSON_SELECT_RAW_MATCH` 작업을 만든다. API와 워커는 값이 없으면 `copy`·`submitted`로 해석한다. 대상 JPG는 기존 파일명+EXIF 촬영시각 매칭을 거치며, 동일 촬영시각·동일 크기의 RAW 복사본은 `copy`에서 하나, `mark`에서 모두 처리한다.

공동 셀렉의 같은 사진에 여러 검토자 값이 있으면 별점은 최댓값, 컬러는 가장 최근 저장값을 사용한다. 개인별 선택은 기존 데이터에 별점·컬러 필드가 없으므로 선택 자체를 Adobe 별점 1로 기록한다.

## XMP 안전성

RAW 파일은 열어 읽기만 하고 절대 수정하지 않는다. XMP는 XML DOM으로 파싱하여 `xmp:Rating`과 `xmp:Label`만 갱신하고 기존 `crs:*` 등 다른 노드는 보존한다. 기존 값과 생성 여부를 `olivia:*` 속성 및 작업 결과에 기록한다. 지우기는 마지막 `mark` 결과에 기록된 XMP만 복원하고, 작업에서 새로 만든 XMP는 삭제한다.

## UI와 결과

확인 창의 주 실행 버튼은 하나다. `mark`일 때만 컬러 라벨 이름 설정을 보여준다. 툴바 아래 결과는 복사 수 또는 별점·컬러·충돌·확인 필요 수를 계속 표시하며, 실패는 단계와 시각을 포함한다. 최근 `mark` 결과에는 `로우 셀렉 지우기`를 제공한다.

## Bridge 연동

XMP 읽기는 별점과 라벨을 함께 반환한다. 로컬 및 NAS Bridge는 Adobe 기준에 이 값을 포함하고, RAW 카드와 안전하게 짝지어진 JPG 카드에 RAW 표시 배지를 노출한다. 창 포커스 시 기존 동기화 흐름으로 다시 읽는다.

## 검증

순수 선택 병합, 라벨 매핑, XML 보존·복원, 중복 RAW 표시, 하위 호환 payload, runner 실패 JSON을 단위 테스트한다. 이후 TypeScript, 관련 Vitest, 전체 build를 실행한다.
