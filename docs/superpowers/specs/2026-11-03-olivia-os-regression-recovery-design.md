# Olivia OS UI 회귀 복구 설계

## 목표

현재 창의 실제 고객·촬영 건·문서를 안정적으로 유지하면서, UI 개편 이후 가려진 스크롤·실행·저장·재생·필터 기능을 복구한다. 현재 세이지 팔레트와 기존 문서 출력은 유지한다.

## 상태와 탐색

- 창의 수명(`windowId`)과 표시 정보 갱신을 분리한다. 고객관리 호스트는 고객명이나 문서 제목 변경만으로 다시 마운트하지 않는다.
- 일반 앱 실행은 고객 문맥을 상속하지 않는다. 명시적인 고객·문서 이동만 해당 ID 묶음을 창에 전달한다.
- 고객·촬영 건·문서 이동은 하나의 요청으로 검증하고, 이전 요청은 취소하거나 응답 식별자로 무시한다.
- 편집기 닫기 계약을 실제 닫기 함수 하나로 통일하고, 자동저장 완료/실패와 미저장 확인 뒤에만 화면을 전환한다.
- 고객관리 안의 견적 편집 상태는 독립 견적 앱의 전역 폼과 분리한다.

## 레이아웃

- 견적서는 실제 컨테이너 폭으로 최근 목록/편집/미리보기를 배치한다. 각 패널은 자체 스크롤을 갖고 미리보기 툴바 아래 캔버스만 남은 높이를 사용한다.
- 프롬프터는 기본 재생 조작과 상세 설정을 분리한다. OS 내부 액션은 헤더 없이 내부 툴바에 노출한다.
- 콘티·계약서·사진작업실은 실제 DOM 래퍼에서 `auto + minmax(0, 1fr)` 높이 구조를 사용한다.
- Bridge의 좁은 폭 필터는 동일 상태를 쓰는 드로어로 열며, overlay 미리보기 모드의 남는 grid 행을 제거한다.
- 공통 우측 정보 패널은 제목/탭을 고정하고 정보 본문만 스크롤한다.

## 검증

- Vitest로 창 문맥, 콘텐츠 키, iframe 타이머, 경로 전환과 상태 보호를 검증한다.
- typecheck와 변경 파일 lint를 실행한다.
- 실제 OS에서 700/1000/1400px 상당 폭, 600px 높이, 우측 패널과 Bridge 900/760px 경계를 확인한다.
