# 상단바 상태표시줄 재구성 설계

작성일: 2026-09-27  
대상: Olivia Desktop 상단바 상태 패널

## 1. 목표

상단바 상태 패널을 단순 진단 목록에서 실제 작업 우선순위 화면으로 바꾼다. 사용자가 즉시 조치해야 하는 문제와 승인·확인 대기 업무를 위에 배치하고, 정상 연결 정보와 과거 기록은 접어서 시각적 소음을 줄인다.

시스템 진단의 단일 소스는 `collectSystemStatus()`다. 패널 API는 진단 로직을 다시 구현하지 않고 이 결과를 전달한다. 패널에만 필요한 업무·진행·최근 기록 데이터만 별도로 조회한다.

## 2. 서버 데이터 구조

`GET /api/olivia-os/status-panel`은 관리자 세션에서만 호출할 수 있으며 다음 네 묶음을 반환한다.

1. `diagnostics`: `collectSystemStatus({ db, now })`의 결과
2. `attentionItems`: 사용자가 직접 처리해야 하는 항목
3. `progressItems`: 현재 실행 중인 사진·원격 작업
4. `recentActivity`: 최근 백업 및 파일 작업 기록

기존 헤르메스 폴백 횟수와 Core 우회 의심은 진단 결과에 없는 패널 전용 이상 신호이므로 `attentionItems`에 포함한다. 시스템 진단과 중복되는 Worker, MCP, 마운트, 씬 AI, DB 테이블 상태는 직접 조회하지 않는다.

독립된 패널 전용 조회는 `Promise.allSettled()`로 병렬 실행한다. 한 테이블 조회 실패는 다른 진단이나 업무 항목을 숨기지 않는다. 실패한 조회 자체는 `unknown` 심각도의 확인 항목으로만 표시한다.

## 3. 내 차례 수집 규칙

다음 데이터를 하나의 정규화된 `attentionItems` 배열로 만든다.

| 출처 | 조건 | 표시 | 이동 |
|---|---|---|---|
| `photo_storage_projects` | `READY`, `DEFERRED` | 1차 승인 대기 | 사진작업실 프로젝트 |
| `photo_storage_projects` | `MERGE_COMPLETED` | 2차 승인 대기 | 사진작업실 프로젝트 |
| `olivia_events` | `event_type = workflow.blocked`, 잔금 확인 대기 | 잔금·계산서 확인 대기 | 연결된 고객 프로젝트 |
| `agent_approvals` | `status = pending` | 승인 대기 문서/업무 | 연결된 고객 프로젝트, 없으면 승인 목록 |
| `agent_tasks` | `status = failed` | 실패한 작업 | 연결된 고객 프로젝트, 없으면 작업 목록 |
| workflow summary와 동일한 판정 | `waitingCustomer` | 고객 대기 중 | 연결된 고객 프로젝트 |

`workflow.blocked` 이벤트는 같은 `workflow_run_id`의 최신 항목 한 건만 표시해 중복 경고를 막는다. 프로젝트 또는 고객 연결 정보가 있으면 `/clients?workflowRunId=...` 또는 `/clients?clientId=...`로 이동하고, 연결 정보가 없으면 해당 집계 화면으로 이동한다.

`/api/workflow/summary` HTTP 호출을 서버에서 다시 하지 않는다. 그 라우트가 사용하는 `CUSTOMER_WAIT_STEPS` 판정 규칙을 공용 helper로 이동해 두 API가 같은 함수를 사용한다. 이렇게 해야 상태 패널과 workflow summary가 같은 결과를 내면서 내부 HTTP 왕복과 로직 복제를 모두 피할 수 있다.

## 4. 진단 심각도와 표시

`collectSystemStatus()`의 `SystemStatusItem`을 그대로 사용한다.

- `error`: 빨강, 즉시 조치 필요
- `warning` 또는 `unknown`: 주황, 확인 필요
- `ok`: 연결 상태 안에서만 표시

`지금 확인할 것`에는 오류·경고·확인 불가 진단, 스키마 문제, 헤르메스 폴백, Core 우회 의심을 보여준다. 항목이 0개면 섹션 자체를 렌더하지 않는다. 진단의 `remedy`는 접거나 펼칠 별도 버튼을 만들지 않고 항목 아래 한 줄 안내로 표시한다. 위험한 재시작·복구 버튼은 제공하지 않는다.

상단바 배지는 다음 우선순위를 따른다.

1. 빨강: `error` 항목이 하나 이상
2. 주황: 빨강 없이 `warning` 또는 `unknown`만 존재
3. 파랑: 시스템 문제 없이 `내 차례`가 존재
4. 없음: 문제와 내 차례가 모두 없음

배지에는 해당 우선순위에서 사용자가 확인할 총 건수를 숫자로 표시한다.

## 5. 패널 UI 구조

패널은 아래 순서로 렌더한다.

1. 헤더: `상태 및 알림`, 수동 새로고침
2. `지금 확인할 것`: 문제가 있을 때만 표시, 항상 펼침
3. `내 차례`: 기본 펼침
4. `진행 중`: 기본 펼침, 비어 있으면 숨김
5. `연결 상태`: 모두 정상이면 기본 접힘, 이상 항목이 있으면 자동 펼침
6. `최근 기록`: 기본 접힘

`내 차례`, `진행 중`, `연결 상태`, `최근 기록`은 동일한 접이식 섹션 패턴을 쓴다. 접힘 상태는 `olivia.status-panel.sections.v1` 키 하나에 저장한다. 초기값은 내 차례·진행 중 펼침, 연결 상태·최근 기록 접힘이다. 저장값이 있어도 연결 상태에 새로운 이상이 생기면 해당 세션에서 자동 펼친다.

정상 연결 정보는 계층적으로 압축한다.

- 맥스튜디오: Worker, Workstation 마운트/접근, Agentstation 마운트/접근, NAS 감지기, Worker 씬 AI, 대기 잡
- 헤르메스: Hermes 상태, 주소 형태, Agent 엔진, MCP 도구
- DB: 필수 테이블 4종

환경변수 값은 표시하지 않는다. 설정 여부와 진단 상태만 표시한다.

## 6. 진행 중과 최근 기록

기존 `PhotoProjectNotificationProvider`, `ShootingProgressCards`, 백그라운드 작업 Store의 데이터 흐름은 유지한다. 패널 안에서는 진행 중인 항목만 `진행 중`에 모으고, 승인·검토 대기는 `내 차례`로 분리한다.

최근 기록에는 최근 완료·실패 원격 작업과 백업 감지 이력을 표시한다. 실패한 원격 작업은 최근 기록에 남기면서 `내 차례`에도 한 번 표시한다. 각 행은 사진작업실 또는 원격 파일 화면으로 이동한다.

기존 닫힘 60초, 열림 25초 폴링 주기는 변경하지 않는다. 패널을 여는 동작과 수동 새로고침은 즉시 조회한다.

## 7. 컴포넌트 경계

`StatusPanelButton.tsx` 안에서 파생 배열 계산과 접이식 섹션 렌더링을 작은 모듈 수준 helper/component로 분리한다. 컴포넌트 내부에 새 컴포넌트를 정의하지 않는다. 서버에서 이미 정규화할 수 있는 데이터는 클라이언트에서 다시 조인하지 않는다.

공용 타입은 상태 패널 전용 타입 파일로 분리해 API와 UI가 공유한다. `collectSystemStatus()`의 타입은 기존 `lib/system-status/types.ts`를 그대로 사용한다.

## 8. 오류 처리

- 관리자 세션이 아니면 기존처럼 401
- `collectSystemStatus()` 자체가 부분 실패하더라도 기존 `unknown` 항목으로 반환
- 패널 전용 조회 실패는 해당 묶음의 `unknown` 항목으로 제한
- 최초 전체 요청 실패 시에만 기존 재시도 UI 표시
- stale 응답이 최신 수동 새로고침 결과를 덮어쓰지 않도록 요청 순번을 비교

## 9. 테스트

다음 회귀 테스트를 추가한다.

1. `collectSystemStatus()`가 상태 패널 API의 진단 단일 소스인지 확인
2. 문제가 없으면 `지금 확인할 것`이 렌더되지 않음
3. 모든 연결이 정상이면 연결 상태가 한 줄로 접힘
4. 하나라도 비정상이면 연결 상태가 자동으로 펼쳐지고 해당 항목 강조
5. `workflow.blocked` 이벤트가 잔금·계산서 확인 대기로 정규화됨
6. 사진 1·2차 승인, pending approval, failed task, waiting customer가 내 차례에 포함됨
7. 연결된 프로젝트는 프로젝트 화면, 연결이 없으면 집계 화면으로 이동
8. localStorage 접힘 상태가 재마운트 후 복원됨
9. 기존 관리자 인증, 부분 실패, 폴링 주기 회귀 없음

최종 검증은 `npm run typecheck`, `npm test`, `npm run build`로 수행한다.

## 10. 범위 제외

- Worker 디스크 여유 보고 및 DB 컬럼 추가
- 팝업에서 서비스 재시작 또는 자동 복구
- 위험한 mutation 실행
- 폴링 주기 단축
- 시스템 상태 채팅 포맷 변경
