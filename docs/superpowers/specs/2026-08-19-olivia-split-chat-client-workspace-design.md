# Olivia 분할 채팅과 고객 워크스페이스 설계

## 목표

Olivia 채팅을 여는 버튼과 닫는 버튼을 같은 위치의 단일 토글로 통합한다. 데스크톱에서는 채팅이 페이지 위를 덮지 않고 기존 페이지와 좌우 영역을 나누며, 고객관리에서는 비어 있는 오른쪽 영역을 선택 고객의 프로젝트 워크스페이스로 사용한다.

## 범위

- 전역 Olivia 열기·닫기 버튼 통합
- 데스크톱 전역 채팅을 오버레이에서 분할 패널로 변경
- 모바일·태블릿 오버레이 방식 유지
- 고객관리 고객 선택을 페이지 이동에서 인라인 선택으로 변경
- 고객관리 오른쪽 영역에 선택 고객 프로젝트 정보 표시
- 기존 상세 페이지와 Conversation Store 유지

## Olivia 토글

- 우측 하단의 Olivia 원형 버튼을 열기와 닫기에 모두 사용한다.
- 채팅이 열려도 버튼은 동일한 viewport 위치에 남는다.
- 닫힌 상태의 접근성 이름은 `Olivia 대화 열기`, 열린 상태는 `Olivia 대화 닫기`로 변경한다.
- 상단의 `-` 버튼은 전역 드로어에서는 제거한다. 워크스페이스 내부 채팅처럼 별도 의미가 있는 경우만 기존 컨트롤을 유지한다.
- Escape 키와 토글 버튼 모두 채팅을 닫을 수 있다.

## 데스크톱 분할 레이아웃

- `olivia-app-row` 안에서 본문은 `flex: 1`, 채팅은 440~480px 범위의 고정 참여자로 배치한다.
- 채팅이 열리면 패널 너비가 0에서 목표 너비로 전환되고 본문은 남은 공간으로 줄어든다.
- 닫히면 채팅 패널이 레이아웃에서 제거되어 본문이 전체 가용 폭을 되찾는다.
- 페이지 자체의 세로 스크롤 정책은 유지하며 불필요한 가로 스크롤이 생기지 않게 한다.
- 채팅 메시지와 Conversation Store는 패널 표시 여부와 무관하게 유지한다.

## 모바일·태블릿

- 900px 이하에서는 기존 페이지 폭을 줄이지 않고 오른쪽 오버레이 드로어로 연다.
- 동일한 우측 하단 토글 버튼으로 열고 닫는다.
- 열린 상태에서 배경 스크림을 누르거나 Escape 키를 누르면 닫힌다.

## 고객관리 워크스페이스

### 기본 구조

- 전역 사이드바 다음의 고객관리 본문은 `고객 목록 | 선택 고객 프로젝트 영역` 두 열을 유지한다.
- 고객 목록에서 행을 누르면 라우트 전체를 교체하지 않고 `selectedClientId`만 변경한다.
- 선택 행은 기존 mint 배경과 테두리로 표시한다.
- 데이터 로드 후 명시된 `clientId`가 없으면 첫 번째 고객을 자동 선택한다.

### URL과 진입

- 인라인 선택은 `/clients?clientId=<id>`를 사용한다.
- URL 갱신은 같은 페이지 안에서 이뤄져 고객관리 컴포넌트를 상세 페이지로 교체하지 않는다.
- 홈, Olivia Action 등 기존 `clientId` 진입도 동일한 인라인 선택 상태로 연결한다.
- 기존 `/clients?id=<id>` 상세 화면은 외부 링크와 기존 기능 호환을 위해 유지한다.

### 오른쪽 프로젝트 영역

- 선택 고객의 이름, 담당자, 연락처와 프로젝트 상태를 상단에 표시한다.
- 활성 프로젝트명, 현재 단계, 촬영 예정일, 진행률, 다음 작업을 표시한다.
- 기존 워크플로우 요약과 다음 단계 액션을 재사용한다.
- 프로젝트가 없는 고객은 빈 카드 대신 `새 프로젝트 생성` 안내와 실행 버튼을 표시한다.
- 데이터 로딩, 오류, 고객 없음 상태를 각각 구분한다.
- 기존 견적·계약·콘티·전체 상세 관리로 가는 명시적 버튼은 유지하되, 고객 행 클릭 자체는 페이지 이동을 발생시키지 않는다.

## 데이터 흐름

1. 고객 목록 데이터 로드
2. URL의 `clientId` 또는 첫 고객을 선택
3. 선택 고객의 상세/워크플로우 데이터를 기존 API로 조회
4. 오른쪽 프로젝트 영역 렌더링
5. 다른 고객 선택 시 이전 페이지를 언마운트하지 않고 선택 데이터만 갱신

오래된 요청이 늦게 도착해 새 선택을 덮지 않도록 AbortController 또는 요청 식별자를 사용한다.

## 컴포넌트 경계

- `OliviaPersistentChat`: 전역 버튼, 데스크톱 분할 패널, 모바일 오버레이를 담당한다.
- `useOliviaChatModeStore`: 열림·닫힘 상태만 제공하며 Conversation 메시지는 관리하지 않는다.
- `ClientWorkspaceView`: 고객 선택과 URL 동기화를 담당한다.
- 고객 프로젝트 패널: 선택 고객 데이터의 로딩·오류·프로젝트 요약을 담당한다.
- 기존 `DetailView`: 레거시 `?id=` 진입과 전체 상세 기능을 유지한다.

## 검증

- 데스크톱에서 같은 버튼으로 열기와 닫기가 되는지 확인한다.
- 채팅을 열었을 때 본문 폭이 줄고 가로 스크롤이 생기지 않는지 확인한다.
- 닫았을 때 본문이 원래 폭으로 돌아오는지 확인한다.
- 모바일에서 오버레이로 열리고 같은 버튼으로 닫히는지 확인한다.
- 고객관리 첫 진입 시 첫 고객 프로젝트가 오른쪽에 표시되는지 확인한다.
- 고객 선택 시 라우트 전체 전환 없이 오른쪽 정보만 바뀌는지 확인한다.
- `/clients?clientId=` 직접 진입과 새로고침 후 선택 복원을 확인한다.
- 프로젝트가 없는 고객에게 생성 안내가 표시되는지 확인한다.
- typecheck, 테스트, production build를 실행한다.

- 견적·계약·콘티 내부 UI 변경
