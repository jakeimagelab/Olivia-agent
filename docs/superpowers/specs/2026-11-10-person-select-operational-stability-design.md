# 사진선택 운영 안정화 설계

## 목표

고객 Bridge, 관리자 사진선택, Olivia Bridge가 대량 사진 프로젝트를 열 때 Supabase와 Vercel에 순간 부하를 만들지 않도록 한다. 기존 사진, 참가자, 셀렉, 제출, 주문 데이터와 화면 구조는 유지한다.

## 확인된 병목

- 고객 공유 링크가 첫 응답에서 모든 사진의 썸네일과 미리보기 URL을 서명한다.
- 관리자 프로젝트 상세도 공유 프로젝트의 모든 사진 URL을 다시 서명한다.
- 관리자 프로젝트 목록이 프로젝트마다 인원/제출 상태를 별도 조회한다.
- 일부 작업 상태 폴링은 숨겨진 탭에서도 계속되거나 느린 응답과 겹칠 수 있다.
- 사진선택 협업 migration이 빠져도 기존 시스템 진단에서 미리 알 수 없다.
- 공개 API의 내부 DB 오류가 고객 화면에 그대로 노출된다.

## 적용 방식

1. 공유 사진 초기 응답은 ID, 파일명, 상대경로, 크기 등 탐색 메타데이터만 반환한다.
2. 고객/관리자 Bridge는 현재 렌더링하는 사진 ID를 최대 240장 단위로 보내 서명 URL을 받는다.
3. 포커스, 전체화면, 리뷰에 필요한 사진은 같은 제한된 캐시와 묶음 요청을 사용한다.
4. 관리자 선택 결과의 소수 썸네일만 묶어서 서명하고, 전체 공유 사진 미리보기는 지연 발급한다.
5. 프로젝트 목록 집계는 프로젝트별 N+1 쿼리 대신 전체 이벤트를 두 개의 페이지 조회로 집계한다.
6. 작업/AI/업로드 상태 폴링은 화면이 보일 때만 실행하고, 진행 중 요청과 겹치지 않는다.
7. 시스템 상태 진단에 사진선택 필수 테이블과 컬럼을 포함한다.
8. 고객 공개 API는 예상 가능한 사용자 오류만 그대로 표시하고 내부 DB 오류는 일반 안내로 바꾼다.

## 보존 조건

- DB migration이나 운영 데이터 변경은 하지 않는다.
- 고객 별점, 컬러 라벨, 메모, 초안 revision, 최종 제출 구조는 변경하지 않는다.
- 관리자 Bridge와 고객 Bridge의 디자인·조작 규칙은 변경하지 않는다.
- URL 발급 실패 시 해당 사진 묶음만 다시 요청할 수 있고 다른 선택 상태는 유지한다.

## 검증

- URL 묶음 크기와 다른 프로젝트 이미지 거부 테스트
- 초기 공유 응답에 서명 URL이 포함되지 않는 테스트
- 고객 Bridge 초안 충돌 회로 차단 회귀 테스트
- 프로젝트 목록 집계 테스트
- 숨은 탭/중복 폴링 테스트
- 사진선택 migration 진단 테스트
- 관련 Vitest, typecheck, lint, build
- 실제 데스크톱/모바일 화면과 네트워크 요청 수 확인
