# 모바일 사진 대기 제어 및 위치 권한 안정화 설계

작성일: 2026-09-24  
대상: Olivia 모바일 홈 및 사진 작업 알림

## 1. 목표

모바일의 `파일 분류 대기`를 사진작업실 진입 링크가 아니라 프로젝트별 작업 제어판으로 바꾼다. 사용자는 사진작업실 화면을 열지 않고 각 프로젝트를 승인, 보류 또는 완료 처리한다. 위치 권한은 홈 진입만으로 요청하지 않으며, 현재 작업 카드는 완료된 문서를 계속 붙잡지 않는다.

## 2. 확정된 분류 정책

`photo_storage_projects`의 `nas_department`와 `nas_shooting_mode`가 촬영의 분류 필요 여부를 결정한다.

- 두 값이 모두 없음: 분류가 필요 없는 촬영이다. 원본 분리까지만 완료하고 사용자가 `완료` 처리한다.
- 두 값이 모두 있음: 병원 촬영이다. 사용자가 `승인`하면 기존 COPY 및 Scene 분류 파이프라인을 자동 실행한다.
- 둘 중 하나만 있음: 설정 불완전 상태다. 자동 분류하지 않고 필요한 값을 카드 안에서 보완하도록 표시한다.

폴더명, 사진 내용 또는 과거 프로젝트를 이용해 진료과나 촬영모드를 추측하지 않는다. `0911_WINF`와 `0815_강지혜`는 현재 두 값이 모두 없으므로 `씬 분류 대기`가 아니라 `원본 분리 완료 · 완료 처리 필요`로 표시한다.

## 3. 파일 분류 대기 화면

`MobilePhotoPending` 목록에서 항목을 누를 때 일반 `PhotoWorkspace`로 이동하지 않는다. 선택한 카드가 목록 안에서 확장되어 다음 정보를 보여준다.

- 프로젝트명과 현재 단계
- RAW/JPG 장수
- 원본 통합 장수와 완료 시각
- 오류가 있는 경우 오류 단계와 원문
- 현재 선택 가능한 동작

프로젝트 ID는 URL 또는 전용 상세 화면으로 넘기지 않고 Provider의 선택 상태로 유지한다. 모바일 대기 화면을 벗어나지 않으므로 사용자는 선택한 프로젝트의 상태를 계속 확인할 수 있다.

### 3.1 승인

- 두 분류 설정이 모두 있는 프로젝트에만 정상 실행한다.
- 기존 승인 API와 기존 상태 머신을 사용한다.
- 화면 이동 없이 카드 상태를 `승인됨`, `복사 준비`, `복사 중`, `씬 분류 중`, `완료` 순으로 갱신한다.
- 진행 상태는 기존 `PhotoProjectNotificationProvider` 폴링 결과를 사용한다.
- 파이프라인이 `CLASSIFY_COMPLETED`에 도달하면 대기 목록에서 자동으로 사라진다.
- 분류 설정이 모두 없는 프로젝트에서 승인 버튼을 누르게 하지 않는다. 이 경우 기본 동작은 완료다.

### 3.2 보류

- 파이프라인의 실제 status를 다른 단계로 되돌리지 않는다.
- 별도의 알림 표시 만료 시각을 현재 시각으로부터 72시간 뒤로 기록한다.
- 72시간 동안 카드에 `보류 중 · N일 후 목록에서 제거`를 표시한다.
- 만료 시 별도 크론 없이 API 조회 단계에서 목록과 팝업에서 제외한다.
- DB 프로젝트 행, 이벤트 이력, NAS 파일은 삭제하지 않는다.

### 3.3 완료

- Scene 분류가 필요 없는 촬영을 사람이 최종 확인하는 동작이다.
- 누르는 즉시 목록과 팝업에서 제거한다.
- 프로젝트 status, 작업 결과, NAS 파일은 보존한다.
- 열린 사진 알림 이벤트는 확인 처리한다.
- `X`는 완료와 같은 서버 동작을 사용하되, `목록에서 완료 처리할까요? 사진 파일은 삭제되지 않습니다.` 확인을 한 번 거친다.

### 3.4 서버 데이터

파이프라인 status를 알림 UI 목적으로 오용하지 않는다. `photo_storage_projects`에 다음 표시 상태를 추가한다.

- `notification_deferred_until timestamptz null`
- `notification_dismissed_at timestamptz null`

보류와 완료용 관리자 전용 API를 추가하고 프로젝트 ID를 검증한다. 완료 API는 프로젝트 행을 DELETE하지 않는다. 승인 또는 명시적 재시작이 발생하면 두 표시 필드를 초기화한다.

프로젝트 조회 API는 다음 규칙으로 분리한다.

- 진행 중 프로젝트: 표시 상태와 무관하게 진행 카드에 노출
- 사람의 확인이 필요한 프로젝트: dismiss되지 않았고 defer 만료 전인 경우만 대기 목록에 노출
- 완료 프로젝트: 최근 완료 토스트 정책만 유지

## 4. 모바일 홈 위치 권한

홈 마운트 시 `navigator.geolocation.getCurrentPosition()`을 바로 호출하지 않는다.

- Permissions API가 있고 상태가 `granted`일 때만 위치와 날씨를 읽는다.
- 상태가 `prompt` 또는 `denied`면 위치 요청을 하지 않는다.
- Permissions API를 지원하지 않는 환경에서도 자동 요청하지 않는다.
- 위치를 읽지 못하면 날짜는 계속 표시하고 날씨와 위치 줄만 숨긴다.
- 홈 전체 로딩은 날씨 요청을 기다리지 않는다.

이 변경으로 PWA 접속만으로 위치 승인 팝업이 나타나지 않는다.

## 5. 현재 작업 중 카드

DB 문서는 시간 경과만으로 삭제하지 않는다. 카드 노출과 실제 DB 수명을 분리한다.

- 임시문서는 기존대로 `linked` 또는 `archived`가 되면 현재 작업 후보에서 제외한다.
- 견적과 계약은 기존 final status가 되면 후보에서 제외한다.
- 현재 context가 완료 문서를 가리키더라도 `isOpenMobileResourceStatus`를 통과하지 않으면 카드에 표시하지 않는다.
- DB 행 자체는 삭제하지 않는다.

이번 범위에서는 현재 작업 문서를 수동 삭제하는 기능을 추가하지 않는다. 사용자가 물어본 수명 문제는 완료 상태인데도 context 때문에 카드가 남는 회귀만 수정한다.

## 6. 오류 및 동시성 처리

- 승인, 보류, 완료 요청 중에는 해당 카드 버튼을 비활성화한다.
- 서버가 409를 반환하면 최신 프로젝트를 다시 조회해 화면을 갱신한다.
- 요청 실패 시 카드를 제거하지 않고 해당 카드 안에 오류를 표시한다.
- 승인 직후 Worker가 아직 잡을 가져가지 않았을 때는 `승인됨 · 작업 대기`로 표시한다.
- 보류 만료와 완료 처리는 UI 시간만 믿지 않고 서버가 반환한 시각을 기준으로 한다.

## 7. 테스트

### 모바일 홈

- 권한 상태가 prompt/denied이면 geolocation을 호출하지 않는다.
- granted이면 날씨 요청을 하고 실패해도 홈이 정상 렌더링된다.
- 완료된 contextual resource는 현재 작업 카드에 표시되지 않는다.

### 사진 대기

- 항목 클릭 시 사진작업실로 이동하지 않고 선택 카드가 확장된다.
- 두 설정이 없는 MERGE_COMPLETED는 `원본 분리 완료 · 완료 처리 필요`로 표시한다.
- 두 설정이 있는 MERGE_COMPLETED만 승인 후 CLASSIFY_APPROVED로 진행한다.
- 한 설정만 있는 경우 자동 실행하지 않는다.
- 승인 후 진행 상태가 동일 카드에 반영된다.
- 보류 후 72시간 동안 표시되고 만료 후 제외된다.
- 완료와 X 확인 후 즉시 제외되며 프로젝트 행과 NAS 파일은 유지된다.
- 요청 실패 시 항목이 사라지지 않는다.

### 회귀

- 기존 데스크톱 사진 알림과 2단계 승인 흐름을 유지한다.
- RAW/JPG 안전장치, Worker 잡, Scene Engine은 변경하지 않는다.
- `npm run typecheck`, `npm test`, `npm run build`를 실행한다.

## 8. 범위 제외

- 사진작업실 기능 변경
- NAS 파일 삭제
- 사진 프로젝트 행의 실제 DELETE
- 분류 설정 자동 추측
- Scene Engine 변경
- 데스크톱 OS UI 개편
