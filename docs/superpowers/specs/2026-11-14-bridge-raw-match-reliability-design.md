# Bridge RAW 매칭 신뢰성 보강 설계

## 목표

Olivia Bridge에서 RAW 검색 범위를 고른 뒤 셀렉이 사라지거나, 같은 파일명의 다른 사진이 섞이거나, 실제 복사가 0장인데 완료로 보이는 오류를 제거한다. 기존 화면 구조와 파일명+촬영시각 사전 확인 규칙은 유지한다.

## 선택과 사진 식별

- RAW 검색 상위 폴더를 고를 때 현재 사진 폴더 핸들을 다시 설정하지 않는다. 같은 폴더의 새 핸들 객체 때문에 공용 셀렉 저장소가 초기화되지 않게 한다.
- Bridge에서 RAW 매칭으로 넘기는 사진은 basename만이 아니라 현재 폴더 기준 상대경로를 식별자로 사용한다.
- 레거시 입력처럼 basename만 전달된 경우는 기존 호환 동작을 유지하되, 상대경로가 있으면 정확히 같은 경로의 JPG만 대상으로 삼는다.
- 별점과 컬러 맵도 상대경로 키를 우선하고 basename 키는 레거시 폴백으로만 사용한다.

## 복사 대상과 충돌 방지

- 같은 작업 안에 동일한 RAW 파일명이 여러 장이면 `Selected_RAW` 아래에 원본의 상대 상위 폴더를 보존해 서로 덮어쓰거나 충돌하지 않게 한다.
- 파일명이 유일하면 기존처럼 `Selected_RAW` 바로 아래로 복사한다.
- 대상 파일 덮어쓰기 금지, 촬영시각 검증, 속성 보존 검증은 유지한다.

## 워커 경로와 실패 처리

- 브라우저가 RAW 폴더의 실제 상위 경로를 알 수 없으면 `/Volumes/<폴더명>`으로 추측하지 않는다. 사용자가 확인할 수 있도록 경로를 비워 둔다.
- JPG 작업 루트는 `JPG전체`, `JPG원본`, `JPG`를 실제 디렉터리 엔트리에서 NFC 기준으로 찾는다.
- 원본을 확인하기 전에 빈 `Selected_RAW` 폴더를 만들지 않는다.
- 처리 대상이 있는데 RAW 복사 성공·기존 완료가 0장이면 작업을 실패로 종료한다. 일부만 성공한 경우에만 성공 수와 단계별 실패를 함께 반환한다.

## Adobe 별점 기준

- `올리비아`: Olivia 별점과 로컬 편집만 사용한다.
- `어도비`: Adobe 별점만 사용하고 Olivia 편집은 무시한다.
- `둘 다`: Olivia와 Adobe를 합친 뒤 1~5점 편집만 덮어쓴다. 0점 편집은 Adobe 별점을 지우지 않는다.

## 검증

- 상위 RAW 폴더 선택 뒤 기존 셀렉 유지
- 동일 basename의 서로 다른 하위 폴더 JPG가 각각 올바른 RAW로 연결
- 동일 RAW basename의 복사 목적지 충돌 방지
- 전체 복사 실패 시 작업 실패 및 빈 결과 폴더 미생성
- `JPG전체`·`JPG원본`·`JPG` 탐색과 잘못된 워커 경로 추정 방지
- Adobe/Olivia/둘 다 별점 병합 규칙
- 관련 Vitest, TypeScript, 프로덕션 빌드
