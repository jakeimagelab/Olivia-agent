# 독립 초상권 동의서 설계

작성일: 2026-10-14  
대상: Olivia `main`

## 1. 목적

초상권 동의서는 고객관리의 촬영 프로젝트 문서로 계속 사용할 수 있어야 하며, 고객이나 프로젝트를 먼저 찾지 않고도 촬영 현장에서 즉시 작성하고 모델에게 서명 링크를 전달할 수 있어야 한다.

하나의 동의서 데이터와 서명 흐름을 두 진입점에서 공유한다.

- 독립 진입: 전체 앱 목록의 `초상권 동의서`
- 연결 진입: 고객관리의 고객·촬영 프로젝트 `문서` 탭

독립 앱과 고객관리용 동의서를 별도로 복제하지 않는다.

## 2. 범위

### 포함

- 전체 앱 목록에 독립 `초상권 동의서` 앱 표시
- `/portrait-consent` 관리자 경로를 독립 화면으로 복원
- 왼쪽 목록·오른쪽 작성/상세의 2열 화면
- 고객 및 촬영 프로젝트 연결, 변경, 해제
- 독립 생성 후 고객관리 문서 탭에서 같은 문서 확인
- 서명 완료 문서의 내용 잠금
- 기존 공개 서명 링크와 PDF 기능 유지
- 넓은 화면과 좁은 화면 대응

### 제외

- Dock 고정 아이콘 추가
- 이메일·문자 자동 발송
- 공개 서명 URL 변경
- 새로운 동의서 테이블 또는 서명 저장소 생성
- 고객이나 촬영 프로젝트의 자동 추정·자동 연결

## 3. 진입점과 라우팅

### 독립 앱

- 전체 앱 목록에 `초상권 동의서`를 별도 앱으로 표시한다.
- Dock 기본 항목에는 추가하지 않는다.
- 앱을 열면 `/portrait-consent`를 네이티브 Olivia 창으로 연다.
- 관리자 세션의 `/portrait-consent`를 고객관리로 리다이렉트하던 규칙은 제거한다.
- 관리자 세션이 없는 사용자가 토큰 없는 `/portrait-consent`에 접근하면 기존처럼 로그인 화면으로 보낸다.

### 고객관리

- 고객관리 `문서` 탭의 초상권 동의서 영역을 유지한다.
- 고객관리에서 열 때는 현재 `clientId`와 `workflowRunId`를 초기 연결값과 목록 필터로 사용한다.
- 독립 앱에서 해당 고객·프로젝트에 연결한 문서는 같은 영역에 즉시 나타난다.

### 공개 서명

- `/portrait-consent/[token]`은 로그인 없는 공개 서명 페이지로 유지한다.
- `/api/portrait-consent/[token]`의 토큰 검증, 만료, 취소, 1회 서명 규칙을 유지한다.

## 4. 화면 설계

동의서 작성은 글과 폼 중심이므로 Olivia UI 규칙의 밝은 화면을 사용한다. 주조는 `#155855`, 밝은 바탕은 `#FDFCFA`, 주 실행은 `#C94A1E`를 사용한다. 탭을 새로 만들지 않고 한 화면의 마스터-디테일 구조로 구성한다.

### 4.1 넓은 화면

화면은 왼쪽 목록과 오른쪽 작성·상세의 2열이다.

#### 왼쪽 목록

- 상단 `새 동의서 작성` 버튼
- 검색 입력
- 상태 필터: 전체, 초안, 전달됨, 서명 완료
- 각 행에 제목, 모델명, 연결 고객, 연결 프로젝트, 상태, 상대 수정 시각 표시
- 선택된 행만 초록 테두리 또는 옅은 초록 배경으로 표시
- 카드 그리드가 아니라 가로 목록 행을 사용
- 빈 목록에서는 동의서를 새로 작성하라는 한 줄 안내 표시

#### 오른쪽 작성·상세

- 새 문서일 때 작성 폼을 바로 표시
- 기존 문서를 선택하면 같은 위치에서 편집 또는 상세 표시
- 상단에 고객·프로젝트 연결 상태와 `고객 연결하기` 또는 `고객·촬영 건 변경` 버튼 표시
- 본문 순서: 제목 → 안내 문구 → 촬영 세부 내용 → 활용 목적
- 하단 고정 작업 영역에 상태 설명과 실행 버튼 배치
- 작성 중 주 실행은 `저장`, 저장된 미서명 문서의 주 실행은 `서명 링크 만들기`
- 한 시점에 채운 주 실행 버튼은 하나만 표시
- PDF 다운로드, 연결 변경, 삭제는 보조 또는 약한 동작으로 표시

### 4.2 좁은 화면

- 처음에는 목록을 표시한다.
- `새 동의서 작성` 또는 목록 항목을 누르면 오른쪽 화면을 전체 폭으로 전환한다.
- 작성 화면 상단의 `목록` 버튼으로 돌아간다.
- 편집 중인 값이 있으면 목록으로 돌아가기 전에 확인한다.

### 4.3 고객관리 내장 화면

- 같은 데이터와 작업 규칙을 사용한다.
- 현재 고객과 프로젝트로 목록을 제한한다.
- 화면 폭이 충분하면 같은 2열 구조를 사용하고, 좁으면 목록과 상세를 전환한다.
- 고객관리 자체 제목과 동의서 화면 제목이 중복되지 않도록 내부 헤더는 한 번만 렌더링한다.

## 5. 고객·촬영 프로젝트 연결

### 5.1 연결하기

1. `고객 연결하기`를 누른다.
2. 고객 검색 목록에서 고객 한 명을 명시적으로 선택한다.
3. 선택한 고객의 촬영 프로젝트만 표시한다.
4. 촬영 프로젝트는 선택 사항이다. 고객만 연결하고 완료할 수 있다.
5. 저장 전에 서버가 프로젝트가 해당 고객 소유인지 검증한다.

고객이나 프로젝트를 자동으로 추정하지 않는다.

### 5.2 변경과 해제

- 연결된 고객과 프로젝트는 변경할 수 있다.
- 고객을 바꾸면 이전 프로젝트 연결을 먼저 해제하고 새 고객의 프로젝트를 다시 선택하게 한다.
- 고객 연결을 해제하면 프로젝트 연결도 함께 해제한다.
- 잘못된 프로젝트 조합은 저장하지 않고 이유를 화면에 표시한다.

### 5.3 서명 완료 후

- 고객·프로젝트 연결 정보는 업무 분류 정보이므로 서명 완료 후에도 변경하거나 해제할 수 있다.
- 제목, 안내 문구, 세부 항목, 활용 목적, 동의 결과, 제공자 이름, 서명은 변경할 수 없다.
- 서명 완료 문서는 삭제 전에 명시적인 확인을 요구한다. 기존 삭제 정책 자체는 이번 범위에서 바꾸지 않는다.

## 6. 데이터와 API

기존 `portrait_consents` 테이블의 아래 열을 그대로 사용한다.

- `client_id`
- `workflow_run_id`
- 동의서 내용과 서명 관련 기존 열

새 DB 마이그레이션은 필요하지 않다.

### 목록

- 독립 앱은 최근 동의서 목록을 가져오고 검색·상태 필터를 적용한다.
- 고객관리에서는 기존 `clientId`와 `workflowRunId` 필터를 사용한다.
- 목록 응답에 연결 고객과 프로젝트를 식별해 표시하는 데 필요한 정보를 제공한다. 불필요한 개인정보 전체를 목록에 싣지 않는다.

### 생성과 편집

- 연결 없이 생성할 수 있다.
- 생성 시 명시적으로 선택한 `clientId`와 `workflowRunId`만 저장한다.
- 관리 API의 연결 변경은 UUID 형식과 고객-프로젝트 소유 관계를 검증한다.
- 서명 완료 상태에서는 연결 필드만 변경할 수 있고 내용 필드 변경 요청은 거부한다.

### 공개 서명

- 기존 32바이트 랜덤 토큰, SHA-256 해시 저장, 30일 만료를 유지한다.
- 링크를 다시 발급하면 이전 토큰을 무효화한다.
- 서명 원본은 계속 DB에 저장하며 PDF는 다운로드 산출물로만 취급한다.

## 7. 상태와 오류 처리

- 목록 로딩, 저장, 고객 연결, 링크 생성 상태를 각각 화면에 표시한다.
- 실패 메시지는 서버가 반환한 구체적인 이유를 보여준다.
- 저장에 실패하면 입력 내용을 유지한다.
- 고객 또는 프로젝트가 사라졌으면 임의의 다른 대상으로 바꾸지 않는다.
- 연결되지 않은 문서는 `미연결`로 명시한다.
- 링크 복사가 실패해도 생성된 URL을 화면에 표시해 직접 복사할 수 있게 한다.
- 서명 완료 문서에 대한 내용 수정 요청은 `서명 완료 문서는 내용을 수정할 수 없습니다.`로 거부한다.

## 8. 기존 기능 보존

- 기본 세부 항목과 활용 목적 편집
- 상태 흐름 `draft → sent → signed`
- 토큰 링크 생성과 재발급
- 공개 페이지의 예/아니오 선택, 제공자 성명, 캔버스 서명
- 관리자와 서명자의 PDF 다운로드
- 접속 횟수와 마지막 접근 시각 기록
- Olivia 검색어 `초상권`, `초상권 동의서`, `촬영 동의서`, `사진 동의서`, `영상 동의서`

## 9. 테스트와 완료 조건

### 라우팅·앱

- 전체 앱 목록에 독립 앱이 한 번 표시된다.
- 기본 Dock에는 표시되지 않는다.
- `/portrait-consent`가 독립 네이티브 창으로 열린다.
- `/portrait-consent/[token]`은 리다이렉트되지 않는다.

### 문서·연결

- 고객과 프로젝트 없이 초안을 생성할 수 있다.
- 고객만 연결할 수 있다.
- 고객과 그 고객의 프로젝트를 연결할 수 있다.
- 다른 고객의 프로젝트 연결은 거부된다.
- 고객 변경 시 이전 프로젝트가 해제된다.
- 연결 해제 시 고객과 프로젝트가 모두 비워진다.
- 연결한 문서가 고객관리 문서 탭에 같은 ID로 나타난다.

### 서명·보존

- 기존 공개 링크에서 서명을 제출할 수 있다.
- 서명 완료 후 내용 편집은 서버에서도 거부된다.
- 서명 완료 후 고객·프로젝트 연결 변경은 가능하다.
- PDF 다운로드가 관리자와 서명자 화면에서 유지된다.
- 기존 토큰 만료·취소·재발급 동작이 유지된다.

### UI·품질

- 넓은 화면에서 왼쪽 목록과 오른쪽 작성 화면이 동시에 보인다.
- 좁은 화면에서 목록과 작성 화면을 전환할 수 있다.
- 제목 중복과 `GlobalHeader` 중복이 없다.
- 주 실행 버튼이 한 화면에 하나다.
- 타입 검사, 변경 파일 린트, 관련 테스트, 전체 Vitest, 프로덕션 빌드를 통과한다.
- Supabase 스키마 변경이 없음을 확인한다.

## 10. 구현 시 주의사항

- 독립 앱과 고객관리 화면이 별도 문서 사본을 만들지 않게 한다.
- 기존 공개 링크를 관리자 독립 라우팅 변경에 함께 리다이렉트하지 않는다.
- UI에서만 잠그지 말고 API에서도 서명 완료 내용 수정을 차단한다.
- 현재 저장된 즐겨찾기나 창의 `portrait-consent` 앱 ID는 독립 앱으로 정상 복원되게 마이그레이션 규칙을 조정한다.
- 관련 없는 고객관리, 계약서, 콘티 기능은 수정하지 않는다.
