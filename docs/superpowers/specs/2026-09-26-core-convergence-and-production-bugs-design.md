# Olivia Core 연결 및 실사용 버그 안정화 설계

작성일: 2026-09-26

## 목표

기존 Core Snapshot과 Command를 새로 만들지 않고 남은 화면과 연결한다. 동시에 채팅 스트림 라우트를 역할별 모듈로 분리하고, 사진 씬 이름·NAS 폴더 조회·고객관리 렌더 루프·창 내부 중복 헤더 문제를 기존 구조 안에서 수정한다.

## A. Core 마무리

### 화면 상태 단일화

견적서, 구형 콘티, 고객관리, 고객 워크스페이스 단계 카드, 모바일 문서 미리보기는 해당 화면이 보유한 정확한 `workflowRunId`로 `useCoreProjectSnapshot`을 조회한다. 프로젝트 단계와 문서 자원 존재 여부는 Snapshot을 기준으로 표시하고, 화면별 중복 workspace 조회는 제거한다. 저장·완료·공개 후에는 `notifyCoreSnapshotUpdated`로 같은 프로젝트를 보고 있는 다른 화면을 무효화한다.

미션 바는 두 모드를 유지한다. 명시적 `workflowRunId`가 있으면 Snapshot을 사용하고, 없으면 기존 요약 API가 가장 급한 프로젝트를 고른 뒤 그 프로젝트의 Snapshot을 조회한다. 추천 미션과 현재 채팅 대상이 다를 수 있다는 기존 의미는 유지한다.

### 스트림 라우트 분리

현행 동작과 이벤트 순서를 바꾸지 않고 승인 대기 처리, Hermes 턴, legacy 턴을 각각 `pendingAction.ts`, `hermesTurn.ts`, `legacyTurn.ts`로 옮긴다. `route.ts`는 요청 파싱, 공통 컨텍스트 준비, 경로 선택, SSE 전송과 최종 저장 조정만 담당한다. 리팩터 전후 전체 테스트 결과를 비교하고 `route.ts`를 400줄 이하로 만든다.

## B. 실사용 버그

### 씬 이름

AI 분석 미실행과 AI 분석 후 판별 실패를 구분한다. 전자는 `미분류` 또는 기존 진료과 규칙으로 얻은 추정 씬명을 사용하며 추정임을 폴더명과 작업 경고에 명시한다. 후자는 기존 `기타`를 유지한다. 시간대 경계 규칙은 변경하지 않는다. Worker 상태 보고에 AI 키 사용 가능 여부를 포함하고 시스템 상태가 작업 전 경고할 수 있게 한다.

### NAS 폴더 조회

최상위 조회는 빈 문자열 대신 설정에서 얻은 명시적 루트 경로를 사용한다. 설정이 없으면 사용자에게 단계와 사유가 드러나는 오류로 끝낸다. `listFolder` 진입점은 빈 경로를 거부한다. 한글 비교는 NFC/NFD 차이를 흡수하도록 Unicode 정규화를 유지·검증한다.

### 고객관리 렌더 루프

먼저 실제 브라우저에서 고객관리 창을 열어 콘솔 스택과 반복 호출을 확인한다. 원인이 Context Store 양방향 동기화라면 읽기 selector를 primitive로 제한하고 쓰기는 구독 없는 `getState()` 경로로 유지한다. 동일값 쓰기와 객체 전체 effect 의존성을 제거하고 고객 전환 회귀 테스트를 보강한다.

### 창 내부 중복 헤더

앱 레지스트리와 legacy iframe 경로를 함께 조사해 창 안에서 자체 헤더·닫기 버튼을 그리는 화면 목록을 만든다. 직접 URL에서는 헤더를 유지하고, Desktop Window에 embedded/modal로 렌더링될 때만 숨긴다. 기존 `mode`, `isModal`, `embedded` 패턴 중 각 화면의 기존 API를 우선 재사용한다.

## 검증

- 각 작업의 지정 grep과 단위 테스트를 실행한다.
- 스트림 리팩터 전 기준은 232개 파일, 1,611개 테스트 통과다.
- 최종적으로 `npm run typecheck`, `npm test`, `npm run build`를 실행한다.
- 고객관리와 창 헤더는 가능한 범위에서 실제 브라우저로 재현·검증하며, 인증이나 운영 데이터 제약으로 확인하지 못한 항목은 완료로 주장하지 않는다.

## 비범위

새 상태 머신, 새 Snapshot, 새 Command 레이어, 사진/워크플로 상태 통합, Scene Engine 시간 경계 변경, `legacyOliviaCore.ts` 수정, Desktop 디자인 개편은 하지 않는다.
