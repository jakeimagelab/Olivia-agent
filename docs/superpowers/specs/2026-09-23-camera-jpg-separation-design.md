# 카메라별 JPG 분리 설계

## 목표

기존 사진 작업 상태 머신(`PHOTO_PREPARE_SOURCE` → `PHOTO_STAGE_JPG` → `PHOTO_CLASSIFY_WORK`)과 RAW 보호 규칙을 유지하면서, JPG를 파일명 접두어와 R5K/DSC 비율에 따라 메인·스케치·프로필/인테리어 폴더로 분리한다.

## 저장 구조

고정 폴더명은 `lib/photo-classifier/node/storageLayout.ts`에서만 선언한다.

```text
Workstation/<project>/
├ JPG전체/                 # R5K 또는 DSC 중 판정된 메인
├ JPG_스케치/              # 나머지 R5K 또는 DSC
└ JPG_프로필인테리어/      # _AK

Agentstation/<project>/
├ JPG전체/
├ JPG_스케치/
├ JPG_프로필인테리어/
└ 씬별분류/
   ├ 메인/
   │  └ Scene...
   └ 프로필인테리어/
      └ Scene...
```

RAW와 영상 파일은 원래 위치에 유지한다. `JPG_스케치`는 복사까지만 수행하고 Scene 분류에서 제외한다.

## 카메라 판정

JPG/JPEG 파일의 basename을 대소문자 구분 없이 검사한다.

- `R5K*`: Sony A7R5
- `DSC*`: Sony A7M4
- `_AK*`: Canon 5D MK4
- 나머지: 지원하지 않는 파일명

`_AK`는 메인 비율에서 제외한다. R5K와 DSC 중 한쪽만 있으면 그쪽이 메인이다. 양쪽이 있으면 각 장수를 둘의 합으로 나눈다.

- R5K 비율이 70% 이상: R5K 메인, DSC 스케치
- DSC 비율이 70% 이상: DSC 메인, R5K 스케치
- 어느 쪽도 70% 미만: 자동 이동 금지, 사용자 선택 필요
- R5K와 DSC가 모두 0장이고 `_AK`만 존재: 메인·스케치는 비어 있고 `_AK`만 프로필/인테리어로 준비

지원하지 않는 파일명이 하나라도 있으면 전체 계획을 중단한다. 결과에는 파일 목록과 카메라별 장수를 포함한다.

## 애매한 비율의 사용자 선택

기존 사진 도구 입력에 선택적 `mainCamera: "R5K" | "DSC"`를 추가한다. 첫 실행이 애매하면 `PHOTO_PREPARE_SOURCE`는 파일을 옮기지 않고 `REVIEW_REQUIRED` 결과에 `cameraSelectionRequired`, R5K/DSC/_AK 장수와 허용 선택지를 기록한다.

`mainCamera`는 자동 비율 판정이 불가능한 경우에만 사용한다. 70% 규칙으로 메인이 확정된 프로젝트에서는 입력값으로 자동 판정을 뒤집지 않는다.

채팅 사진 오케스트레이터는 이 결과를 사용자에게 보여주고 다음 답변의 `R5K` 또는 `DSC`를 같은 프로젝트의 선택으로 해석한다. 사용자가 선택하면 같은 기존 파이프라인을 `mainCamera`와 함께 재주문한다. 프로젝트가 애매한 상태라는 근거 없이 단독으로 들어온 카메라명은 실행 명령으로 해석하지 않는다.

## PHOTO_PREPARE_SOURCE

1. 프로젝트 전체에서 symlink를 거부한다.
2. RAW 스냅샷과 JPG/RAW가 아닌 기존 일반 파일 스냅샷(path/name/size/mtime)을 만든다. 따라서 MP4, MOV 등 영상도 확장자 목록 누락 없이 보호한다.
3. 기존 세 대상 폴더를 재실행 대상으로 제외하고 나머지 JPG를 전수 수집한다.
4. 접두어, 비율, 중복 파일명, 기존 목적지 충돌을 모두 사전 검증한다.
5. 검증이 끝난 뒤 세 목적지 폴더를 만들고 동일 볼륨 `rename`만 수행한다.
6. 중간 실패 시 이동 완료 항목을 역순으로 원래 경로에 되돌린다.
7. 세 대상 폴더의 JPG 합계와 접두어 배치를 검증한다.
8. RAW와 영상 스냅샷이 완전히 같은지 검증한다.

이동 전 첫 진행 메시지는 `R5K 1,842장 / DSC 203장 — R5K를 메인으로 통합합니다` 형식으로 기록한다. `_AK` 장수도 별도 결과 필드에 포함한다.

이미 준비된 프로젝트는 세 폴더의 기존 파일을 판정에 포함해 idempotent하게 완료한다. 기존 파일과 새 파일 사이에 이름 충돌 또는 잘못된 접두어가 있으면 덮어쓰지 않고 `REVIEW_REQUIRED`로 중단한다.

## PHOTO_STAGE_JPG

한 잡 안에서 세 원본 폴더를 각각 같은 이름의 SSD2 폴더로 복사한다. 존재하지 않는 선택적 폴더는 빈 폴더를 강제로 만들지 않지만, 존재하는 모든 폴더는 하나의 사전검사와 최종검증 범위에 포함한다.

- 복사 전 전체 필요 용량과 안전 여유를 확인한다.
- `.olivia-part`, SHA-256 idempotency, metadata 보존, overwrite 금지 규칙을 폴더별로 동일 적용한다.
- SSD1 RAW와 영상 스냅샷을 복사 전후 비교한다.
- 결과 count/bytes는 세 폴더 합계이며 폴더별 요약도 포함한다.
- 한 폴더라도 실패하면 `COPY_COMPLETED`를 반환하지 않는다.

## PHOTO_CLASSIFY_WORK

한 잡 안에서 다음 두 분류를 순차 실행한다.

1. `JPG전체` → `씬별분류/메인`
2. `JPG_프로필인테리어` → `씬별분류/프로필인테리어`

입력 폴더가 없거나 JPG가 0장이면 해당 분류만 건너뛴다. `JPG_스케치`는 읽기·분류하지 않는다. 두 입력의 원본 불변식을 각각 검증하며, 어느 하나라도 실패하면 전체 작업은 완료로 표시하지 않는다. 최종 `jpgCount`와 `sceneCount`는 두 분류의 합계이고 결과에 대상별 요약을 포함한다.

기존 Scene Engine 설정, 시간 밴드, AI 판정 로직은 변경하지 않는다.

## 서버와 UI 연동

- remote job action 이름과 프로젝트 상태 값은 추가하지 않는다.
- remote job payload에 선택적 `main_camera`만 전달한다.
- merge/copy/classification sync는 기존 합산 필드를 계속 기록한다.
- 작업 전 카메라 판정 메시지는 worker progress로 표시한다.
- 애매한 비율 또는 지원하지 않는 파일명은 기존 `REVIEW_REQUIRED` 알림 흐름을 사용한다.
- 채팅 도구 설명과 직접 실행 오케스트레이터에 카메라 선택 후속 처리만 추가한다.
- 기존 알림 카드의 2단계 승인 흐름은 유지한다.

## 검증

회귀 테스트는 최소 다음을 포함한다.

1. R5K 90%: R5K 메인, DSC 스케치, _AK 별도
2. DSC 90%와 MP4: DSC 메인이고 MP4 불변
3. R5K/DSC가 모두 70% 미만: 이동 0, 선택 요구
4. 사용자 R5K/DSC 선택 후 정확한 분리
5. 알 수 없는 접두어: 이동 0, 파일 목록 반환
6. 세 목적지 합계가 원래 JPG 총수와 일치
7. 각 목적지에 허용 접두어만 존재
8. RAW 및 영상 path/name/size/mtime 불변
9. 충돌·symlink·EXDEV 시 완료 금지와 rollback
10. 세 폴더 SSD2 복사, metadata/SHA-256/idempotency 검증
11. 메인과 프로필/인테리어의 별도 Scene 출력
12. 스케치는 Scene Engine 호출 0회
13. 기존 사진 파이프라인 및 저장소 테스트 통과

## 범위 제외

- RAW·영상 이동, 복사, 삭제, 이름 변경
- 잡 action 및 프로젝트 상태 머신 신설
- Scene Engine 시간 정책 또는 가중치 변경
- 스케치 Scene 분류
- 별도 씬 이름 문제 수정
- 알림 카드 승인 단계 변경
