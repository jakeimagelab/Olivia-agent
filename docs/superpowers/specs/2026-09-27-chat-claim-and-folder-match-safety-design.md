# 채팅 완료 주장·사진 폴더 매칭 안전 설계

작성일: 2026-09-27

## 문제

Olivia legacy 실행 경로는 이번 턴에 실제 도구가 실행되지 않아도 모델이 "열었어", "저장했어" 같은 완료 문장을 만들 수 있다. 현재 `executionEvidence.ts`는 이 사실을 다음 턴 프롬프트에만 알려주므로 사용자가 잘못된 완료 안내를 이미 본 뒤에야 정정된다.

사진 직접 실행 경로는 사용자 문장에서 폴더명처럼 보이는 부분을 정규식으로 잘라 검색한다. 이 과정에서 병원명 끝의 `과`가 구분자로 잘리고 `좀` 같은 표현이 검색어에 남아 실제 Workstation 폴더를 찾지 못한다.

## 목표

- 이번 턴의 성공한 도구가 뒷받침하지 않는 완료 주장을 사용자에게 보내지 않는다.
- 검색과 열기를 구분해 `search_`, `get_`, `list_` 성공만으로 "열었다"를 허용하지 않는다.
- 폴더명을 문장에서 추측하지 않고 실제 Workstation 루트 폴더 목록을 사용자 원문과 대조한다.
- 여러 폴더 요청의 문장 순서, 동일 이름의 모호성, 단어 중간 오탐을 보존한다.
- 기존 사진 작업 도구, 워커 잡, 승인·재시작·진료과 확인 흐름은 바꾸지 않는다.

## 작업 A: 완료 주장 가드

### 순수 판정기

`lib/olivia/v2/completionClaimGuard.ts`에 `enforceCompletionClaims()`를 둔다. 입력은 모델 답변과 이번 턴 실행 장부이며, 출력은 정리된 답변과 근거 없이 제거된 주장 그룹이다.

도구 이름은 `mcp_olivia_` 접두사를 제거하고 점을 밑줄로 바꾼 뒤 비교한다. 성공한 도구만 증거로 인정한다.

- `open`: `open_`, `select_`, `preview_`, `navigate`, `_open`
- `create`: `create_`, `add_`, `start_`, `generate_`, `link_new_`, `_create`, `_wizard`
- `update`: `update_`, `apply_`, `set_`, `save_`, `rebalance_`, `resolve_`, `retry_`, `advance_`, `_update`
- `send`: `send_`, `publish_`, `request_`, `download_`, `share_`, `deliver_`, `_publish`, `_pdf`
- `remove`: `delete_`, `remove_`, `archive_`, `cancel_`, `defer_`, `_archive`, `_delete`, `_remove`

`search_`, `get_`, `list_`는 `open` 근거에 포함하지 않는다.

본문은 줄바꿈과 문장부호로 분리한다. 완료 종결형만 검사하며 인용·자백 형태인 `고/다고/라고`, 질문형, 본문 표시 자체로 완료되는 `보여 드렸/표시했`은 제외한다. 근거 없는 문장만 제거하고, 그룹별 실패 안내를 한 번씩 덧붙인다. 다른 사실 문장은 유지한다.

### 적용 지점

`legacyTurn.ts`에서 두 번 적용한다.

1. 각 라운드 텍스트를 `flushTextAsDeltas()`로 보내기 직전
2. 최종 `saveTurnAssistant()` 직전

첫 번째 가드는 화면 노출을 막고, 두 번째 가드는 이후 분기에서 합쳐진 텍스트까지 다시 검증한다. 차단 시 `[olivia/completion-claim]` 구조화 로그에 conversation ID, round, 차단 그룹, 도구명과 성공 여부만 남긴다. 사용자 원문과 응답 본문은 로그에 남기지 않는다.

## 작업 B: 실제 목록 기반 폴더 매칭

### 순수 매처

`lib/photo-storage/folderMatch.ts`에 폴더명 정규화·매칭·그룹화를 둔다.

- NFC 정규화, 소문자화, 공백·밑줄·하이픈 제거 규칙은 기존 카탈로그와 동일하게 유지한다.
- 정규화된 각 글자가 원문의 어느 인덱스에서 왔는지 대응표를 함께 만든다.
- 날짜 접두사는 `/^\d{2,8}[\s._-]*/`로 제거해 핵심 이름을 만든다. 제거 결과가 비면 원래 이름을 쓴다.
- 전체 폴더명부터 찾고 성공하면 점수 2, 핵심 이름은 점수 1로 둔다.
- 매치는 문장 시작 또는 비단어 문자 다음에서만 허용한다.
- 핵심 이름이 3글자 이하면 뒤쪽 단어 경계도 요구한다.
- 2글자 미만 후보는 사용하지 않는다.
- 더 긴 매치가 다른 매치 범위를 완전히 포함하면 짧은 후보를 제거한다.
- 겹치는 범위는 동일 대상의 후보 그룹, 겹치지 않는 범위는 별도 작업 대상으로 분리한다.
- 그룹은 문장 순서, 그룹 내부는 점수와 길이 내림차순으로 반환한다.

### 카탈로그 연결

`photoFolderCatalog.ts`의 `matchPhotoFoldersInMessage()`가 `listRoot({ foldersOnly: true })` 결과를 순수 매처에 전달한다. 새 API나 공개 Tool은 추가하지 않는다.

`directChatExecution.ts`는 `parseOperation()`과 Scene 설정 판정만 유지한다. `cleanFolderQuery()`와 `splitFolderQueries()`는 삭제한다. 새 명령에서는 실제 폴더 매칭 그룹으로 작업 항목을 만든다.

- 그룹 하나에 후보 하나: 원본 `displayName`을 정확한 실행 대상으로 사용한다.
- 그룹 하나에 후보 여러 개: 쓰기 작업을 시작하지 않고 기존 후보 선택 흐름으로 되묻는다.
- 그룹 여러 개: 원문에 등장한 순서대로 독립 처리한다.
- 그룹 없음: 기존처럼 정확한 폴더명을 요청하며 파일 업로드를 제안하지 않는다.

후속 `folder_retry`도 목록 매칭 결과로만 대상을 바꾸며 군말 제거 정규식은 사용하지 않는다. 기존 `find_photo_folder`/`start_photo_source_prep`/`start_photo_scene_sort`와 워커 안전장치는 그대로 유지한다.

## 오류 처리와 안전 경계

- 완료 주장 가드는 텍스트만 교정하며 도구를 새로 호출하거나 반대 작업을 실행하지 않는다.
- 실행 장부에 실패만 있으면 완료 주장은 차단한다.
- 폴더 후보가 모호하면 어떤 폴더도 임의 선택하지 않는다.
- 실제 폴더명과 상대 경로는 정규화 문자열로 대체하지 않고 원문 그대로 실행 도구에 전달한다.
- 직접 실행이 비활성화됐거나 Hermes가 이미 사진 도구를 호출한 경우의 기존 중복 방지는 유지한다.

## 테스트

### 완료 주장

요청서의 11개 사례를 모두 고정한다. 특히 검색만 성공한 상태의 "열었어", 실패한 열기, 복합 생성·전송 문장, 인용형 자백과 질문형을 구분한다. legacy 경로에서는 스트림 전과 저장 전 가드가 모두 적용되고 차단 로그가 남는지 검증한다.

### 폴더 매칭

오늘 실패한 `연세라이프구강내과`와 `0923_연세라이프구강` 문장, 다양한 조사·군말·위치 표현, 여러 폴더 순서, 날짜 접두어, 띄어쓰기 차이를 검증한다. 단어 중간 `청담`, 짧은 `강남`, 더 긴 `연세라이프구강내과`, 동일 핵심명을 가진 날짜별 폴더로 R1~R3와 모호성 방어를 고정한다.

기존 `photoDirectExecution`, `photoFolderCatalog`, Hermes/legacy 실행 테스트에 더해 전체 typecheck, test, production build를 실행한다.

## 범위 밖

- `tool_choice` 강제 확대
