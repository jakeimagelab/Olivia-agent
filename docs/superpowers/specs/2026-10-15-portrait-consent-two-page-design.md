# 초상권 동의서 2면 개편 설계

작성일: 2026-10-15  
기준: `main` v22, 캔버스 「포토클리닉 초상권 동의서」 1면·2면

## 목표

- 공개 서명 화면과 데스크탑 관리 화면에서 같은 2면 동의서 원본을 사용한다.
- 각 면을 `794 × 1123px` A4 비율로 고정하고 PDF를 정확히 2페이지로 만든다.
- PDF 캡처 전에 웹폰트 준비를 기다려 `초상권` 등 굵은 한글의 받침 누락을 없앤다.
- 제공자 연락처, 출연 역할, 실제 신분 여부, 민감정보 동의를 사람별 서명 기록에 추가한다.
- 기존 서명 기록과 기존 공유 링크를 변경하거나 삭제하지 않는다.
- 법적 문구는 요청서와 캔버스 원문을 글자 그대로 사용한다.

## 문서번호 처리

현재 `portrait_consents`와 서명 기록에는 문서번호가 저장되어 있지 않다. 요청대로 `portrait_consents` 스키마를 변경하거나 UUID·작성일에서 번호를 임의 생성하지 않는다.

- 저장된 문서번호가 없는 현재 문서는 헤더에 `문서번호 —`를 표시한다.
- 이후 별도 요구로 문서번호 원천이 생기기 전까지 순번을 추측하지 않는다.
- 이번 마이그레이션은 요청된 서명 기록의 nullable 열 다섯 개만 추가한다.

## 공용 문서 구조

관리자 상세와 공개 서명 완료·미리보기에서 서로 다른 문구가 생기지 않도록 하나의 공용 문서 컴포넌트를 사용한다.

- 루트는 두 개의 페이지를 순서대로 포함한다.
- 각 페이지는 `width: 794px; height: 1123px`로 고정한다.
- 두 페이지 모두 포토클리닉 로고, 문서번호, 딥그린 가로선과 동일한 푸터를 사용한다.
- 1면은 `1 / 2`, 2면은 `2 / 2`를 우측 하단에 표시한다.
- PDF 캡처 루트에는 페이지 사이 시각적 여백을 넣지 않아 기존 세로 분할 로직이 정확히 두 번만 잘라 내도록 한다.
- 화면에서는 필요할 때 바깥 래퍼가 문서를 축소해 보여주되, 캡처 대상의 실제 크기는 바꾸지 않는다.

공용 컴포넌트는 기존 동의서의 `detail_fields`, `usage_items`와 선택한 `portrait_consent_signatures` 한 건을 입력으로 받는다. 새 필드가 모두 `null`인 기존 서명도 체크와 연락처 칸을 비운 채 정상 렌더링한다.

## 1면: 초상권 사용 동의

### 레터헤드와 제목

- 좌측: `/assets/photoclinic-logo.png`
- 우측: 문서번호와 발행일
- 제목: `초상권 사용 동의서`
- 부제: 동의서 제목 또는 촬영 대상 설명

### 촬영 정보

기존 `detail_fields`를 라벨로 찾아 아래 순서로 표시한다.

1. 촬영 목적
2. 촬영 의뢰 — `{병원명} (의뢰) · 포토클리닉 (촬영·제작)`
3. 촬영 일시 · 장소 — 두 기존 값을 한 행에 ` · `로 연결
4. 촬영 내용
5. 사용 기간
6. 출연 역할 — 새 서명 필드
7. 실제 신분 여부 — 새 서명 필드

기존 데이터에 해당 값이 없으면 빈 칸으로 두며 다른 값을 추정하지 않는다.

### 활용 범위

- 홈페이지와 SNS 및 홍보매체는 기존 `usage_items` 값을 사용한다.
- 편집·보정은 아래 두 줄을 그대로 표시한다.

```text
합니다 — 밝기·색감 보정, 자르기, 크기 조정, 먼지·반사 제거
하지 않습니다 — 얼굴·체형 변형, 다른 사람·장소와의 합성, 받지 않은 시술을 받은 것처럼 보이게 하는 편집
```

### 동의 확인과 서명

- `consent_shoot`와 `consent_usage`는 `동의` / `미동의` 체크 상자로 표시한다.
- 선택된 상자만 딥그린 배경과 흰 체크를 사용한다.
- 제공자 연락처, 가운데 날짜, 제공자 서명, 포토클리닉 대표 정연호 서명을 순서대로 배치한다.
- 대표 서명은 `/assets/ceo-signature.png`를 사용한다.
- 유의사항 마지막 줄에 `본 동의서는 2면으로 구성되며, 2면의 개인정보 동의까지 받아야 효력이 있습니다.`를 넣는다.

## 2면: 개인정보 수집·이용 동의

제목 아래에 개인정보 보호법 안내, 수집·이용 안내 표, 거부권 경고 상자, 민감정보, 철회와 문의, 서명 순서로 배치한다.

- 수집 항목·이용 목적·보유 및 이용 기간·취급하는 자 문구는 요청서 원문을 고정 문구로 사용한다.
- 병원명만 1면의 촬영 의뢰 데이터에서 가져온다.
- 거부권 고지는 주황 경고 박스로 표시하고 원문을 그대로 사용한다.
- `is_real_identity === false`이면 민감정보의 `해당 없음`을 선택한다.
- `is_real_identity === true`이면 `consent_sensitive`에 따라 동의 또는 미동의를 선택한다.
- 기존 서명처럼 `is_real_identity === null`이면 세 항목을 모두 비워 둔다.
- 철회 창구와 처리 방법은 요청서 원문을 그대로 사용한다.
- 하단에는 1면 정보 재사용 안내, 날짜, 제공자 서명, 사본 제공 문구를 배치한다.

## 공개 서명 화면

기존 입력의 이름과 순서를 유지한 뒤 아래 네 입력을 추가한다.

1. 연락처 — 필수 전화번호 입력
2. 출연 역할 — 환자·고객 / 의료진 / 직원 / 기타, 기타 선택 시 텍스트 필수
3. 실제 신분 여부 — 실제 본인 신분 / 역할 출연(연기)
4. 민감정보 동의 — 실제 본인 신분일 때만 표시하고 필수

역할 출연을 선택하면 민감정보 입력을 숨기고 제출값은 `null`로 보낸다. 제출 가능 조건과 API 검증 양쪽에서 같은 필수 조건을 적용한다. 기존 이름·촬영 동의·활용 동의·서명 입력의 명칭과 동작은 바꾸지 않는다.

## 데이터와 API

마이그레이션 `supabase/migrations/20261015_portrait_consent_role_fields.sql`에서 `portrait_consent_signatures`에 아래 nullable 열만 추가한다.

- `provider_phone text`
- `appearance_role text`
- `appearance_role_other text`
- `is_real_identity boolean`
- `consent_sensitive boolean`

기존 9인자 `submit_portrait_consent_signature` 함수는 보존한다. 새 공개 제출은 새 열을 함께 저장하는 오버로드 함수를 사용해 한 트랜잭션 안에서 서명 추가, 완료 수 계산, 부모 상태 갱신을 유지한다. 기존 행은 update하지 않으며 새 열은 모두 `null`로 남는다.

- 공개 POST는 네 입력을 검증하고 새 오버로드를 호출한다.
- 공개 응답과 관리자 서명 목록 API는 새 다섯 필드를 반환한다.
- 공개 GET은 다른 서명자의 개인정보를 반환하지 않는 기존 원칙을 유지한다.
- 원격 DB에 마이그레이션을 자동 적용하지 않는다.

## PDF 생성

기존 이미지 로딩 대기 직후, `html2canvas` 호출 직전에 다음 한 줄만 추가한다.

```ts
await document.fonts.ready;
```

페이지 크기 계산과 jsPDF 페이지 추가 로직은 수정하지 않는다. 두 개의 고정 A4 화면을 하나의 캡처 루트에 붙여 기존 분할 로직이 두 페이지를 만들게 한다.

## 디자인

- 주조 `#155855`, 본문 `#1B2A27`, 보조 글자 `#5A7470`
- 라벨 `#F3F7F6`, 표 바깥선 `#D5DEDB`, 안쪽선 `#E4EAE8`
- 안내 상자 `#F1F7F5`와 3px 딥그린 띠
- 경고 상자 `#FFF4EE`, `#F0CDB9`, `#B03F14`
- 라벨 너비 126px, 셀 여백 7px 13px, 모든 셀 세로 중앙 정렬
- Pretendard, 본문 12px 이상, 제목 26px/700, 나머지 굵기 500 이하
- 본문 주황 사용 금지, 계좌번호 미표시, 푸터 가운데 두 줄

## 검증

- 기존 서명 데이터가 마이그레이션 전후 동일하고 새 열만 `null`인지 확인한다.
- 새 입력 검증, 역할 출연의 민감정보 `null`, 실제 신분의 민감정보 필수 조건을 테스트한다.
- 기존 서명과 신규 서명 모두 관리자 화면과 공개 완료 화면에서 2면 문서를 만든다.
- 브라우저에서 794×1123 두 면, 체크 표시, 법적 문구, 11px 이하 글자 부재를 확인한다.
- PDF가 2페이지이고 `초상권` 글자가 정상이며 1면 하단에 과도한 여백이 없는지 렌더링해 확인한다.
- 타입 검사, 변경 파일 ESLint, 관련 Vitest, 전체 Vitest와 프로덕션 빌드를 실행한다.

## 보존 범위

- `portrait_consents` 테이블, 기존 `portrait_consent_signatures` 열과 행을 변경하지 않는다.
- 공유 링크·토큰·서명 인원 제한·기존 서명 패드 동작을 유지한다.
- 로고와 대표 서명 자산을 변경하지 않는다.
- PDF 페이지 배치 계산은 변경하지 않는다.
- 요청서와 캔버스의 법적 문구를 고치거나 요약하지 않는다.
