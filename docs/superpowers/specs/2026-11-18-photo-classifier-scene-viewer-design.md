# 사진 분류 장면 이미지 뷰어 설계

작성일: 2026-11-18

## 목표

사진 분류의 씬 검토 행에서 시작·끝 사진을 식별할 수 있을 만큼 크게 보여주고, 썸네일을 누르면 해당 씬 전체를 원본 기준으로 검토하며 현재 사진 앞에서 바로 분할할 수 있게 한다. 기존 장면 이름·승인·병합·분할 데이터 흐름은 변경하지 않는다.

## 화면 구조

### 씬 검토 행

- 시작·끝 이미지를 각각 96×64px로 표시한다.
- 이미지는 `object-fit: cover`, 모서리는 4px로 표시한다.
- 이미지 아래에 `시작`, `끝` 라벨을 둔다.
- 시작과 끝이 같은 한 장짜리 씬은 썸네일 하나만 표시하고 `시작·끝`으로 표기한다.
- 행용 썸네일 생성 크기는 160px에서 320px로 높인다.

### 장면 뷰어

- `SceneImageViewer`를 독립 컴포넌트로 만든다.
- 목록에는 뷰어 인스턴스를 하나만 두고 현재 씬과 사진 위치만 전달한다.
- 중성 다크 작업 패널 위에 원본 비율을 보존한 이미지를 `contain`으로 표시한다.
- 상단에는 `씬 이름 · 현재 번호 / 전체 · 파일명 · 촬영시각`을 표시한다.
- 좌우 버튼과 키보드 `←`, `→`로 이동하고 `Esc` 또는 오버레이 바깥 클릭으로 닫는다.
- 하단 필름스트립은 현재 사진을 민트 테두리로 강조한다.
- `이 사진 앞에서 분할`은 첫 사진에서는 비활성화하고, 나머지 사진에서는 기존 `onSplitScene(listIndex, currentIndex)`를 호출한다.
- `splitPositions`에 실제 저장된 위치가 있을 때만 해당 위치 앞에 분할 표시선을 그린다. 화면 기본값 `1`은 추천값으로 오인되지 않도록 표시하지 않는다.

## 이미지와 메모리 처리

- 큰 이미지는 `scene.files[index].handle.getFile()`로 읽고 `URL.createObjectURL`로 표시한다.
- 사진 이동, 씬 변경, 뷰어 닫기, 컴포넌트 해제 시 이전 URL을 즉시 `URL.revokeObjectURL`한다.
- 원본 URL은 현재 사진 한 장만 유지한다.
- 필름스트립 항목은 `IntersectionObserver`로 가시 영역에 들어온 경우에만 파일을 읽고 작은 썸네일을 생성한다.
- 이미 생성된 행 썸네일이 있는 시작·끝 사진은 우선 재사용한다.
- 로드 실패는 해당 사진 자리에 파일명과 실패 상태를 표시하고, 뷰어 전체는 닫지 않는다.

## 컴포넌트 경계

- `FieldSceneReviewList`: 현재 열려 있는 씬과 사진 위치를 관리하고 뷰어 하나를 렌더링한다.
- `FieldSceneReviewRow`: 시작·끝 썸네일 표시와 뷰어 열기 요청만 담당한다.
- `SceneImageViewer`: 원본 URL 수명, 키보드 이동, 필름스트립, 분할 실행을 담당한다.
- 지연 필름스트립 썸네일은 뷰어 내부의 작은 독립 컴포넌트로 두어 가시성 구독과 이미지 로드를 항목 단위로 격리한다.

## 기존 기능 보존

- 장면 분할은 기존 `onSplitScene` 콜백을 그대로 사용한다.
- 장면 이름 수정, 추천 이름 적용, 병합, 승인, 경계 요약은 변경하지 않는다.
- 파일 이동, 보고서 생성, 분류 결과 데이터 구조는 변경하지 않는다.
- 새로운 색 체계를 만들지 않고 기존 어두운 작업 패널 색과 민트 선택 표시를 재사용한다.

## 충돌 사본 처리

`lib/photo-classifier/fieldOutput.sync-conflict-20261116-022020-37M3FPY.ts`는 원본과 내용이 다르다. 원본에는 최근 반영된 씬 이름 정리, 보고서 쓰기 오류 억제, 씬 폴더 생성 실패의 항목별 기록이 있으나 충돌 사본에는 없다. 따라서 자동 삭제하지 않고 차이가 있음을 완료 보고에 남긴다.

## 검증

- 120장 씬에서 뷰어를 열어 원본 표시, 좌우 이동, 필름스트립 이동, 분할 실행을 확인한다.
- 시작·끝 행 썸네일 크기와 라벨을 확인한다.
- 현재 사진 이동과 닫기 때 Object URL이 해제되는지 테스트한다.
- 가시 영역 밖 필름스트립 항목이 파일을 읽지 않는지 테스트한다.
- 첫 사진 분할이 막히고 두 번째 이후 사진은 정확한 offset으로 기존 분할 콜백을 호출하는지 테스트한다.
- `npx tsc --noEmit`과 관련 Vitest를 실행한다.
- 실제 120장 폴더를 사용할 수 있으면 캡처를 첨부하고, 사용할 수 없으면 동일 장수의 테스트 fixture로 동작을 검증한 뒤 실제 캡처 미실시를 명시한다.
