# 개인별 사진 셀렉 로컬 폴더 가져오기 설계

작성일: 2026-11-03

## 목표

개인별 사진 셀렉의 `사진 올리기`에서 Mac Studio의 원격 디스크만 탐색하던 흐름을 확장한다. 사용자는 현재 Olivia를 연 기기의 로컬 폴더를 직접 선택할 수 있다.

- Mac Studio에서 Olivia를 열면 Mac Studio의 로컬 폴더를 선택한다.
- 노트북에서 Olivia를 열면 노트북의 로컬 폴더를 선택한다.
- 기존 Mac Studio 원격 폴더 가져오기와 RAW 매칭 경로는 유지한다.
- 원본 JPG와 RAW는 Storage에 저장하지 않고 480px 썸네일과 1600px 미리보기만 저장한다.

## 사용자 흐름

`사진 올리기` 카드에 기존 세그먼트 스타일을 재사용한 실행 위치 선택을 둔다.

1. `이 기기`가 기본 선택된다.
2. `이 기기`에서 `폴더 선택`을 누르면 브라우저가 현재 기기의 폴더 선택기를 연다.
3. 이름 폴더 또는 학교 폴더 구조를 검사하고 가져올 사진 수와 건너뛸 폴더를 표시한다.
4. `사진 올리기`를 누르면 브라우저에서 썸네일과 미리보기를 생성하고 관리자 전용 API로 전송한다.
5. `Mac Studio`를 선택하면 현재의 `PhotoSourcePicker`, 원격 작업 생성, 진행 조회를 그대로 사용한다.

Chrome 계열에서는 File System Access API의 `showDirectoryPicker`를 우선 사용한다. 이를 지원하지 않는 브라우저에서는 `webkitdirectory` 폴더 입력을 사용한다. 두 경로는 동일한 상대 경로 모델과 검사 결과를 만든다.

## UI

현재 승인된 밝은 개인별 셀렉 화면과 `PersonSelectAdmin.module.css`의 토큰을 유지한다.

- 새 색상이나 별도 탭 형태를 만들지 않는다.
- 폴더 구조 선택인 `이름 폴더 / 학교`는 현재 위치와 동작을 유지한다.
- 실행 위치 `이 기기 / Mac Studio`는 기존 알약형 세그먼트를 재사용한다.
- 한 화면의 채운 주 실행은 `사진 올리기` 하나만 유지한다.
- 선택된 로컬 폴더에는 절대 경로 대신 폴더 이름만 표시한다.
- 로컬 폴더가 선택되지 않았거나 브라우저가 폴더 접근을 지원하지 않으면 다음 행동을 설명한다.

로컬 가져오기 중에는 사진 처리 수, 완료 수, 실패 수를 한 진행 영역에 표시한다. 기존 원격 가져오기 결과의 `그룹`, `이름 미변경`, `빈 폴더`, 실패 목록 표현을 재사용한다.

## 로컬 폴더 검사

브라우저 전용 검사 모듈은 파일을 업로드하지 않고 폴더 구조와 JPG 메타데이터만 정리한다.

### 이름 폴더

- 최상위 사람 이름 폴더를 로그인 이름으로 사용한다.
- 각 사람 폴더의 `JPG원본`을 우선하고, 없으면 사람 폴더 바로 아래 JPG/JPEG를 사용한다.
- `그룹N`, `단체`는 고객 사진에서 제외하고 결과에 표시한다.
- `개인N`은 이름 미변경 폴더로 제외하고 결과에 표시한다.
- 숨김 폴더와 `Selected_RAW`는 제외한다.
- RAW 파일은 읽거나 전송하지 않는다.

### 학교 폴더

- 현재 원격 가져오기와 동일하게 `선생님프로필`과 `담임선생님`만 읽는다.
- 학생사진과 매핑되지 않은 폴더는 순회하지 않고 건너뛴 목록에만 표시한다.
- 사람 이름과 담임 반 파싱은 현재 `lib/person-select/core.ts`의 순수 함수를 재사용한다.

같은 행사와 같은 `source_rel_path`는 기존과 같이 중복 등록하지 않는다.

## 이미지 처리와 업로드

브라우저는 선택한 JPG를 디코딩하고 EXIF 방향이 반영된 출력물을 만든다.

- 썸네일: 최대 480×480, JPEG
- 미리보기: 최대 1600×1600, JPEG
- 원본보다 확대하지 않는다.
- 원본 파일명, 상대 경로, 출력 크기와 소유자 정보만 API에 전달한다.
- 원본 JPG와 RAW 바이트는 API나 Storage에 전송하지 않는다.

대량 사진에서 브라우저 메모리가 급증하지 않도록 제한된 동시성으로 한 장씩 변환하고 업로드한다. 각 이미지의 두 파생 파일이 모두 저장된 뒤 DB 행을 등록한다. 부분 실패는 성공 항목을 유지하고 파일별 오류로 보고한다. 재시도 시 이미 등록된 상대 경로는 건너뛴다.

## 서버 API와 보안

관리자 전용 로컬 가져오기 API를 추가한다. 모든 요청은 `isAdminSession`을 확인하고 행사 ID가 실제로 존재하는지 검증한다.

API는 다음 역할만 맡는다.

1. 행사, 카테고리와 기존 이미지 상대 경로 확인
2. 새 사람 생성과 행사 안에서 중복되지 않는 PIN 발급
3. 파생 이미지의 private Storage 저장
4. `person_select_images` 등록
5. 이름 폴더의 최초 가져오기라면 기존 규칙대로 행사 카테고리를 `사진`으로 설정

클라이언트가 보낸 절대 경로는 받지 않는다. 상대 경로는 NFC로 정규화하고 `..`, 절대 경로, 빈 구간과 숨김 경로를 거부한다. 소유자 이름과 카테고리는 선택한 레이아웃 규칙과 일치하는지 서버에서도 검사한다. 파일 크기, MIME 타입, 출력 픽셀 크기와 요청당 항목 수를 제한한다.

## RAW 매칭

로컬 브라우저 폴더는 운영체제 절대 경로를 안전하게 제공하지 않으므로 Mac Studio 워커가 나중에 그 원본 위치를 다시 찾을 수 없다.

- `이 기기` 가져오기는 `source_relative_path`를 만들지 않는다.
- 기존 Mac Studio 원격 가져오기는 현재처럼 원본 폴더와 레이아웃을 기록한다.
- 로컬 가져오기만 한 행사에서 RAW 매칭을 누르면 임의 경로를 추측하지 않고 `Mac Studio에서 원본 폴더를 연결해 주세요.`라고 안내한다.
- 같은 행사의 원본 폴더를 Mac Studio에서 다시 선택해 연결하는 최소 동작을 제공한다. 이 동작은 사진을 중복 업로드하지 않고 행사에 검증된 원격 원본 경로와 레이아웃만 기록한다.
- 원격 원본 연결이 끝나면 현재 `PERSON_SELECT_RAW_MATCH` 작업을 그대로 사용한다.

## 상태와 오류 처리

- 로컬과 원격 선택 상태는 서로 섞지 않는다.
- 실행 위치를 바꾸면 반대쪽 선택을 실행 대상으로 사용하지 않는다.
- 업로드 중 실행 위치나 레이아웃 변경을 막는다.
- 사용자가 폴더 선택을 취소하면 기존 선택과 결과를 유지한다.
- 파일 디코딩, 변환, Storage, DB 실패는 파일별로 표시한다.
- 세션 만료, 행사 삭제, 잘못된 폴더 구조는 업로드 시작 전에 중단한다.
- 페이지 이동 또는 취소 시 새 작업 시작을 막고 진행 중 요청의 결과가 다른 행사 상태를 덮지 않게 행사 ID와 작업 토큰을 확인한다.

## 보존 사항

- 기존 Mac Studio 다중 루트 폴더 탐색
- 기존 `PERSON_SELECT_IMPORT` 및 `PERSON_SELECT_RAW_MATCH` 워커 작업
- 이름 폴더와 학교 폴더의 분류 규칙
- PIN 발급, 고객 선택, 보정 요청, 추가 주문과 CSV 내보내기
- private Storage와 서명 URL
- 고객 공개 화면 디자인

DB 스키마는 변경하지 않는다.

## 검증

### 단위·API 테스트

- 이름 폴더의 `JPG원본`, 바로 아래 JPG, 그룹, 미명명, 빈 폴더 분류
- 학교 폴더의 매핑 대상만 포함
- NFD 경로의 NFC 정규화
- 경로 탈출과 숨김 경로 거부
- 파생 파일만 허용하고 원본·RAW 요청 거부
- 같은 상대 경로 재업로드 시 중복 없음
- 사람 생성과 PIN 중복 방지
- 부분 실패 후 재시도
- 관리자 미인증 401
- 로컬 가져오기 후 원격 원본 연결 전 RAW 매칭 차단
- 원격 가져오기 회귀 없음

### 실제 화면

- Mac Studio 브라우저에서 Mac Studio 로컬 폴더 선택
- 노트북 브라우저에서 노트북 로컬 폴더 선택
- Chrome 폴더 선택과 fallback 폴더 입력
- 이름 폴더와 학교 폴더 각 1회
- 좁은 OS 창과 넓은 독립 화면
- 업로드 진행, 실패 목록, 재시도
- Mac Studio 원격 모드와 RAW 폴더 연결 후 RAW 매칭
