# 문서 열기·고객등록 네이티브 전환 안정화 설계

작성일: 2026-09-24

## 목표

채팅에서 검색한 견적서를 후속 명령으로 열지 못하는 문제와, 견적서 승인 뒤 고객등록 과정에서 예전 `/clients` 화면이 잠깐 나타나거나 아무 창도 열리지 않는 문제를 함께 해결한다. 기존 문서 검색, 견적서, 고객관리 데이터 흐름은 유지하고 Olivia Desktop의 네이티브 앱 전환만 안정화한다.

## 확인된 원인

### 검색한 문서 열기

`search_documents`는 문서를 `quote:<uuid>` 같은 복합 ID로 반환하고 대화 컨텍스트도 이 값을 현재 문서로 저장한다. 후속 요청에서 Hermes가 `open_document` 대신 `preview_quote`를 선택하면 견적 실행기가 복합 ID를 데이터베이스 UUID로 사용해 조회가 실패한다. 운영 기록에서도 검색은 성공했지만 `preview_quote`만 실패했고 `open_document` 호출은 없었다.

### 고객등록 뒤 화면 전환

`link_new_client_to_quote`는 실제 고객 연결에 성공해도 결과에 `clientId`와 `workflowRunId`를 반환하지 않으며, 현재 UI 리졸버는 견적서 새로고침만 만든다. `link_temporary_document_client`는 두 ID를 반환하지만 대응 UI 리졸버가 없다. 또한 `/clients` 딥링크로 루트에 다시 들어왔을 때 `OliviaDesktop`의 초기 실행 가드가 이미 소비돼 있으면 새 고객 창이 열리지 않을 수 있다.

## 채택한 방식

프롬프트에만 의존하지 않고 실행 경계와 UI 액션 경계를 함께 보강한다.

1. 견적·계약·콘티 실행기가 현재 문서 ID를 사용할 때, 요청한 타입과 일치하는 `type:<uuid>` 형식이면 UUID 부분만 사용한다.
2. `open_document`는 검색 결과를 여는 전용 도구임을 설명에 명시하고, `preview_quote`는 이미 활성화된 견적서 전용임을 명시한다.
3. 견적 고객등록 결과에 실제 `clientId`와 가능한 `workflowRunId`를 포함한다.
4. 일반 견적 고객등록과 임시문서 고객등록 모두 성공하면 기존 네이티브 `customer` 앱을 해당 고객 컨텍스트로 열거나 포커스한다.
5. 루트 딥링크는 URL의 실행 요청이 달라지면 다시 처리하되, 같은 요청을 렌더마다 반복 실행하지 않는다.
6. 데스크톱 문서 리소스 카드는 네이티브 문서 열기 액션으로 연결해 채팅 명령이 실패해도 사용자가 직접 열 수 있게 한다.

## 데이터 흐름

### 채팅 문서 열기

1. `search_documents`가 복합 문서 ID를 반환한다.
2. 후속 요청이 `open_document`를 호출하면 기존 방식으로 타입과 UUID를 분리해 네이티브 견적·계약·콘티 창을 연다.
3. Hermes가 문맥상 `preview_quote`를 선택해도 공통 현재 리소스 정규화가 `quote:<uuid>`를 `<uuid>`로 바꾼 뒤 조회하므로 실패하지 않는다.
4. 성공한 `preview_quote`는 기존 `SWITCH_WORKSPACE`와 `PREVIEW_QUOTE` 액션을 그대로 사용한다.

### 고객등록

1. 고객 생성 또는 기존 고객 연결을 기존 도구가 수행한다.
2. 도구 결과가 `clientId`, `workflowRunId`, 기존 `resourceId`를 반환한다.
3. UI 리졸버가 견적 새로고침과 네이티브 고객관리 열기 액션을 생성한다.
4. Desktop에서는 `customer` 어댑터가 선택된 고객 상세를 표시한다. 독립 `/clients` 페이지는 기존 호환 경로로 남긴다.

## 오류 처리

- 타입이 다른 복합 ID는 임의로 잘라 쓰지 않고 기존 오류를 유지한다.
- 고객등록 자체가 실패하면 고객관리 창을 열지 않는다.
- 고객등록은 성공했지만 워크플로 런이 없으면 `clientId`만으로 고객 상세를 연다.
- 네이티브 앱 매핑이 불가능할 때 예전 페이지로 자동 이탈하지 않는다.

## 테스트

- `quote:<uuid>`가 견적 실행 경계에서 UUID로 정규화되는 단위 테스트
- 계약·콘티의 동일 형식과 타입 불일치 테스트
- 검색 결과 후 `open_document`가 네이티브 workspace 액션을 만드는 기존 테스트 유지
- `link_new_client_to_quote` 및 `link_temporary_document_client` 성공 결과가 고객 컨텍스트를 포함한 네이티브 앱 액션을 만드는 테스트
- 다른 URL 실행 요청은 처리하고 동일 요청은 중복 처리하지 않는 딥링크 테스트
- 데스크톱 리소스 카드 클릭 시 해당 네이티브 문서가 열리는 컴포넌트 테스트
- 전체 typecheck, test, build 실행

## 범위 밖

- 문서 검색 알고리즘 변경
- 고객관리 UI 재작성
- 견적 승인·발행 상태 머신 변경
- 모바일 셸 변경
- Hermes MCP 카탈로그 구조 변경
