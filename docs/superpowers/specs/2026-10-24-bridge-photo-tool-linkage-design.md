# Olivia Bridge 사진 도구 연결 보완 설계

작성일: 2026-10-24

## 목적

Bridge에서 선택한 폴더와 JPG 상태를 내부 사진 도구가 그대로 사용하게 한다. 이미 연결된 기능은 유지하고, 실제 점검에서 확인된 다음 네 가지 빈틈만 보완한다.

1. AI 사진 셀렉이 Bridge 폴더를 자동으로 사용하지 않는 문제
2. RAW 매칭이 Bridge 폴더를 받았는데도 폴더 선택 화면을 다시 보여주는 문제
3. 내부 셀렉 도구의 선택·별점 변경이 Bridge로 돌아오지 않는 문제
4. 내부 기능 창의 닫기 버튼이 헤더 드래그로 오인되어 클릭되지 않는 문제

## 현재 상태

- `PhotoStudioExecutionContext`에 `currentLocalFolder`, `selectedJpgNames`, `selectedJpgFiles`가 이미 있다.
- JPG 정리, 직접 사진 셀렉, 사진 분류, T컷 정리, 리사이즈, 이름변경은 `currentLocalFolder`를 이미 사용한다.
- 촬영시간 RAW 매칭도 현재 폴더를 초기 선택 폴더로 사용한다.
- 사진 보정은 `selectedJpgFiles[0]`을 초기 파일로 사용한다.
- Bridge는 선택 상태를 컨텍스트로 보내지만 컨텍스트에서 바뀐 선택을 Bridge로 다시 읽지 않는다.
- Bridge 별점은 Bridge 내부 ID 기준 상태이고 셀렉 도구가 읽은 XMP 별점은 도구 내부 상태다.
- `BridgeFloatingWindow`는 드래그 제외 대상을 `HTMLElement`로만 검사한다. 닫기 아이콘의 실제 이벤트 타깃이 `SVGElement`이면 헤더 드래그가 시작되어 클릭이 취소된다.

## 설계

### 1. 공통 폴더 세션

`PhotoStudioExecutionContext.currentLocalFolder`를 Bridge 내부 모든 사진 도구의 기본 폴더로 유지한다.

- AI 사진 셀렉은 마운트될 때 `currentLocalFolder`를 초기 폴더로 받는다.
- Bridge 안에서 열린 JPG 정리는 기존 폴더 선택 단계를 `현재 Bridge 폴더` 상태로 표시한다. 도구 안에서 폴더를 바꾸어 Bridge 화면과 도구가 서로 다른 폴더를 가리키는 동작은 제공하지 않는다.
- RAW 파일명 매칭은 Bridge 선택 JPG가 있으면 곧바로 선택 목록을 사용하고, 현재 Bridge 폴더를 JPG·RAW 기본 탐색 위치로 사용한다.
- Bridge 선택 JPG가 없더라도 현재 폴더를 다시 선택하게 하지 않는다. 현재 폴더를 자동 스캔해 매칭 대상을 고르는 화면으로 진입한다.
- RAW가 별도 위치에 있는 경우에만 기존 `RAW 폴더 선택` 보조 동작을 유지한다.
- 사진 분류, T컷, 리사이즈, 이름변경, 촬영시간 RAW 매칭, 사진 보정의 기존 연결은 변경하지 않는다.

폴더 스캔과 미리보기는 파일을 변경하지 않는 읽기 작업이다. 이동, 이름변경, 복사, 리사이즈 등 실제 파일 변경은 각 도구의 기존 미리보기·승인·실행 버튼을 그대로 거친다.

### 2. 선택 양방향 동기화

파일명 정규화 키를 사용해 Bridge 파일과 도구 파일을 연결한다.

- 앞뒤 공백 제거
- Unicode NFC 정규화
- 대소문자 무시
- 비교 목적에 맞춰 확장자를 포함하거나 basename으로 통일

Bridge에서 선택이 바뀌면 현재처럼 `selectedJpgNames`와 `selectedJpgFiles`를 갱신한다. 내부 셀렉 도구가 선택을 저장하거나 변경하면 컨텍스트의 `selectedJpgNames`를 갱신하고, Bridge는 그 값을 구독해 `selectedIds`를 갱신한다.

같은 값의 재설정은 무시해 Bridge와 도구 사이의 반복 갱신을 막는다. 현재 폴더에 없는 파일명은 조용히 선택하지 않되 기존 선택 파일이나 다른 폴더의 상태를 삭제하지 않는다.

### 3. 별점 동기화

`PhotoStudioExecutionContext`에 파일명 기준 JPG 별점 맵과 갱신 함수를 추가한다. 값은 0부터 5까지다.

- Bridge에서 숫자 0~5로 별점을 바꾸면 공통 별점 맵도 갱신한다.
- 셀렉 도구가 XMP 사이드카 또는 JPG 내장 XMP에서 별점을 읽으면 공통 별점 맵에 반영한다.
- Bridge는 공통 별점 맵을 현재 폴더의 파일 ID로 변환해 썸네일 별점과 별점 필터에 반영한다.
- 같은 파일에 Bridge에서 이미 명시적으로 매긴 별점이 있으면 도구의 늦게 도착한 자동 스캔 결과가 덮어쓰지 않는다.
- 컬러 레이블과 제외 표시는 이번 범위에서 공통 컨텍스트로 옮기지 않고 Bridge 전용 상태로 유지한다.

Bridge의 기존 폴더별 로컬 저장은 유지한다. 폴더를 다시 열었을 때 복원된 별점도 공통 별점 맵에 반영한다.

### 4. 내부 창 닫기

헤더 드래그 시작 시 이벤트 타깃을 `Element`로 검사해 SVG와 SVG 하위 경로도 버튼 내부로 판정한다. `button`, `input`, `select`, `textarea`, `a`에서 시작한 포인터 입력은 드래그를 시작하지 않는다.

닫기 버튼의 포인터 이벤트는 헤더로 전달되지 않게 하여 클릭 한 번으로 닫히게 한다. 헤더의 빈 영역과 제목 영역 드래그, 창 리사이즈는 그대로 유지한다.

## 오류 처리

- Bridge 폴더 권한이 사라지면 각 도구의 기존 폴더 접근 오류를 그대로 표시한다.
- 선택 이름이 현재 폴더 파일과 매칭되지 않으면 존재하는 파일만 반영한다.
- XMP 별점 읽기 실패는 기존처럼 해당 파일의 별점을 비워 두며, Bridge의 수동 별점을 삭제하지 않는다.
- RAW 별도 폴더가 필요한 경우 현재 안내와 선택 버튼을 유지한다.

## 검증

### 자동 테스트

- Bridge 폴더가 AI 셀렉과 RAW 매칭 기본 폴더로 전달된다.
- 선택 파일명이 양방향으로 동기화되고 동일 값 갱신이 반복되지 않는다.
- XMP 별점과 Bridge 수동 별점의 우선순위가 유지된다.
- SVG 아이콘을 직접 누른 경우에도 닫기 버튼 클릭이 실행된다.
- 헤더 빈 영역 드래그와 창 리사이즈가 계속 동작한다.
- 기존 `tests/oliviaBridge.test.ts`와 사진작업실 관련 테스트가 통과한다.

### 브라우저 확인

1. Bridge에서 폴더를 한 번 선택한다.
2. JPG 정리, 사진 셀렉, RAW 매칭, 사진 분류, T컷 정리, 리사이즈, 이름변경을 차례로 열어 같은 폴더명이 보이는지 확인한다.
3. 사진 셀렉 창에서 선택을 바꾸고 닫았을 때 Bridge 썸네일 선택이 즉시 바뀌는지 확인한다.
4. 셀렉 도구가 읽은 별점과 Bridge에서 입력한 별점이 양쪽에 일치하는지 확인한다.
5. RAW 매칭이 현재 폴더와 선택 JPG를 사용하고 중복 폴더 선택을 요구하지 않는지 확인한다.
6. 각 내부 창의 닫기 아이콘 중앙과 가장자리를 눌러 한 번에 닫히는지 확인한다.

## 범위 밖

- 컬러 레이블과 제외 표시의 다른 사진 도구 연동
- 파일 처리 알고리즘 변경
- 원격 작업 경로 변경
- 사진작업실 단독 화면의 구조 변경
- 기존 파일 이동·복사·삭제 안전 검증 변경
