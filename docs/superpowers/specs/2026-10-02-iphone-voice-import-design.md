# 아이폰 원본 음성 가져오기 설계

## 목표

Olivia 브라우저 녹음을 원본 수집 수단으로 사용하지 않는다. 아이폰 음성 메모 등에서 만든 원본 오디오를 업로드하고, Olivia는 원본 보관·전사·질문별 정리·AI 요약을 담당한다.

## 선택한 구조

1. 일반 음성기록은 `m4a`, `mp4`, `mp3`, `wav`, `webm` 파일 선택 또는 드래그 앤 드롭으로 시작한다.
2. 인터뷰는 질문지와 현장 메모를 계속 사용한다. `인터뷰 진행 시작`은 마이크를 열지 않고 질문 진행의 참고 타임라인만 시작한다.
3. 인터뷰 종료 뒤 아이폰 원본을 하나 올린다. 질문 마커는 별도 시계의 참고 정보이며, 업로드 화면에서 오디오 길이와 차이가 크면 질문별 구간을 자동 확정하지 않고 확인을 요구한다.
4. 업로드 파일은 변환·재압축하지 않고 비공개 원본으로 저장한다. 분석 실패와 원본 저장 실패는 별도 상태로 유지한다.

## 분석과 오류 처리

- 화자 분리가 필요한 파일은 diarization을 우선 시도한다.
- diarization이 지원되지 않는 경우에는 일반 전사로 한 번만 폴백한다. 폴백 결과는 `화자 구분 없음`으로 명확히 표시한다.
- API 응답 상태, OpenAI 오류 코드, 요청 단계는 서버 로그와 사용자용 오류 상태에 분리해 남긴다. API 키·원문 음성·서명 URL은 로그에 남기지 않는다.
- OpenAI의 단일 전사 요청 한도인 25MB를 넘는 파일은 원본은 저장하되, 분석 완료라고 표시하지 않는다. 안전한 서버 측 분할/변환 워커가 도입되기 전에는 임의 Blob 절단을 하지 않는다.

## 상태와 호환성

- 기존 브라우저 녹음 기록과 인터뷰 조각은 읽기·재생·AI 정리를 그대로 유지한다.
- 신규 기록은 `capture_source: iphone_import` 메타데이터를 가진다.
- 브라우저 녹음 엔진은 새 UI에서 시작하지 않는다. 기존 데이터의 복구를 위해 과거 녹음 데이터와 API 읽기 호환성을 유지한다.
- GlobalRecordingBar는 실제 마이크 녹음 상태가 아니라 업로드·분석 진행 상태를 표시한다. 유휴 상태에서는 음성 화면에서만 파일 선택 동작을 제공한다.

## 검증

- iPhone Safari 파일 선택으로 `.m4a` 원본을 올린다.
- 일반/인터뷰 각각 원본 재생, 업로드 완료, 전사 성공, diarization 폴백, 분석 실패를 확인한다.
- 25MB 초과 파일은 원본 보존과 분석 제한 안내를 확인한다.
- 기존 일반 녹음 및 다중 인터뷰 조각 상세 화면 회귀를 확인한다.
