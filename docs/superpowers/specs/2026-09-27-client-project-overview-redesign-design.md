# 고객관리 프로젝트 첫 화면 재설계

작성일: 2026-09-27  
참고 시안: `/Users/jakembpm2/Downloads/Design.pdf`의 `Main` 보드

## 목표

고객 프로젝트 상세의 첫 화면에서 반복되는 프로젝트 상태, 진행 단계, 담당자, 촬영일을 각각 한 번만 표시한다. 화면을 열자마자 현재 단계에서 해야 할 일과 다음 실행 버튼이 보이게 하며, 기존 고객관리 데이터·도구 모달·탭 기능·독립 URL 동작은 유지한다.

## 선택한 접근

새 상세 화면을 만들지 않는다. 기존 `ClientsWorkspace.tsx`의 `DetailView`가 데이터 로딩, 프로젝트 선택, 모달, 탭 상태를 계속 소유한다. `CurrentStepCard`, `ProjectWorkflowStepper`, `ClientOverviewTab`을 재구성해 `Main` 시안의 압축된 헤더, 진행 단계, 개요 영역을 만든다.

CSS만 줄이는 방식은 정보 중복과 촬영일 데이터 불일치를 해결하지 못하므로 사용하지 않는다. 상세 화면 전체 교체는 기존 기능 회귀 위험과 재사용 요구사항 때문에 제외한다.

## 구성

### 프로젝트 헤더

- 고객 아바타와 고객명을 표시한다.
- 프로젝트가 진행 중이면 `진행 중 N%`, 완료면 `완료 100%` 배지를 한 번만 표시한다.
- 담당자, 촬영일과 남은 일수, 프로젝트 기간은 한 줄에 `·`로 연결한다.
- 고객 정보 수정은 고객 정보 줄 옆의 작은 버튼으로 둔다.
- 오른쪽에는 `고객 포털`과 `더보기`만 둔다.
- 더보기 메뉴에는 포털 링크 복사, 프로젝트 수정, 프로젝트 생성, 고객 삭제를 둔다.
- 기존 헤더의 빠른 문서 작성 버튼, 별도 프로젝트 상태, 중복 촬영일은 제거한다.

### 진행 단계

- `ProjectWorkflowStepper`는 7개 상위 단계를 가로 pill로 표시한다.
- 완료 단계는 녹색 계열, 현재 단계는 주황색, 예정 단계는 중립색으로 표시한다.
- 기존 원형 번호, 연결선, 별도 진행률 막대는 제거한다.
- 오른쪽의 `전체 과정 →`는 기존 진행 상세 모달을 연다.
- 단계 클릭 시 기존 `handlePhaseClick` 동작을 그대로 사용한다.

### 개요 왼쪽 영역

왼쪽 영역은 전체 너비의 7/12을 사용한다.

1. `CurrentStepCard`를 `지금 할 일` 카드로 바꾼다.
   - 제목과 설명은 기존 `STEP_INFO` 및 워크플로우 단계 이름을 사용한다.
   - 단계 대표 동작은 기존 `buildStepAppLink`, 도구 모달, 잔금 확인 동작을 재사용한다.
   - 버튼은 주 동작과 참고 동작을 합쳐 최대 2개다.
   - 화면에서 유일한 주황색 버튼은 이 카드의 주 동작이다.
2. 문서 현황 카드는 견적서, 계약서, 촬영 콘티를 한 줄씩 표시한다.
   - 문서가 있으면 상태와 날짜를 표시하고 기존 문서 열기 경로를 사용한다.
   - 현재 만들 수 있는 문서가 없으면 점선 행과 `만들기` 버튼을 표시한다.
   - 아직 순서가 아닌 문서는 회색 조건 문구를 표시한다.

### 개요 오른쪽 영역

오른쪽 영역은 전체 너비의 5/12을 사용한다.

- `촬영까지` 카드는 `workflow_runs.shoot_date`를 기준 촬영일로 표시한다.
- 같은 날짜의 캘린더 일정이 없으면 `캘린더에 등록` 버튼을 표시한다.
- 캘린더 일정이 있으면 그 일정 정보를 보여주며 등록 버튼을 중복 표시하지 않는다.
- `shoot_date`와 캘린더 일정이 모두 없을 때만 `예정된 일정이 없습니다`를 표시한다.
- 촬영일이 있으면 촬영일까지 남은 일수와 콘티 권장 마감일을 계산해 표시한다.
- 메모는 기존 고객 메모 PATCH 경로와 편집 동작을 유지한다.
- 갤러리, 일정, 보정 요청, 활동 기록, 고객 포털, 프로젝트 설정은 2열 링크 묶음으로 표시한다.

## 기존 탭과 기능 보존

- 9개 탭의 본문 컴포넌트와 상태는 삭제하지 않는다.
- 첫 화면에서는 탭바를 제거하고 개요의 버튼과 링크가 `activeTab`을 전환해 같은 콘텐츠를 연다.
- 하위 화면에는 현재 위치와 개요로 돌아가는 진입점을 제공한다.
- 고객 정보 편집은 기존 `InfoPanel`을 사용한다.
- 프로젝트 편집은 기존 `EditPcrmProjectDialog`를 사용한다.
- 문서 생성은 기존 견적·계약·콘티 도구 모달을 사용한다.
- `/clients` 독립 URL과 데스크톱 창은 같은 컴포넌트와 기능을 유지한다.

## 이름 중복 방지

공용 함수가 고객명과 프로젝트명을 정규화해 미션 제목을 만든다.

- 프로젝트명이 고객명과 같거나 고객명으로 시작하면 프로젝트명만 반환한다.
- 그렇지 않으면 `고객명 프로젝트명`을 반환한다.
- 빈 값에는 기존의 안전한 대체 문구를 사용한다.
- `ActiveMissionBar`와 고객 상세에서 같은 함수를 사용한다.

## 반응형과 스크롤

- 넓은 화면은 7/12 + 5/12의 두 열이다.
- 좁은 창은 한 열로 쌓이며 가로 스크롤을 만들지 않는다.
- 기존 고객관리 창의 고정 검색/등록 영역과 본문 세로 스크롤 구조는 유지한다.
- 절반 높이의 창에서도 압축 헤더, 진행 단계, `지금 할 일` 카드가 첫 화면에 들어오도록 세로 여백을 제한한다.

## 오류 처리

- 캘린더 조회 실패는 고객 상세 전체를 실패시키지 않는다. 촬영일은 `shoot_date`로 계속 표시한다.
- 캘린더 등록 실패는 해당 버튼 근처 또는 기존 알림 방식으로 정확히 알린다.
- 문서나 프로젝트가 없으면 실행 불가능한 버튼을 만들지 않고 조건 문구를 표시한다.

## 테스트

- 고객명과 프로젝트명이 모두 `A`일 때 제목은 `A`다.
- 프로젝트명이 `A 브랜드 촬영`이고 고객명이 `A`일 때 제목은 `A 브랜드 촬영`이다.
- `shoot_date`가 있고 캘린더 일정이 없으면 촬영일과 `캘린더에 등록`이 보인다.
- `shoot_date`와 캘린더 일정이 모두 없을 때만 빈 일정 문구가 보인다.
- 현재 단계명과 진행 상태가 첫 화면에서 각각 한 번만 렌더된다.
- 헤더의 주요 버튼은 고객 포털과 더보기 두 개다.
- 개요의 주황색 주 동작은 한 개다.
- 기존 도구 모달, 고객 정보 편집, 프로젝트 편집, 상세 콘텐츠 진입이 유지된다.
- 좁은 창에서 본문 세로 스크롤이 가능하고 가로 스크롤은 생기지 않는다.
