# Hermes 도구 실행 후 타임아웃 복구 설계

작성일: 2026-09-27

## 문제

Hermes가 쓰기 도구를 성공적으로 실행한 뒤 최종 자연어 응답을 만들다가 전체 처리 제한에 걸리면, Olivia는 실제 저장 결과를 잃고 오류만 표시한다. 사용자가 `다시 시도`를 누르면 같은 쓰기 작업이 다시 실행된다.

2026-09-27 운영 사고에서는 `1989 청담스시` 견적이 실제로 저장됐지만 화면에는 Hermes 전체 처리 시간 초과가 표시됐고, 재시도로 동일 견적이 네 번 생성됐다.

## 목표

- 도구 실행이 검증된 뒤 발생한 Hermes 타임아웃은 실패가 아니라 실제 도구 결과로 완료한다.
- 동일 대화에서 동일한 견적 생성 요청이 짧은 시간 안에 재전송돼도 새 행을 만들지 않는다.
- 도구가 시작되지 않은 Hermes 장애에는 기존 legacy 폴백을 유지한다.
- 실행 여부를 확정할 수 없는 경우에는 반대 작업이나 중복 쓰기를 시도하지 않는다.

## 선택한 접근

### 1. 검증된 Tool audit로 타임아웃 복구

`runHermesChat()`이 스트림 타임아웃을 처리할 때 `consumeHermesToolCalls(requestId)`의 결과를 먼저 확인한다.

- 성공 또는 실패로 끝난 audit가 있으면 해당 audit를 `HermesToolCallRecord`로 복원한다.
- 성공한 mutation은 `verification.persisted === true` 또는 이에 준하는 기존 검증 결과를 그대로 사용한다.
- Hermes 자연어가 비어 있으면 도구 결과의 `summary` 또는 기존 결과 렌더러로 최종 문장을 만든다.
- 복구된 결과는 정상 `HermesChatResult`로 반환해 기존 `runHermesTurn()`의 UI action, resource card, 메시지 저장 경로를 그대로 탄다.
- `[HERMES TOOL RESULT RECOVERY]` 구조화 로그에 requestId, timeout phase, 도구명과 성공 여부만 남긴다. 사용자 원문과 개인정보는 기록하지 않는다.

도구 진행 이벤트만 있고 완료 audit가 없는 경우에는 실행 성공으로 간주하지 않는다. 중복 mutation 위험 때문에 legacy 자동 재실행도 하지 않는다.

### 2. `create_quote` 단기 멱등성

견적 생성 시 대화 ID, 정규화한 사용자 원문, 실제 생성할 canonical 견적 데이터를 조합해 생성 지문을 만든다.

- 지문은 `form_state` 안의 Olivia 내부 필드에 저장한다. 새 DB 컬럼은 추가하지 않는다.
- 같은 지문의 견적이 같은 대화에서 최근 10분 이내 생성됐다면 새 행을 만들지 않고 기존 견적을 반환한다.
- 기존 견적에 임시문서 연결이 누락됐다면 기존 등록 함수를 다시 호출해 연결만 복구한다.
- 10분이 지난 새 요청은 정상적으로 새 견적을 만들 수 있다.
- Hermes가 한 턴에서 같은 도구를 반복 호출하거나, 브라우저 재시도·네트워크 단절로 같은 요청이 재전송되는 경우를 모두 막는다.

Hermes 실행 컨텍스트에는 현재 대화 ID를 내부 실행 정보로 전달한다. 모델 입력이나 공개 Tool schema에는 추가하지 않는다.

### 3. 기존 폴백 규칙 유지

- 연결 실패, 첫 이벤트 타임아웃처럼 도구 실행 흔적이 전혀 없는 경우: 기존 legacy 폴백.
- 검증 완료 audit가 있는 경우: audit 결과로 정상 완료.
- 도구 시작 흔적은 있으나 완료 audit가 없는 경우: 불확실 상태로 종료하고 자동 재실행 금지.

단순히 Hermes 전체 제한 시간을 늘리거나 견적 요청 전체를 legacy로 우회하지 않는다.

## 데이터 흐름

1. 사용자가 견적 생성을 요청한다.
2. Hermes가 Olivia MCP `create_quote`를 호출한다.
3. Olivia가 견적과 임시문서를 저장하고 Tool audit를 기록한다.
4. Hermes가 제시간에 끝나면 기존 정상 응답 경로를 사용한다.
5. Hermes가 최종 문장 생성 중 타임아웃되면 Tool audit를 복구한다.
6. Olivia가 검증된 저장 결과로 완료 문장, 리소스 카드와 컨텍스트를 보낸다.
7. 동일 요청이 다시 들어와도 생성 지문이 일치하면 기존 견적을 반환한다.

## 테스트

- `create_quote` 성공 audit 뒤 SSE가 닫히지 않아 total timeout이 발생해도 성공 결과를 반환한다.
- 복구 결과에서 Tool result callback과 resource metadata가 유지된다.
- audit가 없는 total timeout은 성공으로 위장하지 않는다.
- 완료되지 않은 audit 상태에서는 legacy mutation 재실행을 하지 않는다.
- 같은 대화·같은 요청·같은 견적 데이터로 10분 내 두 번 호출하면 견적 행이 한 개다.
- 다른 대화, 다른 요청 데이터 또는 10분 이후 호출은 새 견적을 만들 수 있다.
- 기존 Hermes timeout, Tool verification, quote creation 테스트를 모두 유지한다.

## 범위 밖

이미 중복 생성된 견적 네 건의 삭제는 데이터 삭제이므로 이 패치에서 자동 수행하지 않는다. 사용자가 별도로 대상을 확인하고 승인한 뒤 정리한다.
