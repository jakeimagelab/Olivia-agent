# Bridge Scene 계획 → 사진 분류 연결 설계

작성일: 2026-10-25

## 1. 목적

Olivia Bridge의 Scene 사전 분석 결과를 사용자가 승인했을 때 같은 폴더를 사진 분류 도구에서 다시 분석하지 않는다. 승인한 계획을 기존 사진 분류의 Scene 검토 단계에 그대로 적용하고, 사용자는 기존 이름 변경·합치기·나누기·최종 파일 정리 흐름을 이어서 사용한다.

현재 `승인하고 분류 실행` 버튼은 사진 분류 도구만 열고 분석 결과를 전달하지 않는다. 이 설계의 완료 기준은 Bridge에서 확인한 Scene 수와 경계가 사진 분류 도구의 검토 화면에 동일하게 나타나는 것이다.

## 2. 범위

### 포함

- Bridge 정밀 Scene 분석 결과를 재사용할 수 있는 런타임 계획 데이터 생성
- Bridge와 사진 분류 사이의 일회성 계획 전달
- 현재 폴더와 계획 파일의 유효성 검사
- 사진 분류의 기존 Scene 검토 단계 초기화
- 적용 결과와 실패 원인을 화면에 명확히 표시
- 기존 Scene 편집과 최종 파일 정리 기능 재사용

### 제외

- Bridge Scene 검토 창 안에서 경계 합치기·나누기 기능 추가
- 계획의 서버 저장, 프로젝트 저장, XMP 기록 또는 브라우저 새로고침 복원
- Mac Studio/NAS 원격 Bridge 지원
- 분류 알고리즘, AI 이름 추천, RAW 매칭 규칙 변경
- Bridge 전체 색상 체계 개편

Bridge 안에는 새로운 편집기를 만들지 않는다. 계획을 적용한 뒤 기존 사진 분류 화면에서 이미 제공하는 편집 기능을 사용한다.

## 3. 검토한 접근 방식

### A. 컴포넌트 prop으로 직접 전달

`OliviaBridgeWorkspace`에서 `PhotoWorkspaceEmbeddedTool`을 거쳐 `PhotoSortingWorkspace`까지 계획을 prop으로 전달한다. 변경량은 작지만 도구가 재마운트되거나 다른 진입점이 추가되면 계획 수명과 소비 시점을 관리하기 어렵다.

### B. 공유 실행 컨텍스트의 일회성 계획 사용 — 채택

`PhotoStudioExecutionContext`가 현재 폴더·선택·별점과 함께 Bridge 분류 계획을 보관한다. Bridge가 승인 시 계획을 등록하고, 사진 분류가 계획을 한 번 적용한 뒤 소비 상태로 바꾼다. 현재 작업 폴더가 바뀌면 계획도 함께 폐기한다.

기존 Bridge 도구 연결 방식과 일치하고, 도구 마운트 순서에 덜 민감하며, 영구 저장 범위를 불필요하게 넓히지 않는다.

### C. 프로젝트/XMP에 계획 영구 저장

브라우저 재시작 이후에도 복원할 수 있지만 프로젝트 모델, 동기화 충돌, XMP 쓰기 정책까지 함께 결정해야 한다. 이번 기능의 핵심인 분석 중복 제거보다 범위가 크므로 후속 과제로 둔다.

## 4. 데이터 계약

`lib/photo-bridge`에 Bridge 분석 결과와 분류 전달 계획을 명시하는 타입과 순수 변환 함수를 둔다.

계획은 다음 정보를 가진다.

- 계획 버전과 고유 ID
- 생성 시각
- 원본 폴더 키와 폴더명
- 분석에 사용한 `FileSystemDirectoryHandle`
- 촬영 시각순으로 정렬된 JPG 항목
  - 파일명, 크기, 수정 시각
  - 파일·파일 핸들
  - 분석에서 확정한 촬영 시각과 그 출처
  - 재사용 가능한 시각 특징값
- 안정화된 Scene 경계 결정 목록
- Bridge 검토 창에 표시하는 Scene 범위와 `needsReview` 상태

이 계획은 `File`과 파일 핸들을 포함하므로 직렬화하지 않는다. 현재 브라우저 런타임에서만 유효하다. 새로고침 후에는 기존 사진 분류의 정상 폴더 선택 흐름으로 돌아간다.

`analyzeBridgeScenes`는 Scene 배열만 반환하지 않고, 정렬 파일·특징값·경계·표시용 Scene을 포함한 분석 결과를 반환한다. Bridge UI는 그중 표시용 Scene을 사용하고, 승인 시 전체 결과를 계획으로 변환한다.

## 5. 데이터 흐름

1. Bridge가 현재 폴더의 JPG를 촬영 시각순으로 정렬하고 특징 추출과 경계 안정화를 수행한다.
2. 분석 결과를 Bridge 상태에 보관하고 Scene 검토 창에 요약한다.
3. 사용자가 `계획 적용하고 Scene 검토`를 누른다.
4. Bridge가 현재 폴더와 분석 결과로 `BridgeClassificationPlan`을 만들고 공유 실행 컨텍스트에 등록한다.
5. Bridge가 기존 임베디드 사진 분류 도구를 연다.
6. 사진 분류가 아직 소비하지 않은 계획을 발견하면 폴더와 파일 서명을 검증한다.
7. 검증에 성공하면 기존 `SceneFile`과 `FieldScene` 구조로 변환하고 다음 상태를 초기화한다.
   - 현장 촬영 모드
   - Scene 경계와 Scene 목록
   - JPG/RAW 개수와 RAW 핸들
   - `WAITING_REVIEW` 작업 상태
   - Scene 검토 단계
8. 사용자는 기존 화면에서 이름 변경·합치기·나누기를 수행하고, 기존 최종 정리 동작으로 파일 변경을 승인한다.
9. 적용이 끝난 계획은 같은 컴포넌트 마운트에서 다시 초기화되지 않도록 소비 처리한다.

계획 적용 경로에서는 `handleFieldSort`와 폴더 사전 분석을 자동 재실행하지 않는다. 사용자가 명시적으로 재분석을 선택할 때만 기존 엔진을 다시 실행한다.

## 6. 컴포넌트 책임

### Bridge 분석 모듈

- 정렬 파일, 특징값, 안정화된 경계, 표시용 Scene을 하나의 결과로 반환한다.
- UI 상태나 React 컨텍스트를 알지 않는다.
- 분류 계획 변환과 파일 서명 검증을 순수 함수로 제공한다.

### `OliviaBridgeWorkspace`

- 분석 진행·완료·실패 상태를 표시한다.
- 완료된 최신 분석 결과만 승인할 수 있게 한다.
- 승인 시 계획을 등록한 뒤 사진 분류 도구를 연다.
- 분석 뒤 폴더 내용이나 폴더 위치가 바뀌면 기존 계획을 승인하지 않는다.

### `PhotoStudioExecutionContext`

- 보류 중인 Bridge 분류 계획과 등록·소비·폐기 함수를 제공한다.
- 소비 함수는 내부 ref의 현재 계획을 반환하는 동시에 비워 React Strict Mode 재실행에서도 같은 계획을 두 번 내주지 않는다.
- 현재 로컬 폴더가 바뀌면 계획을 폐기한다.
- 계획을 localStorage나 서버에 쓰지 않는다.

### `PhotoSortingWorkspace`

- Bridge 계획을 적용할 수 있는 유일한 소비자다.
- 계획을 기존 분류 상태로 변환하되 기존 Scene 검토와 파일 정리 구현은 변경하지 않는다.
- 계획 적용 전 폴더와 파일을 검증한다.
- 적용 성공 시 중복 분석을 건너뛰고 Scene 검토 단계로 이동한다.
- 적용 실패 시 파일 작업을 하지 않고 설정 단계와 오류 안내를 유지한다.

## 7. UI와 상호작용

Bridge는 사진을 판단하는 화면이므로 기존 중성 다크 작업 패널을 유지한다. 새 탭이나 별도 마법사는 추가하지 않는다.

- Scene 검토 창의 채운 주 실행 버튼은 하나만 둔다.
- 버튼 이름은 실제 동작을 반영해 `계획 적용하고 Scene 검토`로 바꾼다.
- 분석 중, 분석 실패, JPG 없음 상태에서는 버튼을 비활성화하고 이유를 한 줄로 표시한다.
- 경계 확인 필요 수는 경고 정보이지만 승인을 막지 않는다. 사진 분류의 기존 편집 기능으로 보정할 수 있기 때문이다.
- 사진 분류 화면 상단에는 `Bridge 계획 적용됨 · Scene N개 · JPG N장` 상태 안내를 한 곳에 표시한다.
- 안내 배너는 기존 어두운 패널 토큰과 공통 상태 표현을 재사용한다.
- 최종 파일 정리 전에는 파일 이동·이름 변경·폴더 생성이 일어나지 않는다.

탭 단계는 기존 작업실 1단계 탭과 사진 분류 내부 2단계 흐름을 유지한다. 세 번째 탭 스타일을 만들지 않는다. 사진 분류의 기존 최종 실행 버튼이 해당 화면의 유일한 채운 CTA다.

## 8. 유효성 검사와 오류 처리

계획은 전부 적용하거나 전부 거부한다. 일부 Scene만 적용하지 않는다.

다음 경우 계획을 거부한다.

- 현재 폴더가 계획의 원본 폴더와 다름
- 파일이 삭제되거나 새 JPG가 추가됨
- 같은 이름의 파일 크기 또는 수정 시각이 달라짐
- 파일 핸들 권한을 잃음
- Scene 인덱스가 파일 범위를 벗어나거나 Scene 범위가 겹침
- Scene 범위가 정렬된 JPG 전체를 순서대로 덮지 않음
- 계획 버전을 지원하지 않음

거부 시 파일 시스템을 변경하지 않고 계획을 폐기한다. 사진 분류 설정 화면에 `Bridge 분석 뒤 폴더 내용이 변경되었습니다. 현재 폴더를 다시 분석해 주세요.`와 같이 복구 방법을 포함한 오류를 표시한다. 기존 폴더 선택 및 재분류 기능은 계속 사용할 수 있다.

RAW 파일은 Scene 계획의 입력이 아니지만 최종 정리에 필요하므로, 계획 적용 시 현재 폴더에서 다시 수집한다. RAW가 0개인 폴더는 정상이다. 폴더 열거 또는 파일 핸들 접근 자체가 실패할 때만 계획 적용 실패로 처리하고 구체적인 권한 오류를 표시한다.

## 9. 기존 기능 보존

다음 동작은 변경하지 않는다.

- Bridge 폴더 탐색, 선택, 별점, 색상 라벨, 제외 표시
- Bridge 자동 Scene 분석 알고리즘의 판단 기준
- 사진 분류의 이름 변경·Scene 합치기·Scene 나누기
- AI 이름 추천과 진료과 로직
- 최종 파일 정리의 승인 및 파일 처리 규칙
- JPG 셀렉, RAW 매칭, 리사이즈, 이름 변경, 보정 도구 연결
- 로컬/원격 사진 분류의 기존 분기

Bridge 계획은 로컬 직접 실행에서만 사용한다. 원격 실행에는 계획을 전달하지 않는다.

## 10. 테스트 전략

### 단위 테스트

- 분석 결과가 정렬 파일·경계·표시 Scene을 일관되게 반환하는지 확인
- 계획 변환이 Scene 범위와 파일 순서를 보존하는지 확인
- 파일 추가·삭제·변경, 잘못된 범위, 지원하지 않는 버전을 거부하는지 확인
- 같은 계획을 두 번 소비해도 Scene 상태를 두 번 초기화하지 않는지 확인
- 현재 폴더 변경 시 보류 계획이 폐기되는지 확인

### 컴포넌트/통합 테스트

- Bridge 승인 버튼이 계획을 등록하고 사진 분류 도구를 여는지 확인
- 사진 분류가 계획을 받아 `WAITING_REVIEW`와 Scene 검토 단계로 진입하는지 확인
- 계획 적용 경로에서 기존 분류 분석 함수가 자동 호출되지 않는지 확인
- 적용된 Scene 수, JPG 수, 확인 필요 수가 Bridge 결과와 같은지 확인
- 실패 시 파일 작업 없이 오류와 복구 방법을 표시하는지 확인

### 회귀 및 화면 검증

- 기존 Bridge 테스트와 사진 분류 핵심 테스트 실행
- 타입 검사와 린트 실행
- 넓은 화면과 좁은 창에서 Bridge 검토 창, 분류 적용 안내, Scene 검토 CTA 확인
- 실제 File System Access가 가능한 Chromium 환경에서 임시 사진 폴더로 승인부터 최종 정리 직전까지 확인

## 11. 인수 조건

- Bridge 분석 결과를 승인하면 사진 분류가 같은 Scene 구성으로 바로 열린다.
- 승인 뒤 같은 JPG를 대상으로 특징 추출과 Scene 경계 분석을 자동 반복하지 않는다.
- 분류 화면에서 기존 Scene 편집 기능을 모두 사용할 수 있다.
- 최종 정리를 별도로 승인하기 전에는 파일 시스템이 바뀌지 않는다.
- 원본 폴더가 달라졌거나 파일이 변경되면 계획을 적용하지 않고 복구 방법을 표시한다.
- 폴더 변경과 계획 소비가 다른 사진 도구의 공유 상태를 손상하지 않는다.
- 새 탭, 새 전역 색상 토큰, 두 번째 채운 CTA를 만들지 않는다.
