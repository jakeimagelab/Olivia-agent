# 개인별 사진선택 모바일 즉시 해제 설계

작성일: 2026-11-10

## 문제

개인별 이름·PIN으로 접속하는 모바일 사진선택에서 `선택 해제`를 누르면 서버의 DELETE 요청과 전체 선택 데이터 재조회가 끝난 뒤에야 체크와 선택 장수가 사라진다. 모바일 네트워크에서는 사용자가 버튼이 눌리지 않았다고 느낄 정도로 지연된다.

## 목표

선택 해제는 화면에 즉시 반영하고 서버 저장은 뒤에서 완료한다. 저장이 실패하면 기존 선택을 정확히 복구한다.

## 범위

- 대상: `components/person-select/PersonSelectPublic.tsx`의 모바일 `PersonSelectCategory`.
- 이름·PIN 로그인, 선택 API, DB 구조, 최종 제출, 보정 요청, 데스크톱 `PcWorkspace` 동작은 변경하지 않는다.
- 선택 추가 동작은 현재 방식을 유지하고, 보고된 선택 해제 지연만 최소 수정한다.

## 동작

1. 사용자가 `선택 해제`를 누르면 해당 이미지 ID를 낙관적 해제 집합에 즉시 추가한다.
2. 체크 표시, 선택 장수, 완료 조건은 서버 데이터에서 낙관적 해제 집합을 제외해 계산한다.
3. 해당 사진의 해제 저장이 진행되는 동안 같은 사진에 대한 선택 버튼을 비활성화하고 `저장 중`을 표시한다.
4. DELETE 성공 후 기존 `load({ silent: true })`로 서버 데이터를 재조회한다.
5. 재조회가 끝나면 낙관적 해제 표시를 제거한다. 서버 데이터에는 이미 해제가 반영돼 있으므로 화면 상태는 유지된다.
6. DELETE 또는 재조회가 실패하면 낙관적 해제를 제거해 원래 선택을 복원하고 기존 오류 영역에 저장 실패를 표시한다.

## 동시성 보호

- 사진 ID별 진행 상태를 사용해 같은 사진의 중복 해제 요청을 막는다.
- 컴포넌트가 사라진 뒤 완료된 요청이 현재 화면을 변경하지 않도록 요청 세대 또는 활성 상태를 확인한다.
- 다른 사진의 선택 상태는 변경하지 않는다.

## 검증

- 선택된 사진을 해제하면 네트워크 응답 전에 체크와 선택 장수가 즉시 감소한다.
- 요청 중 같은 사진의 버튼은 중복 실행되지 않는다.
- DELETE 성공 후 서버 재조회 결과와 화면이 일치한다.
- DELETE 실패 시 선택이 복구되고 오류가 표시된다.
- 다른 사진과 다른 카테고리의 선택은 유지된다.
- 데스크톱 개인별 사진선택과 기존 API 계약은 유지된다.
- 관련 Vitest와 `npx tsc --noEmit`을 실행한다.
