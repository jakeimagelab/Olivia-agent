# PCRM 2차 고객 협업 구축 설계

작성일: 2026-07-25

## 목표

PCRM 1차 프로젝트 포털 위에 고객과 관리자가 실제로 자료를 확인하고 준비 정보를 제출하며 장면별 피드백과 문의를 주고받는 협업 흐름을 완성한다.

## 범위

1. 견적·계약·자료의 열람, 승인, 수정 요청
2. 촬영 준비 항목 활성화, 고객 입력, 제출, 관리자 확인
3. 콘티 장면별 승인, 의견, 수정 요청, 관리자 답변
4. 프로젝트 단위 문의와 답변
5. 공통 첨부파일
6. 모든 행동의 활동 기록과 관리자 대기 현황 반영

전자서명 공급자 연동과 실시간 채팅은 범위에서 제외한다.

## 데이터 구조

### 기존 테이블 재사용

`pcrm_publications`를 자료 공개와 고객 승인 상태의 원본으로 사용한다.

- `published`: 고객 확인 가능
- `viewed`: 고객 열람
- `revision_requested`: 수정 요청
- `approved`: 고객 승인
- `completed`: 관리자 완료
- `archived`: 공개 취소

계약 고객 승인과 전자서명 완료는 분리한다. 이번 단계의 승인은 내용 확인이며 기존 계약 테이블의 서명 상태를 임의로 변경하지 않는다.

### 신규 테이블

- `pcrm_preparation_items`
  - 프로젝트별 준비 항목
  - 활성/필수/정렬, 입력 유형, 고객 입력값, 상태
  - 제출 및 관리자 확인 시간
- `pcrm_conti_scene_feedback`
  - 콘티 원본과 장면 키 연결
  - 승인, 의견, 수정 요청, 관리자 답변
- `pcrm_inquiries`
  - 프로젝트 문의 제목, 카테고리, 상태
- `pcrm_inquiry_messages`
  - 고객과 관리자 답변, 읽음 시간
- `pcrm_attachments`
  - 준비 항목, 콘티 피드백, 문의의 공통 첨부 메타데이터

모든 테이블은 프로젝트와 고객 ID를 함께 저장하고, 서버는 포털 토큰 범위와 일치하는지 검증한다.

## API

### 고객 자료 액션

- `POST /api/client-portal/publications/[id]/view`
- `POST /api/client-portal/publications/[id]/approve`
- `POST /api/client-portal/publications/[id]/request-revision`

승인과 수정 요청은 현재 상태를 서버에서 재확인한다. 승인된 항목은 재승인할 수 없다.

### 촬영 준비

- 관리자: `/api/admin/pcrm/preparation`
- 고객: `/api/client-portal/preparation`
- 고객 제출: `/api/client-portal/preparation/submit`
- 관리자 확인: `/api/admin/pcrm/preparation/confirm`

관리자가 항목을 활성화하고 고객은 활성 항목만 조회한다. 제출 후에는 관리자 확인 전까지 수정 가능하며, 관리자 확인 후 수정 시 재제출 상태가 된다.

### 콘티 피드백

- 고객: `/api/client-portal/conti-feedback`
- 관리자: `/api/admin/pcrm/conti-feedback`

장면 키는 콘티 ID와 안정적인 scene key를 함께 사용한다. 장면 배열 순서가 바뀌어도 기존 피드백이 엉뚱한 장면에 붙지 않도록 명시적 ID가 없으면 콘텐츠 기반 키를 생성한다.

### 문의

- 고객: `/api/client-portal/inquiries`
- 관리자: `/api/admin/pcrm/inquiries`
- 메시지: 각 문의의 `/messages`

문의 상태는 `open`, `answered`, `closed`만 사용한다. 실시간 채팅이나 타이핑 표시는 만들지 않는다.

## UI

### 고객

- 문서함에서 공개 자료를 열람하고 승인 또는 수정 요청
- 촬영 준비에서 항목별 입력 후 한 번에 제출
- 콘티에서 장면별 승인과 의견
- 문의 목록, 새 문의, 답변 타임라인
- 제출 중 버튼 비활성화와 인라인 오류

### 관리자

- 고객 상세의 승인 대기와 수정 요청
- 촬영 준비 항목 설정 및 제출 확인
- 장면별 고객 피드백과 관리자 답변
- 문의 대기 목록과 답변

기존 고객 상세의 기능을 제거하지 않고 PCRM 협업 패널을 추가한다.

## 보안과 중복 방지

- 고객 API는 토큰으로 고객과 프로젝트를 결정한다.
- 클라이언트가 보낸 `client_id`, `workflow_run_id`를 신뢰하지 않는다.
- 관리자 API는 기존 관리자 인증 경계를 유지한다.
- 첨부파일은 서버가 발급한 제한된 업로드 세션만 사용한다.
- 승인, 제출, 답변 버튼은 처리 중 비활성화한다.
- 상태 변경 전 현재 상태를 다시 확인한다.
- 모든 주요 변경은 `pcrm_activity_logs`에 기록한다.

## 오류와 빈 상태

- 공개된 문서가 없습니다.
- 준비 요청된 항목이 없습니다.
- 등록된 콘티 피드백이 없습니다.
- 문의 내역이 없습니다.

기술 오류를 그대로 노출하지 않고 사용자가 이해할 수 있는 문구를 반환한다.

## 검증

- 프로젝트 A 토큰으로 프로젝트 B 협업 데이터 접근 차단
- 같은 승인 요청 중복 실행 차단
- 준비 항목 제출과 관리자 확인
- 장면별 승인과 수정 요청 저장
- 고객 문의와 관리자 답변
- 활동 기록 생성
- TypeScript, 전체 테스트, 프로덕션 빌드

## 대표자 결정이 필요한 후속 기능

- 전자서명 공급자와 법적 서명 방식
- 실제 알림 발송 채널과 비용 정책
- 고객 파일의 장기 보관 기간
- 문의 SLA 또는 자동 담당자 배정 정책
