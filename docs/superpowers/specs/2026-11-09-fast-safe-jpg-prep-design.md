# 빠르고 안전한 JPG 정리 설계

## 목표

JPG 정리의 충돌 방지, RAW 무변경, 원본 보존 검증을 유지하면서 실행 위치에 맞는 가장 빠른 파일 이동 방식을 사용한다. NAS와 Mac Studio에서 브라우저 복사·삭제 경로가 선택되지 않게 하고, 노트북 로컬 폴더에서는 브라우저 제약 안에서 안전하게 동작한다.

## 실행 경로

### Mac Studio / NAS

- `PHOTO_PREPARE_SOURCE` 원격 작업을 사용한다.
- Mac Studio 워커가 프로젝트 폴더와 `JPG전체`가 같은 볼륨인지 검증한다.
- 각 JPG는 Node 파일시스템의 `rename()`으로 이동한다.
- `EXDEV`가 발생하면 복사로 자동 전환하지 않고 안전한 오류를 반환한다.
- 원본 스냅샷, 대상 충돌, RAW 스냅샷, 이동 후 수량·용량 검증을 유지한다.
- 유휴 워커의 최대 폴링 간격을 60초에서 10초로 줄여 시작 지연을 제한한다.

### 노트북 로컬

- 브라우저 `FileSystemFileHandle.move()`를 먼저 사용한다.
- 네이티브 이동을 지원하지 않으면 스트리밍 복사, 목적지 크기 검증, 원본 삭제 순서로 처리한다.
- 파일 전체를 `arrayBuffer()`로 메모리에 올리지 않는다.
- 목적지 파일 목록을 사전에 한 번 색인하여 파일별 반복 조회를 줄인다.
- fallback 작업은 제한된 동시성으로 실행하되, 같은 목적지와 중단·오류 처리가 섞이지 않도록 한다.

## 안전 규칙

- 기존 대상 파일을 덮어쓰지 않는다.
- 같은 이름이면서 크기 또는 수정 시각이 다른 파일은 충돌로 남긴다.
- 복사 fallback은 쓰기 완료 및 크기 검증 전 원본을 삭제하지 않는다.
- 검증 실패 시 새 대상 파일을 제거하고 원본을 유지한다.
- RAW는 조회만 하며 이동·복사·삭제하지 않는다.
- 중단 후 다시 실행하면 완료된 파일은 건너뛰고 남은 파일만 처리한다.
- Mac Studio/NAS 경로에서 브라우저 로컬 fallback으로 조용히 전환하지 않는다.

## 오류와 상태

- 네이티브 이동 실패 원인을 보존하고, fallback 사용 여부를 내부 결과에 기록한다.
- 원격 작업은 큐 등록, 워커 대기, 실행, 검증 상태를 기존 작업 상태 표시 경로로 보고한다.
- 파일 충돌과 저장장치 간 이동(`EXDEV`)은 일반 속도 저하가 아니라 확인이 필요한 오류로 표시한다.

## 검증

- 로컬 네이티브 이동과 스트리밍 fallback 단위 테스트.
- 복사 실패·크기 불일치에서 원본 유지 및 대상 정리 테스트.
- 동명 파일, RAW 무변경, 중단 후 재실행 테스트.
- Mac Studio runner가 같은 볼륨에서 `rename()`만 사용하고 `EXDEV`를 거부하는 테스트.
- 워커 유휴 폴링 상한 10초 테스트.
- 관련 Vitest, TypeScript 검사, 변경 파일 lint 실행.
- 실제 운영 데이터는 이동 테스트에 사용하지 않고 테스트용 임시 폴더로 검증한다.

## 범위 제외

- RAW 이동 또는 이름 변경.
- 기존 사진 분류·RAW 매칭 파이프라인 변경.
- 운영 사진의 재정리나 DB 일괄 수정.
- 별도의 데스크톱 에이전트 또는 신규 저장소 도입.
