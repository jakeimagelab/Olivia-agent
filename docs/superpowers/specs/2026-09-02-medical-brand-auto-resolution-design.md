# 의료 문맥 브랜드 자동 판별 설계

## 목표

Olivia 채팅에서 견적서, 계약서, 콘티 등 문서를 만들 때 고객명이나 요청에 명확한 의료 문맥이 있으면 브랜드를 `photoclinic`으로 자동 결정한다. 이 경우 포토클리닉/제이크이미지 선택 버튼을 노출하지 않고 다음 작성 단계 또는 실제 문서 생성으로 바로 진행한다.

## 판별 우선순위

브랜드는 다음 순서로 결정한다.

1. 사용자가 현재 요청에서 브랜드를 명시한 경우
2. 실제 PageContext에 이미 등록된 `brand`
3. 현재 요청, 선택 고객명, 최근 문서 문맥의 의료 용어
4. 어느 쪽도 확정할 수 없으면 기존 브랜드 선택 UI

따라서 “제이크이미지로 피부과 견적 만들어줘”는 `jakeimage`를 사용하고, “라움피부과 견적 만들어줘”는 `photoclinic`을 사용한다.

## 의료 문맥

강한 의료 기관·진료과 단서를 공통 resolver에서 관리한다. 초기 범위는 병원, 의원, 클리닉, 의료원, 한의원, 한방병원, 치과와 주요 진료과 명칭이다. 의사, 원장, 환자, 진료, 시술처럼 의료 업무를 분명하게 나타내는 용어도 보조 단서로 사용한다.

단순 문자열 한두 곳에 중복 조건문을 만들지 않는다. 공통 resolver는 명시 브랜드, Context 브랜드, 의료 문맥을 입력받아 `photoclinic`, `jakeimage`, 또는 미확정을 반환한다.

## 적용 구조

- Olivia 요청 진입점에서 공통 resolver로 이번 턴의 유효 브랜드를 계산한다.
- 유효 브랜드를 Runtime/Page Context와 도구 실행에 전달한다.
- `create_quote` 등 브랜드를 저장하는 문서 생성 도구는 확정된 값을 사용한다.
- `start_quote_wizard`가 호출되더라도 유효 브랜드가 있으면 해당 브랜드로 초기화하고 브랜드 선택 단계를 건너뛴다.
- 계약서처럼 기존 견적의 브랜드를 승계하는 문서는 저장된 실제 문서 브랜드를 우선한다.
- 의료 문맥이 없고 Context에도 브랜드가 없을 때만 기존 브랜드 선택 버튼을 유지한다.

이 변경은 브랜드 판단만 개선하며 기존 문서 생성, 저장, 검증, Workspace 전환 로직을 대체하지 않는다.

## 예외 및 안전장치

- 명시적인 `jakeimage` 요청은 의료 단어가 함께 있어도 덮어쓰지 않는다.
- 기존 문서에서 확인한 브랜드는 새 텍스트 추론보다 우선한다.
- 의료 단서가 없는 일반 기업·개인·브랜드 촬영은 자동으로 포토클리닉으로 단정하지 않는다.
- resolver가 미확정을 반환하면 기존 선택 UI가 그대로 작동한다.

## 테스트

- “라움피부과 견적서 만들어줘” → `photoclinic`, 브랜드 선택 UI 생략
- “서울의원 계약서 만들어줘” → 의료 문맥 `photoclinic`
- “제이크이미지로 피부과 견적 만들어줘” → 명시값 `jakeimage`
- PageContext `brand=jakeimage` 상태의 일반 문서 요청 → `jakeimage` 유지
- “브랜드 촬영 견적서 만들어줘” → 미확정, 기존 브랜드 선택 UI 표시
- 기존 견적에서 계약서 생성 → 저장된 견적 브랜드 승계
- 기존 비의료 견적 생성 및 문서 저장/검증 회귀 테스트 통과
