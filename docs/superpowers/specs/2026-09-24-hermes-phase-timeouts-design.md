# Hermes 단계별 타임아웃 설계

작성일: 2026-09-24

## 문제

현재 Hermes 채팅은 연결 시작부터 스트림 종료까지 하나의 45초 타이머를 사용한다. 정상적으로 텍스트나 도구 진행 이벤트가 들어오는 중에도 45초가 지나면 요청이 중단된다. 스트림이 시작된 뒤 발생한 타임아웃은 fallback 불가로 처리되어 사용자는 `응답 생성 단계에서 Hermes Agent 응답 시간이 초과되었습니다.` 오류만 받는다.

브라우저는 전체 요청을 50초에 중단하므로 서버가 fallback, 오류 안내, 대화 저장을 마칠 여유도 약 5초뿐이다.

운영 데이터에서는 실패한 턴에 사용자 메시지만 저장되고 assistant 완료 메시지가 없었다. 반면 Hermes health는 103ms, 단순 스트리밍 응답은 약 2.8초로 정상이라 연결 장애보다는 복합 도구 턴이 고정 45초 상한에 걸리는 문제로 판단한다.

## 변경 범위

이번 수정은 엔진 라우팅이나 도구 실행 구조를 바꾸지 않는다. Hermes 요청의 타임아웃만 단계별로 분리한다.

- 연결/응답 헤더 제한: 8초
- 첫 의미 있는 이벤트 제한: 25초
- 스트림 유휴 제한: 18초. 데이터 chunk를 받을 때마다 갱신
- Hermes 전체 상한: 52초
- 브라우저 전체 요청 상한: 57초

Vercel 함수 상한 60초보다 서버 상한을 먼저 종료해 오류 전송과 정리 시간을 남긴다.

## fallback 안전성

연결 자체가 실패하거나 첫 의미 있는 출력 전에 중단된 경우에만 기존 fallback 가능 상태를 유지한다. 텍스트 또는 Olivia 도구 진행이 시작된 뒤에는 중복 실행을 막기 위해 fallback하지 않는다.

타임아웃 오류는 연결, 첫 응답, 스트림 유휴, 전체 상한을 구분해 기록한다. 사용자 문구에도 멈춘 단계를 포함한다.

## 검증

- 지속적으로 chunk가 들어오는 스트림은 기존 45초를 넘어도 유휴 타임아웃으로 중단되지 않는다.
- 첫 의미 있는 이벤트가 25초 안에 없으면 fallback 가능한 오류가 된다.
- 이벤트 이후 18초 동안 새 데이터가 없으면 fallback 불가 오류가 된다.
- 전체 52초 상한은 진행 중인 스트림에도 적용된다.
- 외부 AbortSignal 취소는 Hermes 타임아웃으로 오인하지 않는다.
- 기존 도구 감사, 완료 주장 차단, UI 실행 검증 테스트를 유지한다.
