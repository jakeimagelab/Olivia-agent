# 개인별·공동 사진 셀렉 관리자 브릿지·고객 단계 화면 구현 계획

## 1. 공용 도메인 모델과 DB 계약

1. `lib/person-select/adminWorkspace.ts`에 관리자 상태, 고객 단계, 선택 원본과 보정본 짝짓기 순수 함수를 작성한다.
2. 단위 테스트로 여섯 상태, 단계 1·2·3, 보정본 빈 슬롯·여러 버전·수정 요청을 고정한다.
3. `offers_open` 마이그레이션을 추가하고 주문이 있는 기존 프로젝트만 공개 상태로 백필한다.
4. 관리자·공개 타입에 `offers_open`을 가산한다.

## 2. 서버 응답과 권한

1. 기존 관리자 GET 응답에 개인별 원본 최소 메타데이터를 가산한다.
2. 기존 PATCH 허용 목록에 `offers_open`을 추가한다.
3. 개인·공동 공개 응답에 `offers_open`을 가산한다.
4. 주문 저장 API에서 공개 여부를 서버 기준으로 검사하고 비공개면 403을 반환한다.
5. 기존 응답 필드와 선택·delivery·RAW 저장 방식을 변경하지 않는다.

## 3. 관리자 3칸 작업실

1. 툴바, 고객 트리, 썸네일 그리드, 정보 패널, 상태줄을 작은 컴포넌트로 구현한다.
2. 기존 관리자 page의 컨트롤러와 dialog를 새 작업실에 연결한다.
3. 검색과 별점·컬러 필터는 Bridge 공용 명령을 재사용한다.
4. 설정과 업로드는 모달로 이동하고 기존 패널 기능을 재사용한다.
5. 고객·사진 상세를 오른쪽 정보 패널로 옮기고 기존 drawer를 제거한다.
6. 기존 진행 패널은 참조가 사라진 뒤 삭제한다.

## 4. 고객 단계 화면

1. 공통 단계 헤더와 단계 전환 셸을 작성한다.
2. 개인 고객의 사진 선택 화면을 모바일 3열·선택 순서·저장 상태·제출 CTA로 정리한다.
3. delivery 검토를 한 장 큰 카드와 필름 줄 방식으로 재구성한다.
4. 승인 완료 시 다운로드 전용 2열 화면을 표시한다.
5. 공동 셀렉과 PC Bridge에 같은 단계 계산과 진행 막대를 적용한다.
6. 기존 원본/보정본 탭은 참조를 제거한 뒤 삭제한다.

## 5. 액자·앨범 공개

1. 관리자 설정과 툴바 칩을 같은 `offers_open` 값에 연결한다.
2. 비공개 고객 화면에서 액자·앨범 진입과 상품을 숨긴다.
3. 공개 상태에서 기존 주문 화면과 저장 로직을 재사용한다.
4. 이미 저장된 주문은 관리자 정보 패널에서 계속 표시한다.

## 6. 검증

1. 관련 Vitest를 실행하고 실패한 기존 정적 소스 테스트를 새 구조에 맞춰 갱신한다.
2. `npx tsc --noEmit`을 통과시킨다.
3. 로컬 개발 서버에서 벨라비타 관리자 흐름을 확인한다.
4. 390px 고객 1·2·3단계와 액자·앨범 공개 전후를 캡처한다.
5. 실제 데이터나 worker 권한으로 수행하지 못한 검증은 완료로 보고하지 않고 막힌 지점을 기록한다.
