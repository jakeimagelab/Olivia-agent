# 사진작업실 숨김파일·성능·진행 표시 구현 계획

## 1. 숨김파일 제외 기준 고정

- `lib/photo/extensions.ts`에 `isHiddenSystemFile`을 추가한다.
- 확장자 테스트에 숨김 파일 판정 케이스를 추가한다.
- `folderScanner`, `countJpgFiles`, `PhotoSortingWorkspace`, `PhotoJpgPrepWorkspace`의 파일·폴더 순회에 확장자 판정 전 가드를 넣는다.
- JPG정리 계획에 `hiddenExcluded`를 추가하고 기존 계획 테스트에 숨김 파일·숨김 폴더·`JPG전체` 제외를 추가한다.
- 기준 SSD 폴더의 실제 JPG·숨김 JPG 수를 터미널로 다시 확인한다.

## 2. JPG정리 입력과 안내 보완

- 선택 폴더가 `JPG_INTEGRATED_DIRECTORY`이면 미리보기와 실행을 차단한다.
- 선택한 원본 폴더 이름을 섹션과 머리글 chip에 표시한다.
- 숨김 제외 수가 0보다 클 때만 두 번째 안내 문장을 표시한다.
- 구조 유지 기본값 `true`를 테스트로 고정한다.

## 3. 썸네일 메모리와 상태 갱신 최적화

- `AiPhotoSelectPanel`, `PhotoTcutWorkspace`, `SelectMatchWorkspace`의 썸네일 출력을 Blob URL로 바꾼다.
- URL 회수 함수를 두고 폴더 교체·후보 비우기·언마운트에서 호출한다.
- 순차 생성 루프는 유지하며 20장마다 이벤트 루프에 제어를 돌려준다.
- 진행 상태는 120ms 또는 20장마다, 마지막 항목에서 갱신한다.
- 사진 셀렉 후보 렌더 한도를 200장으로 두고 더 보기로 200장씩 확장한다.

## 4. 사진 분류 진행 상태 갱신 제한

- `PhotoSortingWorkspace` 안에 화면 표시용 진행 갱신 제한기를 추가한다.
- 기존 진행 숫자와 메시지는 보존하고 고빈도 반복문 호출만 120ms·20장·마지막 항목 기준으로 줄인다.
- 분류, 이동, 분석 알고리즘과 파일 작업 코드는 바꾸지 않는다.

## 5. 상태표시줄 폴링 조절

- `PhotoTaskStatusBar`의 폴링을 재예약 방식으로 바꾼다.
- 보임+작업 있음 5초, 숨김 60초, 보임+작업 없음 30초를 적용한다.
- `visibilitychange`에서 보임 전환 시 즉시 조회한다.

## 6. JPG정리 실제 진행·중지

- 계획 행 전체를 분모로, 완료한 행을 분자로 진행 상태를 관리한다.
- 현재 파일, 옮김·건너뜀·충돌을 상태에 넣고 120ms 또는 20장마다 표시한다.
- 중지 ref를 확인해 현재 파일 뒤 다음 행부터 멈춘다.
- 중지·실패·완료 결과 계획을 유지하고 충돌을 표 맨 위로 정렬한다.
- 표는 40줄만 렌더링하고 나머지 수를 표시한다.
- 진행 UI 스타일은 기존 `WorkspaceSurface.module.css` 토큰으로 추가한다.

## 7. 검증

- 관련 단위 테스트와 URL/작업실 회귀 테스트를 실행한다.
- 변경 파일 ESLint, `npm run typecheck`, 전체 Vitest, `npm run build`를 실행한다.
- Playwright로 JPG정리 준비·진행 화면과 사진 셀렉 200장 제한을 넓은 폭·좁은 폭에서 확인한다.
- 금지 파일·패키지 변경 여부와 호출 개수를 `rg`·`git diff`로 감사한다.
