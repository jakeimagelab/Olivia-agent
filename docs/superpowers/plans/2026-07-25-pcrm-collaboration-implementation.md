# PCRM 2차 협업 기능 구현 계획

## 목표

1차 PCRM 기반 위에 고객과 관리자가 실제로 확인·승인·피드백을 주고받는 협업 기능을 추가한다. 기존 프로젝트 토큰, 공개 상태, 활동 기록, 콘티 및 문서 데이터를 재사용하며 관리자 전용 데이터는 고객에게 노출하지 않는다.

## 구현 순서

### 1. 데이터 및 공통 로직

- `20260725_pcrm_collaboration.sql` additive migration 작성
- 촬영 준비 항목, 콘티 장면 피드백, 문의/답변, 첨부 메타데이터 테이블 추가
- 프로젝트 범위 검증, 공개 상태 전이, 입력 검증, 장면 키 생성 유틸 추가
- 서비스 역할 전용 RLS와 프로젝트 중심 인덱스 적용

### 2. 문서 확인·승인

- 고객 공개물 열람, 승인, 수정 요청 API 추가
- 상태 전이를 서버에서 현재 상태와 함께 검증
- 문서함에 상태, 승인, 수정 요청 UI 연결
- 모든 변경을 PCRM 활동 기록에 저장

### 3. 촬영 준비

- 관리자가 기본 준비 항목을 생성·활성화·필수 설정·확인하는 API/UI 추가
- 고객이 활성 항목을 입력, 임시 저장, 제출하는 API/UI 추가
- 필수 항목 누락과 중복 제출 방지

### 4. 콘티 장면 피드백

- 공개된 콘티의 장면에만 고객 피드백 허용
- 장면 승인, 의견, 수정 요청 API/UI 추가
- 관리자 답변과 해결 처리 UI 추가
- 장면 식별자는 저장 데이터가 달라도 안정적으로 유지되는 공통 키 사용

### 5. 문의와 첨부

- 프로젝트 단위 문의와 답변 API/UI 추가
- 고객 메뉴에 문의 페이지 추가
- 관리자 고객 상세에 문의 패널 추가
- PCRM 전용 비공개 Storage 버킷과 서명 업로드를 사용
- 파일 형식, 크기, 연결 대상과 프로젝트 소유권을 서버에서 검증

### 6. 검증

- 상태 전이, 입력 검증, 장면 키 단위 테스트
- 타입 검사, 전체 테스트, 프로덕션 빌드
- 관리자/고객 주요 화면을 실제 브라우저에서 데스크톱·모바일 확인
- 변경 파일만 커밋하고 푸시·배포하지 않음

## 명시적으로 보류하는 운영 결정

- 외부 전자서명 공급자 선택
- 고객 알림 메일/문자 공급자 및 발송 과금 정책
- 첨부파일 장기 보관 기간과 자동 삭제 정책
- 승인 이후 추가 수정의 과금 및 계약 규칙

위 항목은 확장 지점을 준비하되 대표자 결정 전 자동 실행하지 않는다.
