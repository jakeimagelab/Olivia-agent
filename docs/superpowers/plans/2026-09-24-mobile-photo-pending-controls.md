# 모바일 사진 대기 제어 구현 계획

## 목표

모바일 사진 대기 목록에서 사진작업실로 이동하지 않고 프로젝트를 승인·보류·완료 처리한다. 파이프라인 상태는 기존 값과 승인 API를 유지하고, 알림 표시 상태만 별도 컬럼으로 관리한다. 홈 진입 시 위치 권한 팝업도 자동으로 띄우지 않는다.

## 작업 순서

1. `photo_storage_projects`에 `notification_deferred_until`, `notification_dismissed_at`을 추가하고 대기 조회용 부분 인덱스를 만든다.
2. 프로젝트 목록 API가 진행 중 작업은 항상 반환하고, 확인 필요 항목은 완료 처리 여부와 72시간 보류 만료를 반영하도록 한다.
3. 기존 승인·재시도 시 알림 표시 필드를 초기화한다. 보류는 파이프라인 상태를 바꾸지 않고 72시간 만료만 기록한다.
4. 관리자 전용 완료 API를 추가해 프로젝트와 NAS 파일을 보존하면서 열린 이벤트만 확인 처리한다.
5. Notification Provider에 `complete`를 추가하고 409 시 최신 상태를 새로 읽는다.
6. `MobilePhotoPending`을 인라인 확장 카드로 바꾸고, 진료과·촬영모드 유무에 따라 승인/완료/설정 불완전 상태를 구분한다.
7. 모바일 홈의 대기 건수는 서버가 반환한 실제 대기 항목만 세고, 완료된 현재 작업 리소스는 context에 남아 있어도 숨긴다.
8. 위치 권한은 Permissions API가 `granted`일 때만 읽고, `prompt`·`denied`·미지원 환경에서는 자동 요청하지 않는다.
9. API·Provider·모바일 회귀 테스트를 추가하고 typecheck, 관련 테스트, 전체 테스트, build를 실행한다.

## 안전 조건

- `photo_storage_projects` 행과 NAS 파일은 삭제하지 않는다.
- Scene 분류 필요 여부를 추측하지 않는다. `nas_department`와 `nas_shooting_mode` 두 값만 사용한다.
- 승인 동작은 기존 상태 머신을 사용한다.
- 데스크톱 알림과 기존 2단계 승인 흐름은 유지한다.
