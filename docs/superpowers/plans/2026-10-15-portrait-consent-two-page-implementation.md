# 초상권 동의서 2면 개편 구현 계획

작성일: 2026-10-15

## 1. 데이터 계약과 마이그레이션

- `lib/portraitConsent.ts`에 출연 역할 타입과 서명 필드 다섯 개를 nullable로 추가한다.
- `supabase/migrations/20261015_portrait_consent_role_fields.sql`에서 열 다섯 개를 `add column if not exists`로 추가한다.
- 기존 제출 함수를 보존하고 새 필드를 받는 오버로드를 추가한다. 기존 행은 update하지 않는다.
- 공개 제출 API와 관리자 서명 목록 API가 새 필드를 검증·저장·반환하도록 수정한다.
- 공개 API 테스트에 신규 입력, 역할 출연, 실제 신분 민감정보 조건과 기존 입력 호환을 추가한다.

## 2. 공용 2면 문서

- `components/portrait-consent/PortraitConsentSignedDocument.tsx`와 전용 CSS 모듈을 만든다.
- 캔버스 기준 1면·2면의 표, 체크, 서명, 레터헤드, 푸터를 공용 컴포넌트에서만 렌더링한다.
- 각 페이지를 794×1123px로 고정하고 기존 서명 null 필드를 빈 상태로 표시한다.
- 관리자와 공개 화면의 기존 단일 문서 마크업을 공용 컴포넌트로 교체한다.

## 3. 공개 서명 입력

- 기존 입력 순서를 보존한 뒤 연락처, 출연 역할, 실제 신분, 민감정보 입력을 추가한다.
- 역할 출연은 민감정보를 숨기고 null로 제출한다.
- 실제 신분은 민감정보 답변 전 제출을 막는다.
- 제출 완료 문서와 PDF가 방금 제출한 신규 값을 사용하도록 연결한다.

## 4. PDF와 화면 검증

- 이미지 로딩 대기 후 `await document.fonts.ready`를 추가한다.
- 기존 페이지 분할 계산은 유지한다.
- 타입 검사, 변경 파일 lint, 관련 Vitest와 전체 Vitest를 실행한다.
- 로컬 브라우저에서 공개 서명·관리자 상세을 넓은 폭과 좁은 폭으로 확인한다.
- 2페이지 PDF를 생성해 페이지 수, 한글 제목, A4 채움, 법적 문구와 글자 크기를 확인한다.

## 5. 완료 및 전달

- 요청서 9장의 확인란을 실제 줄 번호, 문구, 개수와 테스트 결과로 작성한다.
- 원격 Supabase 적용과 배포·푸시는 별도 승인 전에는 실행하지 않는다.
