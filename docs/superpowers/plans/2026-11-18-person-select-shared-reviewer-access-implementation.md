# 공유 셀렉 검토자 식별·권한·PIN·메모 구현 계획

설계 기준: `docs/superpowers/specs/2026-11-18-person-select-shared-reviewer-access-design.md`

## 1. 스키마와 순수 도메인

1. Supabase CLI로 새 마이그레이션을 생성한다.
2. 행사 PIN 옵션, 검토자 PIN 해시·버전, 접속 로그, PIN 실패 제한, 메모 반영 상태를 추가한다.
3. 모든 신규 테이블에 서비스 역할 전용 RLS와 조회 인덱스를 적용한다.
4. PIN 생성·scrypt 해시·검증, 서명 쿠키, device/IP/UA 정규화, legacy 최종 확정자 보호를 순수 함수로 분리한다.
5. 링크·PIN·로그 단위 테스트를 먼저 작성한다.

## 2. 공유 접근 서버 경계

1. `shared_link_active`를 legacy 공용 토큰에만 적용하도록 `sharedAccess`를 수정한다.
2. request context를 받아 PIN 쿠키 검증과 접속 기록을 처리하는 공용 서버 helper를 추가한다.
3. 공유 공개 API가 같은 helper를 사용하도록 교체하고 기존 드래프트·제출·대화 응답 형태를 보존한다.
4. PIN 확인 API와 초기 접근 확인 API를 추가한다.
5. 30분 접속 중복 제거와 5회 실패·15분 잠금을 테스트한다.

## 3. 관리자 권한·발급·접속 기록

1. 검토자 생성·링크 재발급·공용 링크 재발급에서 PIN을 함께 생성하고 원문은 응답에서 한 번만 반환한다.
2. 공용 링크 끄기와 legacy 권한 변경 전에 다른 활성 finalizer 존재를 검사한다.
3. 행사 PIN 옵션을 저장하고, 활성 검토자 중 PIN이 없는 사람에게 일괄 발급한다.
4. 검토자 접속 기록 조회 API와 다중 기기 요약을 추가한다.
5. 설정 화면에 공용 링크 경고·토글, PIN 토글·일회성 PIN 표시, 접속 기록 모달을 추가한다.

## 4. 고객 PIN·기기 식별

1. localStorage device ID와 `x-person-select-device` 헤더를 제공하는 공유 셀렉 fetch helper를 추가한다.
2. 공유 셀렉의 직접 fetch 호출을 helper로 통일한다.
3. 기존 로그인 카드 스타일을 재사용해 PIN gate를 추가한다.
4. 성공 후 30일 httpOnly 쿠키로 원래 공유 화면을 열고, 잠금·오류 상태를 명확히 표시한다.

## 5. 메모 모아보기와 고객 아이콘

1. canonical 메모 상태에서 검토자·사진·수정 시각을 묶는 관리자 메모 API를 추가한다.
2. 보정 반영 완료 체크 API와 새 메모 발생 시 미완료 계산을 구현한다.
3. 관리자 Bridge 오른쪽 패널에 `메모 모아보기` 탭, 검토자·메모 필터, 완료 체크를 추가한다.
4. 고객 Bridge 썸네일·리뷰 목록과 상세에 메모 아이콘, 작성자, 수정 시각을 표시한다.

## 6. 검증

1. 기존 공용 토큰·검토자 토큰·드래프트·제출·대화 회귀 테스트를 실행한다.
2. 링크 활성, finalizer 보호, PIN 발급·쿠키·잠금, 로그 중복 제거, 메모 완료 상태 테스트를 실행한다.
3. `NODE_OPTIONS=--max-old-space-size=8192 npx tsc --noEmit`을 실행한다.
4. 변경 파일과 응답 형태를 검토하고 운영 DB를 변경하지 않았음을 확인한다.
