# 장비 세팅 연동 설계

작성일: 2026-10-25

## 목표

장비 마스터, 공통 촬영 세팅 규칙, 콘티 편집·현장뷰·공유뷰, 업무일지 장비 목록, 공개 스텝 가이드를 하나의 결정론적 규칙으로 연결한다. 규칙에 없는 장비는 추정하지 않는다.

## 데이터와 마이그레이션

- `equipment`에 `quantity`, `usage`, `note`를 추가하고 카테고리를 11종으로 확장한다.
- 기존 행은 삭제하지 않고 비활성화한 뒤 요청서의 35개 장비를 기존 이름 또는 현재 이름으로 재실행 가능하게 갱신한다.
- `conti_scenes.shot_type`은 `scene/group/profile/interior/video`만 허용한다.
- 기존 `shot_type = null` 장면은 이름과 그룹으로 화면에서만 추론하며, 사용자가 값을 바꿀 때만 저장한다.
- `conti_runs.studio_state` 안에 `shootSetup`과 `equipmentChecked`를 저장한다.

## 공통 규칙

- `lib/shootSetup/rules.ts`가 카메라 역할, 종류별 세팅, 포장 목록, 스텝 업무와 주의 문구의 유일한 원본이다.
- 영상 세팅의 `Ronin 4 Mini`는 다른 장비 종류로 오인되지 않도록 `gimbals` 필드에 둔다.
- 포장 목록은 장비 마스터의 `sort_order`와 같은 고정 순서를 사용하고, 중복 장비는 더 큰 수량 하나로 합친다.

## 콘티 연결

- 편집기 상단에서 촬영 종류, 영상 여부, 프로필 형태를 저장한다.
- 장면마다 `shot_type`을 지정할 수 있고 현장 카드에는 공통 규칙으로 만든 세팅 요약만 표시한다.
- 현장뷰와 현장팀 공유에는 오늘 장비와 카메라 역할을 표시한다. 병원·고객 공유에는 장비 정보를 표시하지 않는다.
- 병원 작성 화면은 `scene/profile/interior`만 바꾸며 `group`, 영상 여부, 프로필 형태는 서버가 기존 값을 보존한다.

## 업무일지와 공개 가이드

- 업무일지는 활성 장비 전체와 해당 일정에 이미 선택된 비활성 장비를 함께 보여준다.
- 현재 일정과 콘티 사이에 안정적인 외래키 연결이 없으므로 요청서 원칙대로 `콘티 기준 추천 선택` 버튼은 추가하지 않는다.
- `/staff-guide`는 로그인 없는 서버 렌더링 페이지로 제공하고, 공개 응답에는 활성 장비의 표시 정보만 포함한다. 체크 상태는 브라우저 저장소에 보관한다.

## 오류·호환성

- 신규 DB 컬럼이 아직 없는 환경에서는 기존 콘티 저장 호환 경로를 유지한다.
- 비활성 장비라도 과거 일정에서 선택된 행은 회색 상태로 보존한다.
- 기존 `COMPUTER` 값을 새 제약에 맞추려면 기존 제약을 먼저 제거한 뒤 `STORAGE`로 바꾸고 새 제약을 건다.

## 검증

- 공통 규칙의 네 가지 고정 입력을 단위 테스트한다.
- 타입 검사, 린트, 관련 Vitest를 실행한다.
- 두 대표 입력의 포장 목록 원문을 스크립트 또는 테스트 출력으로 확인한다.
- 운영 DB 마이그레이션을 실제 적용하지 못한 경우 정적 검증과 미실시 항목을 분리해 보고한다.
