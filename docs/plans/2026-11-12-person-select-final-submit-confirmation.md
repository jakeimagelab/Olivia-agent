# 사진선택 최종 제출 확인 설계

## 목표

고객의 자동 저장 선택은 진행 중 초안으로 유지한다. 고객이 `제출하기`를 누른 뒤 최종 선택 확인 화면에서 내용을 검토하고 `확인하고 최종 제출`을 눌러야만 관리자에게 최종 제출본으로 표시한다.

## 화면 흐름

1. 사진 선택·별점·컬러·메모는 기존처럼 자동 저장한다.
2. 하단의 기존 `최종 제출` 버튼은 `제출하기`로 바꾼다.
3. 버튼을 누르면 저장 대기 항목을 먼저 서버에 반영한다.
4. `최종 선택 확인` 대화상자에서 선택 장수, 항목별 장수, 파일명과 보정 요청 요약을 보여준다.
5. 고객이 확인 체크박스를 선택한 뒤 `확인하고 최종 제출`을 눌러야 제출 API를 호출한다.
6. `돌아가서 수정`은 대화상자만 닫고 자동 저장 초안을 유지한다.

## 적용 범위

- 개인별 셀렉 모바일·PC
- 공동 셀렉 Classic
- 공동 셀렉 고객 Bridge

세 화면은 같은 최종 확인 컴포넌트를 사용한다. 기존 갤러리·Bridge 레이아웃과 사진 조작은 변경하지 않는다.

## 관리자와 서버 규칙

- 제출 전 선택은 관리자에게 `선택 중`으로 보이지만 최종 제출로 집계하지 않는다.
- 개인별 셀렉은 제출 후 사진·메모가 바뀌면 `submitted_at`을 비워 다시 `선택 중`으로 돌린다.
- 공동 셀렉은 기존 초안과 제출 스냅샷 분리를 그대로 사용한다.
- RAW 매칭의 `최종 제출본만`은 제출 완료 상태만 사용하고, 제출 전 선택은 명시적으로 `지금 고른 상태`를 선택했을 때만 사용한다.

## 검증

- 첫 번째 버튼만 눌러서는 제출 API가 호출되지 않는다.
- 확인 체크 전에는 최종 제출 버튼이 비활성이다.
- 저장 대기 변경이 있으면 최종 확인을 열 수 없다.
- 최종 확인 후에만 완료 화면으로 이동한다.
- 제출 후 선택 변경 시 관리자 상태가 다시 `선택 중`으로 바뀐다.
