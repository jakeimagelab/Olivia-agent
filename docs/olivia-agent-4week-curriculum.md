# 올리비아 에이전트로 배우는 AI 실무 자동화 구축 — 4주 커리큘럼

## 개요

| 항목 | 내용 |
|---|---|
| 대상 | 비개발자 실무자 (코딩 경험 없음) |
| 목적 | 결과물을 그대로 따라 만들기가 아니라, **"기획 → 도구 선택 → AI와 협업 → 시행착오 극복 → 운영"** 이라는 개발 과정과 의사결정 방식을 이해하고 본인 업무에 적용할 수 있게 하기 |
| 기간 | 4주, 주 1회 강의(2~3시간) + 주간 과제 |
| 사례 | 실제 "올리비아" 에이전트(포토클리닉 어드민 시스템) 개발 3개월 여정을 매주 실제 사례로 활용 |
| 원칙 | 코드를 가르치지 않는다. "AI 코딩 어시스턴트(Claude Code)에게 무엇을, 어떻게 시키고 확인하는가"를 가르친다 |

### 사전 준비 (강의 전 안내)
- 노트북, 이메일 계정
- 강의 중 실습에 필요한 계정은 Week 2에 함께 만들므로 미리 준비할 필요 없음

## Week 1 — 왜, 무엇을 만드는가: 기획과 전체 그림

### 학습 목표
- "AI 에이전트"가 챗봇과 어떻게 다른지 구분할 수 있다
- 자기 업무 중 자동화할 가치가 있는 지점을 스스로 찾아낼 수 있다
- 전체 시스템이 어떤 부품들로 이루어지는지 큰 그림을 그릴 수 있다

### 강의 내용
1. **AI 에이전트란 무엇인가** — 질문에 답만 하는 챗봇과, 실제로 작업 단계를 만들고(agent_tasks) 진행시키고(승인/큐) 다음 단계로 넘기는(워크플로우 자동화) "일하는 AI"의 차이를 올리비아를 예시로 설명
2. **왜 만들었는가** — 실제 업무 고통 지점에서 출발한 사례: 견적서 수작업 작성, 병원 이미지 진단, 리뷰 콘텐츠 정리 등 반복 업무를 하나씩 자동화 대상으로 골라온 과정
3. **전체 그림 그리기** — "사용자(직원) ↔ 웹 관리자 화면 ↔ AI 두뇌(Claude) ↔ 데이터 창고(Supabase) ↔ 이메일 발송" 흐름을 그림 한 장으로 정리
4. **노코드 vs 로우코드 vs AI 코딩 어시스턴트** — 왜 이번 프로젝트는 Claude Code로 직접 코드를 짜는 방식을 택했는지, 각 방식의 장단점 비교
5. **완벽보다 MVP** — 처음부터 다 만들지 않고 가장 아픈 업무 하나부터 자동화하고 넓혀간 실제 순서 (견적서 → 갤러리 → 워크플로우 자동화 순으로 확장된 이야기)

### 실습
- 올리비아 어드민 화면 라이브 데모 (로그인 → 견적서 생성 → 워크플로우 진행 → 승인)

### 과제
- **문제 정의서 작성** (양식 제공)
  - 지금 어떤 방식으로 처리하고 있는가
  - 한 번 처리하는 데 시간이 얼마나 드는가
  - 자동화되면 무엇이 좋아지는가

## Week 2 — 무엇으로 만드는가: 도구, 웹서비스, 도메인

### 학습 목표
- 개발에 필요한 핵심 서비스 4가지의 역할을 비유로 설명할 수 있다
- 본인 계정으로 배포까지 한 번 직접 경험한다
- "환경변수"와 "도메인"이 왜 중요한지 실패 사례로 이해한다

### 강의 내용
1. **핵심 4대 축**
   - GitHub = 코드를 보관하는 캐비닛 (버전 기록도 남음)
   - Vercel = 만든 것을 실제 인터넷에 여는 매장 오픈
   - Supabase = 데이터를 담는 창고이자 장부 (테이블 = 엑셀 시트)
   - Anthropic Claude API = 직원 역할을 하는 AI의 두뇌
2. **도메인과 환경변수 — 실제 시행착오 사례**
   - 서비스 도메인을 이전하는 과정에서, 코드 여러 곳에 옛 주소(`photoclinic-diangnoisis.vercel.app` 등)가 그대로 박혀 있어서 메일 로고가 깨지고 링크가 잘못 걸렸던 실제 사고
   - "이미 처리됐다"고 적힌 항목도 실제로는 안 되어 있던 경우 — 왜 직접 확인이 필요한지
   - 그래서 주소·비밀번호처럼 바뀔 수 있는 값은 코드에 직접 쓰지 않고 **환경변수**로 분리해서 관리해야 하는 이유
3. **비밀번호/API 키를 코드에 넣으면 안 되는 이유** (`.env` 개념)
4. **이메일 자동발송**(Gmail/Resend) 연동이 하는 일 — "왜 사람이 매번 메일을 보내지 않아도 되는가"

### 실습
- 참가자 본인 GitHub 계정 생성 → Vercel과 연결 → Claude Code 도움으로 "Hello World" 페이지 배포까지 직접 경험

### 과제
- 본인 GitHub + Vercel 계정 셋업 완료, 배포된 페이지 스크린샷 제출

## Week 3 — AI와 함께 일하기: 설계, 지시서, 워크플로우

### 학습 목표
- AI 코딩 어시스턴트에게 "일을 시키는 법"을 익힌다
- 업무를 단계별 워크플로우로 쪼개는 방법을 익힌다
- 버그(오류)를 발견했을 때 "증상을 정확히 설명"하는 능력을 기른다

### 강의 내용
1. **좋은 지시서 vs 나쁜 지시서** — 실제 인수인계 문서(HANDOFF)에 남아있는 "사용자가 실제로 보낸 원본 지시서" 예시를 보며, 무엇을 어떻게 요청해야 AI가 정확히 알아듣는지 분석
2. **업무를 단계로 쪼개기** — 올리비아의 실제 워크플로우 구조(단계 진입 → 작업 자동 생성 → 실행 → 초안/메일큐/승인 생성 → 승인 → 다음 단계 이동) 사례로, 하나의 큰 업무를 작은 단계로 나누는 법
3. **데이터 구조 기초** — 테이블이란 무엇인가(엑셀 시트에 비유), "고객 하나당 어떤 정보가 필요한가"를 정리하는 것이 곧 데이터베이스 설계라는 것
4. **AI가 실수했을 때 대처법 — 실제 버그 사례 스터디**
   - 진행률 표시가 "6/12"처럼 어긋났던 사고: 전체 목록 기준과 실제 사용 중인 목록 기준이 서로 달라서 생긴 문제
   - 완료된 고객이 "미시작"으로 잘못 표시되던 사고: 화면에서 데이터를 가져올 때 조건을 빠뜨려서 생긴 문제
   - 공통점: 코드를 몰라도 **"어떤 화면에서, 무엇을 봤는데, 기대와 뭐가 달랐는지"**만 정확히 설명하면 AI가 원인을 찾아낼 수 있다는 것
5. **승인 단계를 넣는 이유** — 자동화해도 중요한 지점(예: 실제 발송 직전)에는 사람 확인을 넣는 설계 판단

### 실습
- 버그 리포트 "나쁜 예 vs 좋은 예" 비교 연습 (예: "안 돼요" vs "고객 목록에서 방금 승인한 A병원이 완료가 아니라 미시작으로 나와요")

### 과제
- Week 1의 본인 업무 프로세스를 단계별 워크플로우 다이어그램으로 설계 (도구 자유: 종이, 파워포인트 등)

## Week 4 — 운영과 지속적 개선

### 학습 목표
- "다 만들었다고 끝이 아니다"라는 것을 실제 운영 사례로 이해한다
- 인수인계/기록 습관의 중요성을 이해한다
- 본인 기획안을 발표할 수 있는 수준으로 정리한다

### 강의 내용
1. **배포 후에도 계속 생기는 문제들 — 실전 사례**
   - 페이지마다 배경색이 미묘하게 달라 보이던 문제: 겉보기엔 같은 색 코드인데 실제 렌더링은 달랐던 이유(공통 규칙 상속 여부)를 브라우저로 직접 확인해서 찾아낸 과정
   - 도메인 이전 후에도 곳곳에 남아있던 옛 주소 잔재를 전체 검색으로 훑어서 정리한 과정
   - 구글 로그인 연동 시, 코드만 고치는 걸로 끝나지 않고 Vercel 환경변수·구글 클라우드 콘솔 설정까지 함께 맞춰야 했던 사례
2. **인수인계 문서화 습관** — 세션(작업 시간)이 끊겨도 다음 작업자(사람이든 AI든)가 이어받을 수 있도록 "완료 / 부분 진행 / 미착수"를 구분해서 기록하는 습관이 왜 중요한지
3. **보안 기초** — 관리자 비밀번호를 코드에 넣지 않고 환경변수로 관리하기, 데이터베이스에 실행할 SQL은 실행 전 반드시 검토하는 습관
4. **피드백 반영 사이클** — 실제 써보고 → 문제 발견 → 고치고 → 다시 배포하는 반복이 정상이라는 것
5. **다음 기능을 기획하는 법** — 지금까지 배운 "문제 정의 → 단계 설계 → 도구 선택" 틀을 다음 자동화 대상에도 그대로 적용하는 법

### 실습 / 발표
- 참가자별로 본인이 설계한 워크플로우를 5분씩 발표, 서로 피드백

### 최종 과제
- 본인의 자동화 기획안 1페이지 제출: 문제 정의 + 단계별 워크플로우 + 필요한 도구 목록

## 부록: 쉬운 용어 사전
- **API**: 두 프로그램이 서로 데이터를 주고받는 통로 (예: 우리 시스템이 Claude에게 "이 내용 요약해줘"라고 요청을 보내는 창구)
- **배포(Deploy)**: 만든 것을 실제 인터넷 주소에서 사용할 수 있게 올리는 것
- **환경변수**: 코드에 직접 적지 않고 별도로 안전하게 보관해두는 값 (비밀번호, 주소, API 키 등)
- **데이터베이스**: 정보를 체계적으로 저장해두는 창고 (테이블 = 엑셀 시트, 행 = 한 줄의 정보)
- **워크플로우**: 업무를 순서대로 진행되는 단계들로 나눈 것
- **프롬프트**: AI에게 내리는 지시문
- **승인(Approval) 단계**: 자동화 과정 중 사람이 최종 확인하고 넘어가는 지점
