## 슬라이드 2. 실제 사례 1 — 같은 색인데 다르게 보이던 문제

**증상**: 페이지마다 배경색이 미묘하게 달라 보인다는 제보. 그런데 코드를 봐도 각 페이지가 지정한 색상 값은 실제로 다 달랐음 (`#EDF5F3`, `#faf7f2`, `#F0F9F8` 등).

**진짜 원인**: 실제로는 아래 같은 공통 규칙이 있었습니다.

```css
/* pc-header를 직접 자식으로 가진 페이지는 자동으로 mesh 그라디언트 배경을 받는다 */
main:has(> .pc-header),
div:has(> .pc-header) {
  background: var(--mesh-bg) !important;
}
```

즉 **이 규칙에 걸리는 페이지는 자기가 지정한 색과 무관하게 이미 같은 배경**(청록/주황 은은한 그라디언트)을 쓰고 있었고, 딱 한 페이지(`/quote`)만 이 규칙 밖에 있어서 실제로 달라 보였습니다.

**여기서 배우는 것**
1. 코드에 적힌 값(`#F0F9F8`)만 보고 판단하면 틀릴 수 있다 — **실제 화면(브라우저)에서 확인**해야 진짜 원인을 안다
2. "다 만들었다"의 기준은 코드가 아니라 **실제로 사람이 보는 결과**다

## 슬라이드 3. 실제 사례 2 — 로그인 연동은 코드만으로 안 끝난다

구글 로그인을 새 도메인(`olivia.photoclinic.kr`)에 맞게 연결하는 작업에서:

- 코드에서 콜백 주소(`NEXTAUTH_URL`)를 새 도메인 기준으로 고침 → **여기서 끝이 아님**
- 실제로 로그인이 되려면 **두 곳이 더 맞아야** 합니다
  1. Vercel에 `NEXTAUTH_URL` 환경변수가 실제로 새 주소로 설정되어 있는가
  2. Google Cloud Console의 "승인된 리디렉션 URI" 목록에 `https://olivia.photoclinic.kr/api/auth/google/callback`이 등록되어 있는가

**핵심 문장**: 서비스가 여러 외부 서비스(우리 코드 + Vercel 설정 + Google 설정)로 연결되어 있을 땐, **코드 수정 하나로 끝나지 않고 연결된 곳을 전부 같이 맞춰야** 실제로 동작합니다.

## 슬라이드 4. 실제 사례 3 — 스스로 매일 점검하는 AI

## 슬라이드 5. 인수인계 문서화 습관 — 실제 문서 구조

실제로 작업 세션이 중단됐을 때 다음 담당자(사람이든 AI든)에게 남긴 인수인계 문서의 실제 구조입니다.

```
# 인계 문서 — 2026-07-19

## ✅ 완료된 작업
  (무엇을 왜 어떻게 고쳤는지, 관련 파일까지 기록)

## 🟡 부분 진행
  (어디까지 됐고, 무엇이 아직 미검증인지)

## ❌ 미착수
  (원래 요청 원문 그대로 보존)

## ⚠️ 확인 필요
  (사람이 직접 확인해야 할 것 — 환경변수 설정, 외부 서비스 등록 여부 등)
```

**왜 이렇게 3단계(완료/부분/미착수)로 나누는가**: "다 했다" 아니면 "안 했다" 둘로만 나누면, "반은 했는데 검증은 안 한" 애매한 상태가 사라져 버립니다. 그 애매한 상태를 기록해둬야 다음 사람이 처음부터 다시 확인하지 않아도 됩니다.

**비개발자에게 적용법**: 본인 업무를 AI에게 맡기고 자리를 비울 때도 이 3단계로 메모를 남기면, 돌아왔을 때(혹은 다음 담당자가) 바로 이어받을 수 있습니다.

## 슬라이드 6. 보안 기초

- 관리자 비밀번호는 코드에 적지 않고 환경변수(`ADMIN_PASSWORD`)로 관리 (Week 2 복습)
- API 키(Anthropic, OpenAI, Google 등)도 전부 환경변수
- 데이터베이스에 실행할 SQL(테이블 생성/수정 명령)은 **실행 전 반드시 내용을 확인**하고 실행 — 특히 기존 데이터를 지우거나 바꾸는 명령은 더 신중하게

## 슬라이드 7. 피드백 반영 사이클

```
실제로 써본다 → 문제/불편함 발견 → 증상을 정확히 설명 (Week 3 방식) → 수정 요청 → 다시 배포 → 다시 써본다
```

올리비아도 이 사이클을 3개월간 계속 돌린 결과입니다. "한 번에 완벽하게"가 아니라 "계속 돌리는 것"이 정상입니다.
