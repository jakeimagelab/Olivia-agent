## 슬라이드 2. 챗봇과 "일하는 AI"의 차이

| | 챗봇 | 올리비아 같은 워크플로우 에이전트 |
|---|---|---|
| 하는 일 | 질문에 답만 함 | 작업을 스스로 만들고, 진행시키고, 다음 단계로 넘김 |
| 기억 | 대화가 끝나면 사라짐 | 데이터베이스에 "지금 몇 단계인지" 계속 저장됨 |
| 사람의 역할 | 매번 질문해야 함 | 중요한 순간에만 승인/확인 |
| 예시 | "견적서 양식 알려줘" | 촬영 일정이 잡히면 → 견적서 초안을 스스로 만들고 → 담당자 승인만 받으면 → 자동 발송 |

**핵심 문장**: 챗봇은 "물어보면 답하는 것", 에이전트는 "일이 스스로 굴러가게 만드는 것".

## 슬라이드 4. 왜 만들었는가 — 실제 업무 고통 지점

| 기존 방식 (사람이 직접) | 걸리던 시간/문제 | 올리비아가 하는 일 |
|---|---|---|
| 견적서를 매번 엑셀/한글로 새로 작성 | 병원마다 옵션이 달라 매번 재작성 | 조건 입력하면 견적서 초안 자동 생성 |
| 촬영 후 리뷰 콘텐츠를 손으로 정리 | 카드뉴스/캡션까지 직접 작성 | 리뷰 DB 수집 + 인스타 콘텐츠 초안 생성 |
| 병원 채널(SNS 등) 분석을 수작업으로 | 데이터 모으고 정리하는 데 오래 걸림 | 채널 분석 자동 수행 |
| 진행 상황을 메모/기억으로 관리 | 어디까지 했는지 놓치기 쉬움 | 12단계 워크플로우로 자동 추적 (Week 3에서 자세히) |

**공통점**: 전부 "반복적이고, 규칙이 있고, 사람이 안 해도 될 만큼 패턴이 명확한" 업무부터 골랐습니다.

## 슬라이드 5. 전체 그림 — 5개의 부품

```
[사용자/직원]
      │  (웹 브라우저로 접속)
      ▼
[웹 관리자 화면] ── Next.js로 만든 화면, Vercel에서 서비스됨
      │
      ├──▶ [AI 두뇌]  Claude / OpenAI  → 문서 작성, 이미지 분석, 요약
      │
      ├──▶ [데이터 창고]  Supabase  → 고객·프로젝트·진행상태 저장
      │
      └──▶ [발송 채널]  Gmail / 카카오 / 텔레그램  → 사람에게 결과 전달
```

이 5개 부품의 이름과 역할은 Week 2에서 각각 실제로 만져봅니다.

## 슬라이드 6. 실제 예시 — AI 두뇌는 사실 하나가 아니다

올리비아는 업무 성격에 따라 다른 AI 모델을 나눠 씁니다. (`.env.local.example`에 실제로 설정된 값)

| 업무 | 사용 모델 |
|---|---|
| 리뷰 콘텐츠 작성, 문서 요약 | Anthropic Claude |
| 사진 속 장면(Scene) 분석 | OpenAI Vision (`gpt-4.1-mini` / 고정밀은 `gpt-4.1`) |
| 음성 메모 → 텍스트 전환 | OpenAI Transcribe |
| 메모 이미지 정돈 | OpenAI Vision |

**핵심 문장**: "AI 하나로 다 한다"가 아니라, **업무 성격에 맞는 AI를 골라 쓰는 것**도 기획의 일부입니다. 글은 글 잘 쓰는 모델, 사진은 사진 잘 보는 모델.

## 슬라이드 7. 노코드 vs 로우코드 vs AI 코딩 어시스턴트

| | 예시 | 장점 | 한계 |
|---|---|---|---|
| 노코드 | 챗봇 빌더, 자동화 툴(자피어류) | 매우 빠름, 코드 지식 불필요 | 복잡한 로직·데이터 구조엔 한계 |
| 로우코드 | 일부 코드 + 화면 빌더 | 어느 정도 커스터마이징 | 특정 플랫폼에 종속됨 |
| AI 코딩 어시스턴트 (Claude Code) | 실제 코드를 AI가 작성 | 제한 없이 원하는 대로 확장 가능, 표준 기술 사용 | 처음엔 사람이 방향을 정확히 줘야 함 |

올리비아는 "12단계 워크플로우 + 승인 + 자동발송 + 카카오봇 + 매일 자동 브리핑"처럼 조합이 많고 계속 커지는 시스템이라, 노코드로는 한계가 뚜렷해서 AI 코딩 어시스턴트 방식을 택했습니다.

## 슬라이드 8. 완벽보다 MVP — 올리비아의 확장 순서

처음부터 지금 모습으로 만들지 않았습니다. 실제로는 이런 순서로 넓어졌습니다.

1. **견적서 자동 생성** (가장 반복적이고 아픈 업무 하나부터)
2. **사진 갤러리 + 리뷰 콘텐츠 정리**
3. **12단계 워크플로우 자동화** (승인/큐/다음 단계 이동)
4. **카카오톡 대표자 비서** (이메일 조회·요약, 일정 알림)
5. **매일 자동 브리핑/모니터링** (Vercel Cron으로 아침마다 스스로 체크)

**핵심 문장**: "가장 아픈 곳 하나 → 써보면서 다음 아픈 곳 추가"가 3개월 개발의 실제 순서였습니다. 처음부터 5번까지 한 번에 설계하려 했다면 시작도 못 했을 것입니다.

## 슬라이드 10. 과제 — 문제 정의서 작성

아래 양식을 채워서 다음 시간까지 제출합니다.

```
1. 자동화하고 싶은 업무: (예: 매주 반복되는 __ 작업)
2. 지금은 어떻게 처리하고 있나요?
3. 한 번 처리하는 데 걸리는 시간은?
4. 얼마나 자주 반복되나요?
5. 자동화되면 무엇이 좋아지나요?
6. 이 업무에서 "사람이 꼭 최종 확인해야 하는 지점"이 있다면 어디인가요?
```

> 6번을 미리 생각해보게 하는 이유: Week 3의 "승인 단계 설계"로 이어집니다.
