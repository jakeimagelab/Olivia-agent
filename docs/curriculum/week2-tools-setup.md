## 슬라이드 5. 환경변수란 무엇인가

**나쁜 예**: 코드 안에 `비밀번호 = "1234"` 라고 직접 적어놓는 것
- 코드를 다른 사람과 공유하거나 GitHub에 올리는 순간 비밀번호가 그대로 노출됨
- 비밀번호를 바꾸려면 코드를 고치고 다시 배포해야 함

**좋은 예**: 코드에는 "비밀번호는 어딘가에 따로 있다"라고만 적고, 실제 값은 Vercel의 별도 보관함(환경변수)에 저장
- 코드를 공유해도 비밀번호는 안 보임
- 값이 바뀌면 보관함만 수정하면 됨 (코드 재배포 불필요)

**정리**: 바뀔 수 있는 값(비밀번호, API 키, 주소)은 코드에 직접 쓰지 않고 환경변수로 분리한다.

## 슬라이드 6. 실제 시행착오 — 도메인 이전 사고

올리비아 서비스 주소를 옮기는 과정에서 실제로 있었던 일입니다.

**무슨 일이 있었나**
- 예전 주소(`photoclinic-diangnoisis.vercel.app` 등)를 새 주소(`olivia.photoclinic.kr`)로 옮겼습니다
- 그런데 메일 발송 코드, 로고 이미지 경로 등 **여러 파일 곳곳에 예전 주소가 코드에 직접 적혀 있었습니다** (환경변수가 아니라)
- 그래서 옮긴 뒤에도 일부 메일에서 로고가 깨지고, 링크가 옛날 주소로 걸리는 문제가 발생했습니다
- 더 큰 문제: 지시서에 "이미 새 주소로 되어있어 조치 불필요"라고 적힌 항목이 **2곳은 실제로는 안 되어 있었습니다**

**여기서 배우는 것**
1. 주소처럼 언젠가 바뀔 수 있는 값은 반드시 환경변수(`NEXT_PUBLIC_BASE_URL`)로 관리해야 한다
2. "이미 되어 있다"는 문서를 믿지 말고, **실제로 검색해서 확인**해야 한다 (강사 코멘트: 이후 전체 코드에서 옛 주소를 검색해 남은 곳을 다 찾아 정리했습니다)

## 슬라이드 7. 이메일 자동발송이 하는 일

- Gmail / Resend 같은 서비스를 연결하면, 시스템이 "이 조건이 되면 이 사람에게 이 내용을 보내라"를 자동으로 처리
- 올리비아 예시: 최종 파일이 승인되면 → 고객에게 "파일이 준비됐습니다" 메일이 자동 발송
- 사람은 **발송 직전 승인 버튼만** 누르면 됨 (Week 3의 승인 단계와 연결)
